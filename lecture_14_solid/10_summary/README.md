# 10. Итоги и связь принципов между собой

**Пункт плана:** 10 — итоги, взаимосвязь принципов.

## Что показывает пример

Небольшая система уведомлений (`NotificationService`), в которой одновременно
работают все пять принципов SOLID плюс TDA. В `main.cpp` каждое место помечено
комментарием с названием принципа.

## Сборка и запуск

```bash
cmake -S .. -B ../build       # из папки лекции
cmake --build ../build
./../build/10_summary
```

## Связь принципов

| Принцип | Что решает | Связь |
|---------|-----------|-------|
| SRP | Одна причина для изменения | Основа для ISP и DIP |
| OCP | Расширение без модификации | Реализуется через полиморфизм (LSP) |
| LSP | Корректность подстановки | Гарантирует работу OCP |
| ISP | Минимальные интерфейсы | Следствие SRP для интерфейсов |
| DIP | Зависимость от абстракций | Использует ISP для определения интерфейсов |

## Где какой принцип в примере

* **SRP** — форматирование (`IMessageFormatter`) и отправка
  (`INotificationSender`) разнесены по разным ответственностям.
* **ISP** — оба интерфейса узкие, ровно с одним методом.
* **LSP** — каждый отправитель (`EmailSender`, `SmsSender`, ...) честно
  выполняет контракт `send()`.
* **OCP** — добавление `TelegramSender` не меняет `NotificationService`.
* **DIP** — `NotificationService` зависит от абстракций, конкретные каналы
  подставляются в Composition Root (`main`).
* **TDA** — клиент говорит `service.notify(text)`, а не управляет каналами
  вручную.

## Главный вывод

SOLID — не догма, а набор взаимоусиливающих эвристик. SRP даёт основу, ISP
дробит интерфейсы, DIP инвертирует зависимости через абстракции, LSP
обеспечивает корректность подтипов, а OCP делает систему расширяемой.
Применяйте с умом: избыточная абстракция вредна так же, как и её отсутствие.
