# Лекция 14. Принципы SOLID

Примеры к лекции. Покрывают все пункты плана: связанность и связность,
идиому Pimpl, принципы Tell-Don't-Ask и CQRS, а также пять принципов SOLID
(SRP, OCP, LSP, ISP, DIP) и их взаимосвязь. Каждый пример построен по схеме
«плохо → хорошо»: в комментариях показано нарушение принципа, а `main.cpp`
содержит правильный (отрефакторенный) вариант.

## Сборка

```bash
cmake -S . -B build
cmake --build build
```

Запуск примеров:

```bash
./build/01_coupling_cohesion
./build/02_pimpl
./build/03_tell_dont_ask
./build/04_cqrs
./build/05_srp
./build/06_ocp
./build/07_lsp
./build/08_isp
./build/09_dip
./build/10_summary
```

## Ключевые идеи лекции

1. **Coupling / Cohesion.** Цель проектирования — слабая связанность и высокая
   связность: каждый модуль делает одно дело и минимально зависит от других.
2. **Pimpl** скрывает реализацию за непрозрачным указателем: изменение приватных
   полей не требует перекомпиляции клиентов. Деструктор обязан быть в `.cpp`.
3. **Tell, Don't Ask.** Не вытаскивайте состояние наружу, чтобы принять решение, —
   поручите объекту действие; он сам проверит свои инварианты.
4. **CQRS.** Команда меняет состояние и ничего не возвращает; запрос возвращает
   данные и ничего не меняет. Это упрощает рассуждение и безопасность исключений.
5. **SRP** — у класса одна причина для изменения. Основа для ISP и DIP.
6. **OCP** — открыт для расширения, закрыт для модификации; реализуется
   полиморфизмом.
7. **LSP** — подтип полностью заменяет базовый тип: предусловия не усиливаются,
   постусловия не ослабляются, инварианты сохраняются.
8. **ISP** — много маленьких интерфейсов лучше одного «толстого».
9. **DIP** — модули верхнего и нижнего уровня зависят от абстракций; абстракция
   принадлежит слою бизнес-логики.
10. **SOLID — набор эвристик, а не догма.** Принципы усиливают друг друга, но
    избыточная абстракция вредна так же, как и её отсутствие.
