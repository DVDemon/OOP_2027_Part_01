# 02. Идиома Pimpl — брандмауэр компиляции

**Пункт плана:** 2 — идиома Pimpl (Pointer to Implementation).

## Что показывает пример

Pimpl скрывает детали реализации за непрозрачным указателем и решает две задачи:

1. **Брандмауэр компиляции** — изменение приватных полей не требует
   перекомпиляции зависимых модулей.
2. **Сокрытие зависимостей** — заголовок не включает «тяжёлые» заголовки
   (`<vector>`, `<algorithm>` и т.п.).

Файлы:

* `widget.h` — публичный интерфейс, `struct Impl` объявлена forward, поле —
  `std::unique_ptr<Impl>`;
* `widget.cpp` — полное определение `Impl` и всех методов;
* `main.cpp` — использование (демо).

## Сборка и запуск

```bash
cmake -S .. -B ../build       # из папки лекции
cmake --build ../build
./../build/02_pimpl
```

Цели: `02_pimpl` — демонстрация в консоли.

## Плохо → Хорошо

**Плохо** — приватные поля и тяжёлые заголовки прямо в `widget.h`:

```cpp
// widget.h
#include <vector>            // утекает всем, кто включает widget.h
class Widget {
    std::string name_;
    std::vector<int> data_;  // добавили поле -> перекомпиляция всех клиентов
public:
    // ...
};
```

**Почему плохо:** любое изменение приватного представления (новое поле, смена
контейнера) меняет размер класса и требует перекомпиляции каждой единицы
трансляции, включающей `widget.h`. Плюс зависимости реализации навязываются
всем клиентам.

**Хорошо** — указатель на реализацию:

```cpp
// widget.h
class Widget {
public:
    explicit Widget(std::string name);
    ~Widget();                       // объявлен здесь, определён в .cpp
    // ...
private:
    struct Impl;                     // forward declaration
    std::unique_ptr<Impl> pimpl_;    // непрозрачный указатель
};
```

**Почему хорошо:** заголовок стабилен — приватные поля живут в `.cpp`. Клиенты
перекомпилируются только при изменении публичного интерфейса.

## Важная деталь: деструктор

`~Widget()` нельзя оставить `= default` **в заголовке**: там `Impl` — неполный
тип, и `unique_ptr<Impl>` не сможет его удалить. Поэтому деструктор объявляется
в `widget.h`, а определяется (как `= default`) в `widget.cpp`, где `Impl` полный.
То же касается move-операций.
