# 04. CQRS — Command-Query Responsibility Segregation

**Пункт плана:** 4 — паттерн CQRS.

## Что показывает пример

Принцип Бертрана Мейера: **каждый метод — либо команда (изменяет состояние,
ничего не возвращает), либо запрос (возвращает данные, ничего не меняет).**
В примере `Stack` разделён на команды (`push`, `pop`) и запросы (`top`, `size`,
`empty`). Запросы помечены `const`.

## Сборка и запуск

```bash
cmake -S .. -B ../build       # из папки лекции
cmake --build ../build
./../build/04_cqrs
```

## Плохо → Хорошо

**Плохо** — `pop()` одновременно удаляет и возвращает:

```cpp
int pop() {
    int val = data_.back();
    data_.pop_back();   // состояние изменено
    return val;         // копирование val при возврате может бросить исключение
}
```

**Почему плохо:** метод совмещает команду и запрос. Если копирование
возвращаемого значения бросит исключение уже после `pop_back()`, элемент
потерян — нарушена безопасность исключений. Кроме того, неясно, есть ли у
метода побочный эффект.

**Хорошо** — запрос и команда разделены:

```cpp
int top() const { return data_.back(); }  // запрос: без побочных эффектов
void pop()       { data_.pop_back(); }     // команда: ничего не возвращает
```

**Почему хорошо:** `top()` безопасен и идемпотентен, его можно вызывать
сколько угодно. `pop()` меняет состояние, но не «теряет» данные. По сигнатуре
сразу видно, меняет ли метод состояние. Именно так устроен `std::stack`.
