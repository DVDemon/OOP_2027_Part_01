# 09. Умные указатели и полиморфизм

**Пункт плана:** 9.

## Что показывает пример

* Коллекцию `std::vector<std::unique_ptr<Shape>>` с разнородными фигурами.
* Фабрику `createShape`, возвращающую владение через `unique_ptr<Shape>`.
* Полиморфные вызовы через умный указатель и `dynamic_pointer_cast`.

## Запуск

```bash
./build/09_polymorphism
```

## Когда что использовать

| Ситуация | Указатель |
|---|---|
| Единоличное владение (95% случаев) | `unique_ptr` |
| Разделяемое владение | `shared_ptr` |
| Наблюдатель без владения (кэш, observer) | `weak_ptr` |
| Не-владеющая ссылка (параметр функции) | сырой указатель или ссылка |

## Плохо → Хорошо

**Плохо** — вектор сырых указателей: владение неясно, легко словить утечку:

```cpp
std::vector<Shape*> shapes;
shapes.push_back(new Circle(5.0));
// придётся вручную delete каждый элемент; при исключении — утечка
```

**Хорошо** — вектор `unique_ptr`: владение явное, освобождение автоматическое:

```cpp
std::vector<std::unique_ptr<Shape>> shapes;
shapes.push_back(std::make_unique<Circle>(5.0));
// деструктор вектора освободит все фигуры
```

**Почему:** базовый класс с виртуальным деструктором плюс `unique_ptr<Base>`
дают полиморфизм без ручного `delete`. Контейнер `unique_ptr` сам разрушает
элементы — даже если заполнение прервётся исключением, уже добавленные фигуры
будут корректно освобождены.
