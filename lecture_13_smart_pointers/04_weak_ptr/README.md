# 04. `std::weak_ptr`

**Пункт плана:** 4.

## Что показывает пример

* Циклическую ссылку из двух `shared_ptr` — деструкторы не вызываются (утечка).
* Разрыв цикла заменой обратной связи на `weak_ptr`.
* Работу с `weak_ptr`: `expired()`, `lock()`.

## Запуск

```bash
./build/04_weak_ptr
```

## Плохо → Хорошо

**Плохо** — оба направления связи владеющие (`shared_ptr`):

```cpp
struct Node {
    std::shared_ptr<Node> next;
    std::shared_ptr<Node> prev;   // цикл a -> b -> a
};
// use_count никогда не упадёт до 0 — объекты не удалятся
```

**Хорошо** — обратная связь не владеет (`weak_ptr`):

```cpp
struct Node {
    std::shared_ptr<Node> next;
    std::weak_ptr<Node> prev;     // не увеличивает счётчик
};
```

**Почему:** `shared_ptr` удаляет объект, когда счётчик сильных ссылок достигает
нуля. В цикле каждый объект держит ссылку на другой, поэтому счётчик не падает
до нуля даже после выхода из области видимости. `weak_ptr` наблюдает за
объектом, но не продлевает его жизнь — это разрывает цикл. Чтобы безопасно
обратиться к объекту через `weak_ptr`, его «повышают» до `shared_ptr`
методом `lock()`.
