# 01. Мотивация: ручное управление памятью + исключения = утечки

**Пункт плана:** 1.

## Что показывает пример

* Почему пара `new`/`delete` ломается при исключениях.
* Как RAII (`std::make_unique`) гарантирует освобождение памяти при любом
  выходе из функции, включая исключение.

## Запуск

```bash
./build/01_motivation
```

## Плохо → Хорошо

**Плохо** — ручной `new`/`delete`. Если между `new` и `delete` бросается
исключение, `delete` не выполнится:

```cpp
int* a = new int(10);
process(a);   // бросает исключение
delete a;     // НЕ выполнится — утечка
```

**Хорошо** — владение выражает `unique_ptr`. Деструктор сработает при выходе
из области видимости по любой причине:

```cpp
auto a = std::make_unique<int>(10);
process(a.get());   // даже если бросит — ~unique_ptr освободит память
```

**Почему:** деструкторы локальных объектов вызываются при раскрутке стека
(stack unwinding). Память, которой владеет умный указатель, освобождается
автоматически — программисту не нужно расставлять `delete` в каждом `catch`.
