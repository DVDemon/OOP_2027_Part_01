# 07. Реализация собственного `UniquePtr` (учебная)

**Пункт плана:** 7.

## Что показывает пример

* Учебную реализацию `edu::UniquePtr` (`unique_ptr.h`): конструкторы,
  перемещение, запрет копирования, `release`, `reset`, `swap`, `operator*`,
  `operator->`, `operator bool`.
* Аналог `make_unique` — `edu::makeUnique`.

## Сборка и запуск

```bash
cmake -S .. -B ../build       # из папки лекции
cmake --build ../build
./../build/07_custom_unique_ptr
```

Цели: `07_custom_unique_ptr` — демонстрация в консоли.

## Плохо → Хорошо

**Плохо** — позволить копирование владеющего указателя:

```cpp
UniquePtr(const UniquePtr& other) : ptr_(other.ptr_) {}   // два владельца!
// при разрушении обоих — двойной delete
```

**Хорошо** — копирование запрещено, владение передаётся только перемещением:

```cpp
UniquePtr(const UniquePtr&) = delete;
UniquePtr(UniquePtr&& other) noexcept : ptr_(other.ptr_) { other.ptr_ = nullptr; }
```

**Почему:** эксклюзивное владение означает, что ресурс принадлежит ровно
одному объекту. Запрет копирования (`= delete`) делает двойное освобождение
невозможным на этапе компиляции, а перемещение явно «обнуляет» источник, чтобы
его деструктор не освободил уже переданный ресурс.

## Какие специальные функции нужны

| Функция | Зачем |
|---------|-------|
| Деструктор | освободить ресурс |
| Копирующий конструктор/присваивание | `= delete` — запрет дублирования владельца |
| Перемещающий конструктор/присваивание | передача владения, обнуление источника |
