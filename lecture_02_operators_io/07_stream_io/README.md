# 07. Потоковый ввод-вывод: `std::cin`, `std::cout`, манипуляторы

**Пункт плана:** 7 — потоковый ввод-вывод и манипуляторы.

## Что показывает пример

* Манипуляторы форматирования: `fixed`/`scientific`, `setprecision`, `setw`,
  `setfill`, `left`/`right`, `dec`/`hex`/`oct`, `showbase`, `boolalpha`.
* Проверку корректности ввода: `if (stream >> value)` и восстановление через `clear()`.
* Классическую ловушку «`>>` оставляет `\n`, и следующий `getline` читает пустую строку».

> Чтобы пример запускался без интерактивного ввода, данные читаются из
> `std::istringstream`. С реальной консолью это был бы `std::cin` — синтаксис идентичен.

## Плохо → Хорошо

**Плохо** — не проверять результат `>>`:

```cpp
int x;
std::cin >> x;          // если ввели не число, x остаётся неинициализированным
use(x);                 // чтение мусора
```

**Хорошо** — проверять поток и восстанавливать его:

```cpp
if (std::cin >> x) { use(x); }
else { std::cin.clear(); std::cin.ignore(1000, '\n'); }
```

**Плохо** — смешивать `>>` и `getline` без очистки буфера:

```cpp
int n; std::cin >> n;             // '\n' остаётся в буфере
std::string s; std::getline(std::cin, s);   // s == "" — прочитан остаток строки
```

**Хорошо** — пропустить остаток строки перед `getline`:

```cpp
std::cin >> n;
std::cin.ignore();                // или ignore(max, '\n')
std::getline(std::cin, s);
```

> **Почему:** оператор `>>` останавливается на пробельном символе и НЕ извлекает
> его из потока. `getline` же читает до `\n` — и сразу натыкается на оставшийся
> перевод строки. Поэтому между ними нужен `ignore`.
