# 11. Неявные и явные преобразования типов

**Пункт плана:** 11 — promotion, usual arithmetic conversions, `static_cast`.
Только базовые типы: `int`, `short`, `char`, `unsigned`, `float`, `double`, `bool`.

## Что показывает пример

* **Неявные преобразования**:
  * расширение `int → double` (безопасно);
  * сужение `double → int` (потеря дробной части);
  * integer promotion `short → int` перед арифметикой;
  * usual arithmetic conversions `int + double → double`;
  * `int → bool` (0 — `false`, любое ненулевое — `true`);
  * `char` в арифметике ведёт себя как целое.
* **Опасности неявных преобразований**: `signed → unsigned` (ловушка `-1 < 1u`),
  переполнение при сужении, потеря значения при `int → short`.
* **`{}`-инициализация** запрещает сужающие преобразования на этапе компиляции.
* **Явные преобразования**: `static_cast` для чисел, `char`, `bool`,
  `unsigned/signed`; почему C-style cast `(int)x` хуже именованных cast'ов.
* **Практические приёмы**: отделить целую и дробную части числа, округление
  через `static_cast` без `<cmath>`.

## Запуск

```bash
./build/11_type_conversions
```

## Плохо → Хорошо

**Плохо** — полагаться на неявное сужение при присваивании:

```cpp
double pi = 3.99;
int x = pi;        // 3 — дробная часть молча потеряна, warning
```

**Хорошо** — сужение намеренно и явно:

```cpp
double pi = 3.99;
int x = static_cast<int>(pi);   // читается однозначно: «сужу осознанно»
```

**Плохо** — неявное смешение `signed`/`unsigned` в сравнении:

```cpp
if (neg < 1u) { ... }   // -1 превращается в 4294967295, условие ЛОЖНО
```

**Хорошо** — явное преобразование, чтобы ловушка была видна:

```cpp
if (static_cast<unsigned int>(neg) < 1u) { ... }
```

> **Почему:** неявные сужающие преобразования незаметно теряют данные, а
> `signed → unsigned` меняет смысл сравнения. `{}`-инициализация и
> `static_cast` делают преобразование явным и проверяемым компилятором.
