# 05. Составные операторы присваивания. `std::numeric_limits`

**Пункт плана:** 5 — составные операторы присваивания; `std::numeric_limits`.

## Что показывает пример

* Все составные операторы: `+= -= *= /= %= <<= >>= &= |=`.
* Границы и свойства типов через `std::numeric_limits`.
* `NaN != NaN` — особенность чисел с плавающей точкой.
* Разницу между переполнением `signed` (UB) и `unsigned` (определённый wraparound).
* Безопасную проверку переполнения ДО операции.

## Запуск

```bash
./build/05_compound_numeric_limits
```

## Плохо → Хорошо

**Плохо** — макросы из C для границ типов:

```cpp
#include <climits>
int m = INT_MAX;        // макрос, не типобезопасно, только для конкретных типов
```

**Хорошо** — `std::numeric_limits`, работает с любым типом и шаблонами:

```cpp
#include <limits>
int m = std::numeric_limits<int>::max();
auto e = std::numeric_limits<double>::epsilon();
```

**Плохо** — складывать, надеясь, что переполнения не будет:

```cpp
int x = std::numeric_limits<int>::max();
x += 1;   // UB для signed: компилятор вправе сделать что угодно
```

**Хорошо** — проверить до операции:

```cpp
if (x > std::numeric_limits<int>::max() - addend) { /* отклонить */ }
else x += addend;
```

> **Почему:** переполнение знакового целого — неопределённое поведение, и
> оптимизатор может «удалить» наивную проверку `x + 1 < x`. Поэтому сравнивать
> нужно через границу из `numeric_limits`, не вызывая само переполнение.
