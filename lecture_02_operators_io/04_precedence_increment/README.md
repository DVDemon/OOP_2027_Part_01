# 04. Приоритет, ассоциативность, инкремент/декремент

**Пункт плана:** 4 — приоритет и ассоциативность операторов; префиксный/постфиксный инкремент.

## Что показывает пример

* Приоритет: `*` выше `+`; `<<` выше сравнений (отсюда скобки в `cout`).
* Ассоциативность: `=` правоассоциативен (`x = y = 5`), `-` левоассоциативен.
* Разницу `++n` (вернуть новое) и `n++` (вернуть старое).
* Почему `++it` предпочтительнее `it++` для итераторов.
* Почему `i = i++ + ++i;` писать нельзя.

## Плохо → Хорошо

**Плохо** — полагаться на память про приоритеты в сложных выражениях:

```cpp
std::cout << a + b == 3;        // разбор: (cout << a+b) == 3 — ошибка компиляции
int t = flags & MASK == 0;      // flags & (MASK == 0) — не то, что хотелось
```

**Хорошо** — скобки делают намерение явным:

```cpp
std::cout << ((a + b) == 3);
int t = (flags & MASK) == 0;
```

**Плохо** — постфиксный инкремент для нетривиальных итераторов:

```cpp
for (auto it = v.begin(); it != v.end(); it++) { ... }  // лишняя копия итератора
```

**Хорошо** — префиксный инкремент:

```cpp
for (auto it = v.begin(); it != v.end(); ++it) { ... }
```

> **Почему:** для встроенных `int` разницы нет, но `it++` обязан вернуть копию
> старого значения, поэтому для итераторов привычка писать `++it` экономит работу.
> А выражения вроде `i = i++` имеют неочевидный/неопределённый порядок — их избегают.
