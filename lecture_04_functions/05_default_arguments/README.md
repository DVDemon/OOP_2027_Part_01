# 05. Аргументы по умолчанию

**Пункт плана:** 5.

## Что показывает пример

* Функция `log` с двумя аргументами по умолчанию (`level`, `timestamp`).
* Вызовы с разным числом переданных аргументов.

## Правила

1. Аргументы по умолчанию — только в **конце** списка параметров (справа налево).
2. Значение по умолчанию указывается **один раз** (обычно в объявлении в `.h`).
3. Нельзя одновременно иметь перегрузку и значение по умолчанию, дающие
   неоднозначность.

## Запуск

```bash
./build/05_default_arguments
```

## Плохо → Хорошо

**Плохо** — перегрузка вместе со значением по умолчанию, дающие двусмысленность:

```cpp
void foo(int a, int b = 10);
void foo(int a);
foo(5);   // ОШИБКА: подходят обе — foo(int) и foo(int, b=10)
```

ПОЧЕМУ плохо: вызов `foo(5)` одинаково хорошо соответствует обеим версиям —
компилятор не может выбрать (ambiguity). Дублирование «способа вызвать с одним
аргументом» создаёт конфликт.

**Хорошо** — выбрать что-то одно: либо значение по умолчанию, либо перегрузку:

```cpp
// Вариант А: только значение по умолчанию
void foo(int a, int b = 10);
foo(5);       // b = 10
foo(5, 20);   // b = 20

// Вариант Б: только перегрузки с разным числом параметров
void foo(int a);
void foo(int a, int b);
```

ПОЧЕМУ хорошо: каждый вызов однозначно сопоставляется ровно с одной функцией.
Значения по умолчанию короче, перегрузки гибче (могут отличаться телом) — но
смешивать их так, чтобы возникала неоднозначность, нельзя.
