# 01. Объявление vs определение функции. Прототипы

**Пункт плана:** 1.

## Что показывает пример

* **Объявление (прототип)** — имя, типы параметров и тип возврата, без тела
  (в `math_utils.h`).
* **Определение** — тело функции, ровно одно на программу (в `math_utils.cpp`).
* Локальный прототип `square` перед `main` с определением ниже — иллюстрация
  того, что компилятору достаточно объявления.
* **ODR** (One Definition Rule): объявлений сколько угодно, определение — одно.

## Запуск

```bash
./build/01_declaration_definition
```

## Плохо → Хорошо

**Плохо** — вызвать функцию, которую компилятор ещё «не видел»:

```cpp
int main() {
    std::cout << square(6);   // ОШИБКА: 'square' не объявлена
}
int square(int x) { return x * x; }
```

ПОЧЕМУ плохо: C++ обрабатывает файл сверху вниз. Без объявления на момент
вызова компилятор не знает типов параметров и возврата и не может проверить
вызов.

**Хорошо** — объявить прототип до использования, определить позже:

```cpp
int square(int x);            // объявление (прототип)

int main() {
    std::cout << square(6);   // OK: вызов проверяется по объявлению
}

int square(int x) {           // единственное определение
    return x * x;
}
```

ПОЧЕМУ хорошо: интерфейс (что функция принимает и возвращает) отделён от
реализации. Это и есть основа разбиения на `.h`/`.cpp`: заголовок содержит
объявления, один `.cpp` — определения, линковщик связывает вызовы.
