# 07. Возвращаемые значения. RVO и NRVO

**Пункт плана:** 7.

## Что показывает пример

Тип `Tracker` печатает сообщение при копировании и при перемещении. По выводу
видно, какие оптимизации сработали:

* `make_prvalue()` — **RVO** (гарантирована с C++17): ни копии, ни перемещения.
* `make_named()` — **NRVO**: обычно тоже без копии/перемещения.
* `make_with_move()` — `return std::move(t)` запрещает NRVO → видно «ПЕРЕМЕЩЕНИЕ».

## Запуск

```bash
./build/07_rvo_nrvo
```

(собирайте без агрессивной отладки, RVO виден и на `-O0`, NRVO — обычно тоже).

## Условия для NRVO

1. Возвращается локальная переменная (не параметр, не глобальная).
2. Тип переменной совпадает с типом возврата.
3. Все пути возврата возвращают одну и ту же переменную.

## Плохо → Хорошо

**Плохо** — «помогать» компилятору через `std::move` при возврате локальной:

```cpp
std::vector<int> bad() {
    std::vector<int> v = {1, 2, 3};
    return std::move(v);   // запрещает NRVO -> навязанное перемещение
}
```

ПОЧЕМУ плохо: `std::move(v)` превращает возврат именованной переменной в
возврат rvalue-выражения. Это отключает NRVO (которая дала бы НОЛЬ операций) и
заставляет компилятор выполнить перемещение. Результат хуже, не лучше.

**Хорошо** — просто вернуть переменную по имени:

```cpp
std::vector<int> good() {
    std::vector<int> v = {1, 2, 3};
    return v;   // NRVO: объект строится прямо в вызывающем коде
}
```

ПОЧЕМУ хорошо: компилятор применяет NRVO и строит результат прямо в памяти
вызывающей стороны — ни копии, ни перемещения. Возврат по значению с C++17 —
эффективный способ по умолчанию.
