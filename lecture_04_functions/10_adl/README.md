# 10. ADL (Argument-Dependent Lookup)

**Пункт плана:** 10.

## Что показывает пример

* ADL находит `geometry::print(p)` без явного `geometry::`, потому что тип
  аргумента `Point` живёт в `namespace geometry`.
* `std::cout << p` работает благодаря тому, что ADL находит
  `geometry::operator<<`.
* Идиома `using std::swap; swap(a, b);` — ADL выбирает специализированный
  `my::swap` для `my::Widget`.

## Запуск

```bash
./build/10_adl
```

## Где ADL критически важен

1. **Операторы** — `std::cout << x` ищет `operator<<` в namespace типа `x`.
2. **Идиома `swap`** — пользовательский `swap` находится автоматически.
3. **`begin`/`end`** для range-based `for` — находятся пользовательские версии.

## Плохо → Хорошо

**Плохо** — жёстко звать `std::swap`, игнорируя специализацию типа:

```cpp
template <typename T>
void swap_two(T& a, T& b) {
    std::swap(a, b);   // всегда обобщённый std::swap, my::swap не используется
}
```

ПОЧЕМУ плохо: квалифицированный вызов `std::swap` отключает ADL. Если у типа
есть оптимизированный `my::swap`, он не будет вызван — теряется эффективность,
а для некоторых типов обобщённый `std::swap` может быть и вовсе неуместен.

**Хорошо** — идиома «два шага»: подключить `std::swap` и вызвать без квалификации:

```cpp
template <typename T>
void swap_two(T& a, T& b) {
    using std::swap;   // std::swap становится кандидатом (fallback)
    swap(a, b);        // ADL предпочтёт my::swap, иначе возьмёт std::swap
}
```

ПОЧЕМУ хорошо: неквалифицированный вызов включает ADL, поэтому для `my::Widget`
выбирается специализированный `my::swap`, а для типов без своего `swap`
сработает `std::swap` из `using`. Это стандартная идиома обобщённого кода.
