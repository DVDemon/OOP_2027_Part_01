# 03. Перегрузка функций

**Пункт плана:** 3.

## Что показывает пример

* Перегрузку по **количеству** параметров (`max_of(a,b)` vs `max_of(a,b,c)`).
* Перегрузку по **типу** параметров (`int` vs `double`).
* Перегрузку по **квалификатору `const`** (`std::string&` vs `const std::string&`).
* Тип возвращаемого значения **не** участвует в разрешении перегрузки.

## Запуск

```bash
./build/03_overloading
```

## Плохо → Хорошо

**Плохо** — пытаться «перегрузить» только по типу возврата:

```cpp
int    parse(const std::string& s);
double parse(const std::string& s);   // ОШИБКА: тот же список параметров
```

ПОЧЕМУ плохо: компилятор выбирает перегрузку по аргументам вызова, а тип
возврата он на этом этапе не знает (вызов может стоять в `auto x = parse(...)`).
Поэтому две функции с одинаковыми параметрами, но разным возвратом — это
переопределение, а не перегрузка → ошибка компиляции.

**Хорошо** — различать перегрузки по списку параметров либо давать разные имена:

```cpp
int    parse_int(const std::string& s);
double parse_double(const std::string& s);
// или перегрузка по параметрам:
int    to_number(const std::string& s, int    tag);
double to_number(const std::string& s, double tag);
```

ПОЧЕМУ хорошо: имя + список параметров образуют сигнатуру, по которой
компилятор однозначно выбирает функцию. Различие в параметрах (или явные разные
имена) делает выбор детерминированным.
