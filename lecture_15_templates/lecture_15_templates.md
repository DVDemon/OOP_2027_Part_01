## 1. Зачем нужны шаблоны

Обычная функция фиксирует типы параметров. Если нужна та же логика для `int`,
`double` и `std::string`, приходится либо дублировать код, либо терять
типобезопасность, приводя всё к `void*`.

```cpp
int    max_int(int a, int b)       { return a > b ? a : b; }
double max_double(double a, double b) { return a > b ? a : b; }
// ...ещё одна копия для каждого типа
```

Шаблон — это **схема функции или класса**, из которой компилятор создаёт
конкретную реализацию для нужных типов. Это называется **обобщённым
программированием**: алгоритм описывается один раз, а типы подставляются на
этапе компиляции.

Ключевое отличие от наследования и виртуальных функций: шаблонный полиморфизм
разрешается **во время компиляции** (статический полиморфизм), поэтому не
платит за виртуальные вызовы, но и не умеет выбирать тип во время выполнения.

## 2. Шаблон функции: синтаксис и инстанцирование

Шаблон объявляется с помощью `template` и списка параметров шаблона:

```cpp
template <typename T>
T max_value(T a, T b) {
    return a > b ? a : b;
}
```

`typename T` (можно писать `class T`) объявляет **параметр-тип**. При вызове
`max_value(3, 7)` компилятор выводит `T = int` и создаёт конкретную функцию —
это **инстанцирование** (instantiation).

```cpp
int    a = max_value(3, 7);          // T = int
double b = max_value(2.5, 1.5);      // T = double
std::string c = max_value(std::string("ab"), std::string("cd"));
```

Требование к типу `T` не записано в сигнатуре явно: он должен поддерживать
`operator>`. Если тип его не поддерживает, ошибка возникнет при инстанцировании,
а не при объявлении шаблона. В C++20 такие требования можно выразить
**концептами** (`requires`), но это тема следующего семестра.

## 3. Вывод аргументов шаблона: `T`, `T&`, `const T&`

Тип `T` выводится из типа аргумента, и форма параметра меняет результат.

### Параметр по значению: `T`

```cpp
template <typename T>
void by_value(T x);

int n = 42;
by_value(n);        // T = int, x — копия
by_value(42);       // T = int
const int c = 1;
by_value(c);        // T = int: const и ссылочность отбрасываются
```

При передаче по значению `T` получает **неквалифицированный** тип: `const`,
`volatile` и ссылка отбрасываются.

### Параметр по ссылке: `T&`

```cpp
template <typename T>
void by_ref(T& x);

int n = 42;
by_ref(n);          // T = int
const int c = 1;
by_ref(c);          // T = const int
// by_ref(42);      // ошибка: временный объект нельзя привязать к T&
```

`T&` сохраняет `const`: аргумент `const int` даёт `T = const int`.

### Параметр по константной ссылке: `const T&`

```cpp
template <typename T>
void by_const_ref(const T& x);

by_const_ref(42);   // T = int, время жизни временного объекта продлено
```

Это удобная форма для «только читать»: принимает и lvalue, и временные
объекты, не копируя их.

### Итог

| Форма параметра | Что выводится | Копирование |
|---|---|---|
| `T` | тип без `const` и ссылки | да |
| `T&` | точный тип, включая `const` | нет |
| `const T&` | тип без ссылки, `const` добавляется | нет |

## 4. Явное указание аргументов и перегрузка

Аргументы шаблона можно указать явно:

```cpp
auto x = max_value<double>(3, 7);   // T = double, 3 и 7 преобразуются к double
```

Это нужно, когда вывод невозможен или когда требуется зафиксировать тип.
Явное указание не выполняет неявных преобразований для вывода: компилятор
берёт ровно указанный тип.

Шаблон участвует в перегрузке вместе с обычными функциями. Правило простое:
**обычная функция предпочтительнее шаблона**, если обе подходят одинаково
хорошо; более специализированный шаблон предпочтительнее более общего.

```cpp
template <typename T>
void print(T x) { std::cout << "template: " << x << '\n'; }

void print(int x) { std::cout << "int: " << x << '\n'; }

print(42);          // обычная функция print(int)
print(3.14);        // шаблон, T = double
print("hello");     // шаблон, T = const char*
```

Перегрузка шаблонов с разным числом параметров тоже работает:

```cpp
template <typename T>
T sum(T a) { return a; }

template <typename T, typename... Rest>
T sum(T a, Rest... rest) { return a + sum(rest...); }
```

(Последний пример — variadic-шаблон; подробно он разбирается в семестре 2.)

## 5. Нетиповые параметры шаблона

Параметром шаблона может быть не только тип, но и **значение** известного на
этапе компиляции типа: целое, указатель, ссылка, `enum`, а с C++20 — также
плавающая точка и литеральные типы классов.

```cpp
template <typename T, std::size_t N>
class Array {
public:
    T& operator[](std::size_t i) { return data_[i]; }
    const T& operator[](std::size_t i) const { return data_[i]; }
    constexpr std::size_t size() const { return N; }

private:
    T data_[N]{};
};

Array<int, 4> a;        // размер — часть типа
static_assert(sizeof(a) == sizeof(int) * 4);
```

Нетиповой параметр позволяет создавать массивы фиксированного размера без
динамической памяти и без потерь производительности. `N` — часть типа:
`Array<int, 4>` и `Array<int, 5>` — разные типы.

С C++17 нетиповой параметр можно выводить через `auto`:

```cpp
template <auto N>
struct Constant {
    static constexpr auto value = N;
};
```

## 6. Где определять шаблон: заголовочный файл

Компилятор должен видеть **тело** шаблона в каждой единице трансляции, где он
инстанцируется. Поэтому шаблоны обычно определяют целиком в заголовочном файле:

```cpp
// math.h
#pragma once

template <typename T>
T max_value(T a, T b) {
    return a > b ? a : b;
}
```

Если вынести определение в `.cpp`, другие единицы трансляции увидят только
объявление и получат ошибку линковки. Исключение — **явное инстанцирование**,
когда набор типов заранее известен:

```cpp
// math.cpp
#include "math.h"

template <typename T>
T max_value(T a, T b) { return a > b ? a : b; }

template int max_value<int>(int, int);
template double max_value<double>(double, double);
```

Явное инстанцирование уменьшает время компиляции и размер кода, но фиксирует
список поддерживаемых типов.

## 7. Шаблон класса: синтаксис

Шаблон класса параметризуется так же, как функция:

```cpp
template <typename T>
class Box {
public:
    explicit Box(T value) : value_(std::move(value)) {}

    const T& get() const { return value_; }
    void set(const T& value) { value_ = value; }

private:
    T value_;
};

Box<int> a(42);
Box<std::string> b("hello");
```

Внутри шаблона имя класса без аргументов (`Box`) означает текущее
инстанцирование `Box<T>`. Вне шаблона нужно писать `Box<int>`, `Box<double>`.

Методы можно определять и вне класса:

```cpp
template <typename T>
class Box {
public:
    explicit Box(T value);
    const T& get() const;
private:
    T value_;
};

template <typename T>
Box<T>::Box(T value) : value_(std::move(value)) {}

template <typename T>
const T& Box<T>::get() const { return value_; }
```

Обратите внимание: перед каждым определением повторяется `template <typename T>`,
а в квалифицированном имени класса указывается `Box<T>`.

## 8. Методы-шаблоны внутри шаблонного класса

Метод может иметь **собственные** параметры шаблона, независимые от параметров
класса:

```cpp
template <typename T>
class Value {
public:
    explicit Value(T v) : value_(v) {}

    // Метод-шаблон: U выводится отдельно от T
    template <typename U>
    U as() const { return static_cast<U>(value_); }

    // Конвертирующий конструктор из другого инстанцирования
    template <typename U>
    Value(const Value<U>& other) : value_(static_cast<T>(other.get())) {}

    T get() const { return value_; }

private:
    T value_;
};

Value<int> i(42);
double d = i.as<double>();       // U = double
Value<double> d2(i);             // конвертирующий конструктор
```

Такой метод не увеличивает размер объекта: каждая пара `(T, U)` создаёт свою
функцию, но данные остаются одного типа `T`.

## 9. Статические члены, CTAD и псевдонимы

### Статические члены

У каждого инстанцирования шаблона **свой** набор статических членов:

```cpp
template <typename T>
class Counter {
public:
    Counter() { ++count_; }
    static int count() { return count_; }
private:
    inline static int count_ = 0;   // C++17: определение в классе
};

Counter<int> a, b;
Counter<double> c;
// Counter<int>::count() == 2, Counter<double>::count() == 1
```

`Counter<int>` и `Counter<double>` — разные типы, поэтому и счётчики разные.

### CTAD (Class Template Argument Deduction, C++17)

Для шаблонов классов компилятор может вывести параметры из аргументов
конструктора:

```cpp
std::pair p(1, 2.5);        // std::pair<int, double>
std::vector v{1, 2, 3};     // std::vector<int>
Box b(42);                  // Box<int>
```

CTAD работает, если из конструктора можно однозначно вывести параметры.
Пользовательские deduction guides позволяют задать правила явно (тема семестра 2).

### Псевдонимы шаблонов

`using` создаёт новое имя для шаблона, в отличие от `typedef`:

```cpp
template <typename T>
using Vec = std::vector<T>;

template <typename T>
using Matrix = std::vector<std::vector<T>>;

Vec<int> v;                 // std::vector<int>
Matrix<double> m;           // std::vector<std::vector<double>>
```

Псевдоним не создаёт новый тип — это лишь другое имя.

## 10. Параметры по умолчанию и практика: `Pair<T, U>`

Параметры шаблона могут иметь значения по умолчанию:

```cpp
template <typename T, typename U = T>
struct Pair {
    T first;
    U second;
};

Pair<int> p1{1, 2};             // Pair<int, int>
Pair<int, double> p2{1, 2.5};   // Pair<int, double>
```

Учебная реализация пары и динамического массива:

```cpp
template <typename T, typename U>
class Pair {
public:
    Pair(T first, U second) : first_(std::move(first)), second_(std::move(second)) {}

    T& first() { return first_; }
    U& second() { return second_; }
    const T& first() const { return first_; }
    const U& second() const { return second_; }

private:
    T first_;
    U second_;
};

template <typename T>
class Vector {
public:
    void push_back(const T& value) {
        if (size_ == capacity_) grow();
        data_[size_++] = value;
    }

    T& operator[](std::size_t i) { return data_[i]; }
    const T& operator[](std::size_t i) const { return data_[i]; }
    std::size_t size() const { return size_; }

private:
    void grow() {
        capacity_ = capacity_ ? capacity_ * 2 : 1;
        auto next = std::make_unique<T[]>(capacity_);
        for (std::size_t i = 0; i < size_; ++i) next[i] = std::move(data_[i]);
        data_ = std::move(next);
    }

    std::unique_ptr<T[]> data_;
    std::size_t size_ = 0;
    std::size_t capacity_ = 0;
};
```

Это упрощённый `std::vector`: он показывает, как шаблон класса сочетает
управление ресурсами (RAII, `unique_ptr`) с обобщённым алгоритмом.

## Ключевые концепции

1. **Шаблон — схема, а не тип.** Конкретный код появляется при инстанцировании.
2. **Вывод аргументов** зависит от формы параметра: `T` отбрасывает `const` и
   ссылку, `T&` сохраняет, `const T&` добавляет `const`.
3. **Обычная функция предпочтительнее шаблона** при равном качестве
   сопоставления; более специализированный шаблон — предпочтительнее общего.
4. **Нетиповые параметры** (`Array<T, N>`) делают размер частью типа.
5. **Шаблон определяется в заголовке**, если не используется явное
   инстанцирование.
6. **У каждого инстанцирования свои статические члены** и свой машинный код.
7. **CTAD** позволяет не писать аргументы шаблона класса явно.
8. **`using`** создаёт псевдоним шаблона, а не новый тип.
9. Шаблоны — основа STL: `vector`, `map`, `sort` и `accumulate` параметризованы
   типами и функторами.

## Типичные ошибки

1. **Определение шаблона в `.cpp` без явного инстанцирования** — ошибка
   линковки: другие единицы трансляции не видят тело.
2. **Ожидание неявного преобразования при выводе** — `max_value(3, 2.5)` не
   компилируется: вывод требует одного типа `T`; нужен явный `max_value<double>`.
3. **`const` в параметре по значению** — `template <typename T> void f(const T x)`
   выводит `T` без `const`; `const` относится к локальной копии.
4. **Забытый `typename` для зависимого имени** — `typename T::value_type`
   требуется в шаблонном контексте.
5. **Статический член, общий для всех типов** — так не бывает: каждый
   `Counter<T>` имеет собственный `count_`.
6. **Слишком общий шаблон** — ошибки проявляются в момент инстанцирования,
   поэтому требования к типу лучше документировать или выражать концептами.
