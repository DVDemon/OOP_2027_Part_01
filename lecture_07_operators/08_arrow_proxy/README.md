# 08. Операторы `*` и `->` (proxy-объекты)

**Пункт плана:** 8.

## Что показывает пример

Пример без шаблонов — только перегрузка `operator*` и `operator->`.

* `WidgetPtr` — «умный» указатель на `Widget`:
  * `operator*` возвращает `Widget&` — сам объект (lvalue, ему можно
    присваивать);
  * `operator->` возвращает `Widget*` — указатель для доступа к членам.
  * Есть const- и не-const-перегрузки: через const-указатель объект
    доступен только для чтения.
* `ArrowProxy` — `operator->` возвращает не указатель, а объект-прокси,
  у которого тоже есть `operator->`. Компилятор повторяет `->`, пока не
  получит настоящий указатель («drill-down»). Прокси логирует начало и
  конец обращения (RAII).
* `DerefProxy` — `operator*` тоже может вернуть прокси. Он ведёт себя
  как `Widget` благодаря `operator Widget&()`, а его конструктор и
  деструктор обрамляют использование объекта.

## Ключевые правила

* `operator*` обычно возвращает ссылку: `*p` — это lvalue, поэтому
  работает `(*p).hello()` и даже `*p = Widget(10)`.
* `operator->` должен вернуть либо указатель, либо объект, у которого
  тоже есть `operator->`. Цепочка разворачивается компилятором:
  `w->hello()` → `w.operator->().operator->()->hello()`.
* Временный прокси живёт до конца полного выражения — поэтому его
  деструктор срабатывает уже после вызова метода или функции.

## Запуск

```bash
./build/08_arrow_proxy
```

## Плохо → Хорошо

**Плохо** — обращаться к объекту напрямую и вручную логировать каждый раз:

```cpp
std::cout << "доступ начат\n";
w.hello();
std::cout << "доступ завершён\n";
```

ПОЧЕМУ плохо: ручной парный код легко забыть; при исключении «завершён»
не напечатается; логирование засоряет вызывающий код.

**Хорошо** — прокси через `operator->`:

```cpp
ArrowProxy operator->() { return ArrowProxy(&obj_); }
// ...
w->hello();   // "начат" — в конструкторе прокси, "завершён" — в деструкторе
```

ПОЧЕМУ хорошо: временный прокси живёт ровно на время выражения. Его
конструктор/деструктор гарантированно обрамляют вызов (даже при
исключении), а вызывающий код остаётся чистым: просто `w->hello()`.
