# 08. Виртуальные вызовы из конструктора и деструктора

**Пункт плана:** 8 — виртуальные вызовы из конструктора/деструктора.

## Что показывает пример

* В конструкторе `Base` виртуальный вызов `init()` идёт в `Base::init`,
  а не в `Derived::init` — даже когда создаётся `Derived`.
* В деструкторе `Base` виртуальный вызов `cleanup()` идёт в `Base::cleanup`,
  потому что часть-потомок уже разрушена.
* Рекомендуемый приём: вызывать виртуальный метод **после** полного построения.

## Запуск

```bash
./build/08_virtual_in_ctor
```

## Плохо → Хорошо

**Плохо** — рассчитывать на полиморфизм в конструкторе:

```cpp
class Base {
public:
    Base() { init(); }            // вызовет Base::init, НЕ Derived::init
    virtual void init() { /* база */ }
};
class Derived : public Base {
    int* buf;
public:
    void init() override { buf = new int[10]; }  // НЕ вызовется из Base()!
    // buf останется неинициализированным -> позже UB
};
```

**Хорошо** — инициализация после конструирования (двухфазная) или через
фабрику, которая строит объект и затем вызывает виртуальный метод:

```cpp
auto d = std::make_unique<Derived>();
d->init();   // объект уже полностью Derived — полиморфизм работает
```

**Почему:** во время работы конструктора `Base` производная часть ещё не
построена, поэтому `vptr` указывает на vtable `Base` — это защитный механизм
языка (иначе виртуальный метод обращался бы к неинициализированным полям
потомка). В деструкторе всё симметрично: потомок уже разрушен.
