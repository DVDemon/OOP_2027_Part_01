# 06. Виртуальный деструктор

**Пункт плана:** 6 — виртуальный деструктор (обязательно!).

## Что показывает пример

* При удалении объекта-потомка через указатель на базовый класс деструктор
  **обязан** быть виртуальным, иначе деструктор потомка не вызовется.
* С виртуальным деструктором `delete Base*` вызывает `~Derived`, затем `~Base`.
* `unique_ptr<Base>` корректно работает при виртуальном деструкторе.

## Запуск

```bash
./build/06_virtual_destructor
```

Ожидаемый вывод (фрагмент): при `delete ptr` сначала `~Derived()`, потом `~Base()`.

## Плохо → Хорошо

**Плохо** — невиртуальный деструктор у полиморфного класса:

```cpp
class Base {
public:
    ~Base() {}                 // НЕ виртуальный
};
class Derived : public Base {
    int* data = new int[1000];
public:
    ~Derived() { delete[] data; }
};

Base* p = new Derived();
delete p;   // UB: вызовется только ~Base(), data НЕ освобождён -> утечка
```

**Хорошо** — виртуальный деструктор:

```cpp
class Base {
public:
    virtual ~Base() = default;   // delete p вызовет ~Derived(), затем ~Base()
};
```

**Почему:** `delete` через `Base*` без виртуального деструктора — формально
неопределённое поведение; на практике вызывается только `~Base`, а ресурсы
потомка утекают. **Правило:** если в классе есть хотя бы одна виртуальная
функция — деструктор делайте виртуальным. Если класс не для наследования —
пометьте его `final`.
