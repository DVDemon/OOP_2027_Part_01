# 07. `dynamic_cast`, RTTI и `typeid`

**Пункт плана:** 7 — `dynamic_cast`, RTTI и `typeid`.

## Что показывает пример

* `dynamic_cast` для **указателя** при неудаче возвращает `nullptr`.
* `dynamic_cast` для **ссылки** при неудаче бросает `std::bad_cast`.
* `typeid` (из `<typeinfo>`) возвращает информацию о фактическом типе в runtime.
* RTTI работает только для **полиморфных** типов (есть хотя бы одна `virtual`).

## Запуск

```bash
./build/07_dynamic_cast_rtti
```

> Имена из `typeid(...).name()` зависят от компилятора (часто «искажены»,
> mangled). Это нормально.

## Плохо → Хорошо

**Плохо** — длинная цепочка `dynamic_cast` ради вызова специфичного поведения:

```cpp
void draw(Base* b) {
    if (auto* c = dynamic_cast<Circle*>(b))    { /* рисуем круг */ }
    else if (auto* r = dynamic_cast<Rect*>(b)) { /* рисуем прямоугольник */ }
    // новый тип -> снова правим эту функцию
}
```

**Хорошо** — виртуальная функция, поведение «внутри» объекта:

```cpp
class Shape { public: virtual void draw() const = 0; };
void draw(const Shape& s) { s.draw(); }   // новый тип не требует правок
```

**Почему:** частый `dynamic_cast` — признак того, что поведение, которое
должно быть виртуальным методом, «вынесено наружу». Это нарушает OCP и
дублирует диспетчеризацию. `dynamic_cast`/`typeid` оправданы лишь в редких
случаях (например, сериализация, отладка, взаимодействие с чужим API).
