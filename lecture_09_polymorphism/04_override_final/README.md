# 04. Спецификаторы `override` и `final`

**Пункт плана:** 4 — спецификаторы `override` и `final`.

## Что показывает пример

* `override` — компилятор проверяет, что метод реально переопределяет
  виртуальную функцию базового класса (ловит опечатки и расхождения сигнатур).
* `final` у метода — запрещает дальнейшее переопределение.
* `final` у класса — запрещает наследование от него.

## Запуск

```bash
./build/04_override_final
```

## Плохо → Хорошо

**Плохо** — переопределение «по памяти», без `override`:

```cpp
class Base    { public: virtual void process(int x) const; };
class Derived : public Base {
public:
    void process(int x) { /* ... */ }   // забыли const!
    // Это НЕ override, а новая перегрузка. Компилятор молчит.
    // Через Base& вызовется Base::process — тихий баг.
};
```

**Хорошо** — `override` превращает ошибку в ошибку компиляции:

```cpp
class Derived : public Base {
public:
    void process(int x) const override { /* ... */ }
    // Если сигнатура не совпадёт с виртуальной из Base — ошибка компиляции.
};
```

**Почему:** малейшее расхождение в сигнатуре (`const`, тип параметра, опечатка
в имени) без `override` создаёт новую функцию вместо переопределения. Баг
проявляется в runtime неверным поведением. `override` ловит это на компиляции.
`final` дополнительно фиксирует контракт и помогает девиртуализации (см. 09).
