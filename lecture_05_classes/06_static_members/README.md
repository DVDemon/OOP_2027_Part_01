# 06. Статические поля и методы

**Пункт плана:** 6 — статические поля и методы, `inline static` (C++17).

## Что показывает пример

* Статические поля (`instance_count_`, `prefix_`) принадлежат **классу**, а не
  объекту — они общие для всех экземпляров.
* `inline static` (C++17) позволяет инициализировать статическое поле прямо в
  теле класса, без отдельной строки в `.cpp`.
* Статический метод (`getInstanceCount`, `setPrefix`) не имеет `this` и не видит
  нестатические поля; вызывается через имя класса: `Logger::getInstanceCount()`.
* Конструктор увеличивает счётчик, деструктор уменьшает — видно по выводу.

## Плохо → Хорошо

**Плохо** — до C++17: определить статическое поле прямо в заголовке без `inline`:

```cpp
// logger.h — ПЛОХО
class Logger {
    static int instance_count_ = 0;  // ошибка: нельзя инициализировать так,
};                                   // а определение в .h без inline нарушает ODR
```

Если заголовок с определением `int Logger::instance_count_ = 0;` включат две
`.cpp`, линковщик увидит **два** определения → ошибка «multiple definition».

**Почему плохо:** классическое статическое поле требует ровно одного определения
в одном `.cpp`, иначе нарушается ODR. Это легко забыть.

**Хорошо** — C++17 `inline static`: одно определение в заголовке, без `.cpp`:

```cpp
class Logger {
    inline static int instance_count_ = 0;       // OK в любом числе единиц трансляции
    inline static std::string prefix_ = "[LOG]";
};
```

(До C++17 альтернатива — объявление в `.h` и единственное определение в `.cpp`:
`int Logger::instance_count_ = 0;`.)

**Вывод:** в C++17+ предпочитайте `inline static` — это короче и исключает
ошибки множественного определения.
