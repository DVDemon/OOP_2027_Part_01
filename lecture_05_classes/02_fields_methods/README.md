# 02. Поля и методы: внутри класса и в `.cpp`

**Пункт плана:** 2 — поля и методы; определение внутри и вне класса.

## Что показывает пример

* Поля (`x_`, `y_`) и методы класса `Point`.
* Метод можно определить **внутри** тела класса (неявно `inline`) — это удобно
  для коротких тривиальных функций (`getX`, `getY`).
* Можно вынести **только объявление** в `point.h`, а реализацию — в `point.cpp`,
  квалифицируя имя как `Point::distanceTo`.

cmake -S .. -B ../build       # из папки лекции

./../build/02_fields_methods

## Плохо → Хорошо

**Плохо** — определять ВСЕ методы прямо в заголовке, включая тяжёлую логику:

```cpp
// point.h — ПЛОХО
#include <cmath>   // <cmath> подтянется во ВСЕ единицы трансляции, включающие point.h
class Point {
    double x_, y_;
public:
    double distanceTo(const Point& o) const {
        return std::sqrt((x_-o.x_)*(x_-o.x_) + (y_-o.y_)*(y_-o.y_));
    }
};
```

**Почему плохо:** реализация в заголовке тянет лишние `#include`, раздувает
зависимости и заставляет перекомпилировать всех клиентов при любой правке тела
метода.

**Хорошо** — в заголовке объявление, реализация в `.cpp`:

```cpp
// point.h
class Point {
    double x_, y_;
public:
    double getX() const { return x_; }      // тривиально — оставляем inline
    double distanceTo(const Point& o) const; // объявление
};

// point.cpp
#include "point.h"
#include <cmath>                              // include только здесь
double Point::distanceTo(const Point& o) const { /* ... */ }
```

**Вывод:** короткие геттеры — в заголовок, нетривиальную логику и тяжёлые
зависимости — в `.cpp`. Это ускоряет сборку и уменьшает связность.
