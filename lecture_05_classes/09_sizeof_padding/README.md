# 09. `sizeof`, выравнивание и padding

**Пункт плана:** 9 — `sizeof`, выравнивание и padding.

## Что показывает пример

* Компилятор выравнивает поля: каждое поле размещается на адресе, кратном его
  `alignof`, между полями появляются «дыры» (padding).
* Порядок полей влияет на `sizeof`: `Bad{char, double, char}` крупнее, чем
  `Good{double, char, char}` с теми же полями.
* `sizeof(Empty) >= 1` — пустой класс занимает минимум 1 байт (уникальность адреса).
* `alignas(16)` задаёт более строгое выравнивание (`AlignedData`).
* `offsetof` показывает реальные смещения полей и места padding.

> Конкретные значения зависят от платформы/ABI; на типичной x86-64
> `sizeof(Bad) == 24`, `sizeof(Good) == 16`.

## Сборка и запуск

```bash
cmake -S .. -B ../build       # из папки лекции
cmake --build ../build
./../build/09_sizeof_padding
```

## Плохо → Хорошо

**Плохо** — складывать поля в «естественном» порядке, не думая о выравнивании:

```cpp
struct Particle {
    char  type;     // 1 + 7 padding
    double x, y, z; // 24
    char  flag;     // 1 + 7 padding
};  // sizeof == 40, при миллионе частиц — лишние ~16 МБ
```

**Почему плохо:** мелкие поля между крупными создают padding. На массивах из
миллионов объектов это заметный перерасход памяти и хуже работа кэша процессора.

**Хорошо** — сортировать поля по убыванию размера/выравнивания:

```cpp
struct Particle {
    double x, y, z; // 24
    char  type;     // 1
    char  flag;     // 1 + 6 padding
};  // sizeof == 32
```

**Вывод:** при большом числе объектов располагайте поля от крупных к мелким,
чтобы сократить padding. Для специальных требований (SIMD) применяйте `alignas`.
Проверяйте раскладку через `sizeof`, `alignof` и `offsetof`.
