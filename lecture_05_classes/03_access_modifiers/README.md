# 03. Модификаторы доступа

**Пункт плана:** 3 — `public`, `protected`, `private`.

## Что показывает пример

* `public` — часть интерфейса, доступна всем (`getBalance`, `deposit`).
* `protected` — доступна классу и наследникам, но не внешнему коду (`setOwner`).
* `private` — только самому классу (`owner_`, `balance_`).
* Наследник `AdminAccount` может вызвать `protected`-метод, но не трогает
  `private`-поля базового класса напрямую.

| Модификатор | Из класса | Из наследника | Извне |
|-------------|:---:|:---:|:---:|
| `public`    | да  | да  | да  |
| `protected` | да  | да  | нет |
| `private`   | да  | нет | нет |

## Плохо → Хорошо

**Плохо** — все поля `public`, любой меняет состояние в обход проверок:

```cpp
struct Account {
    double balance;  // public
};
Account a;
a.balance = -1000;   // прямой переход в недопустимое состояние
```

**Почему плохо:** инвариант «баланс контролируется правилами» нарушается
снаружи без всякой проверки. Класс не может гарантировать корректность.

**Хорошо** — поля `private`, изменение только через методы с проверкой:

```cpp
class Account {
    double balance_ = 0.0;   // private
public:
    void deposit(double amount) {
        if (amount > 0) balance_ += amount;  // инвариант защищён
    }
    double getBalance() const { return balance_; }
};
```

**Вывод:** делайте поля `private` по умолчанию, `protected` — только то, что
действительно нужно наследникам, `public` — лишь продуманный интерфейс.
