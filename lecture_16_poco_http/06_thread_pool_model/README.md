# 06. Модель пула потоков

**Пункт плана:** 6 — модель пула потоков.

## Что показывает раздел

Обзорный материал без кода (сборка не требуется). Как `HTTPServer` обслуживает
много клиентов ограниченным числом потоков.

## Схема

```
[Клиент 1] ──TCP──┐
[Клиент 2] ──TCP──┤     ┌──────────────────┐
[Клиент 3] ──TCP──┼────>│   HTTPServer      │
[Клиент N] ──TCP──┘     │   (ServerSocket)  │
                        └──────┬────────────┘
                               │
                   ┌───────────┼───────────┐
                   │           │           │
              [Thread 1]  [Thread 2]  [Thread N]
                   │           │           │
              Handler     Handler     Handler
             (создан)    (создан)    (создан)
             (удалён)    (удалён)    (удалён)
```

* Сервер слушает один сокет и принимает соединения.
* Каждое соединение отдаётся свободному потоку из пула.
* В потоке фабрика создаёт обработчик, сервер вызывает `handleRequest`,
  затем обработчик уничтожается.
* Если все потоки заняты — запрос ждёт в очереди; при переполнении очереди новые
  соединения отклоняются.

## Настройка через HTTPServerParams

```cpp
auto* params = new Poco::Net::HTTPServerParams;
params->setMaxThreads(16);                       // максимум рабочих потоков
params->setMaxQueued(256);                       // максимум запросов в очереди
params->setKeepAlive(true);                      // HTTP Keep-Alive
params->setKeepAliveTimeout(Poco::Timespan(10, 0));
params->setTimeout(Poco::Timespan(30, 0));       // таймаут соединения
params->setSoftwareVersion("MyApp/1.0");         // заголовок Server:
```

`HTTPServer` берёт владение объектом `params` (выделенным через `new`) и удалит
его сам — освобождать вручную не нужно.

## Следствия для кода обработчика

* **Не блокируйте поток** надолго (сеть, диск, тяжёлые вычисления) — поток из
  пула не сможет обслуживать другие запросы. Под нагрузкой это «съедает» пул.
* Разделяемое состояние (кэш, БД-соединение) живёт **вне** обработчика и должно
  быть потокобезопасным, т.к. обработчики работают параллельно в разных потоках.

## Плохо → Хорошо

**Плохо** — блокирующая операция прямо в обработчике занимает поток пула:

```cpp
void handleRequest(...) override {
    std::this_thread::sleep_for(std::chrono::seconds(30)); // держит поток!
    response.send() << "done";
}
```

**Хорошо** — короткая обработка; тяжёлую работу выносят в отдельный сервис/очередь
или увеличивают `setMaxThreads` осознанно под профиль нагрузки.
