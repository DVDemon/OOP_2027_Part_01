# 05. Частотный анализ слов: всё вместе

**Пункт плана:** 7 — прикладной пример, соединяющий все компоненты STL.

## Что показывает пример

Полноценная мини-программа «частота слов в тексте»:

1. `std::map<std::string, int>` — считаем частоты за O(n log n); `operator[]`
   в этой роли честно работает (вставка с умолчанием = «новое слово, частота 1»).
2. `std::vector<std::pair<...>>` — переносим пары из map в вектор, потому что
   map отсортирован **по ключу**, а нам нужна сортировка **по частоте**.
3. `std::sort` + лямбда-компаратор — сортируем по убыванию частоты.
4. Вывод топ-N.

Этот же приём — «таблица в памяти → обработка алгоритмами» — лежит в основе
лабораторной №6 (реляционные данные в памяти).

## Сборка и запуск

```bash
cmake -S .. -B ../build       # из папки лекции

```

## Плохо → Хорошо

**Плохо** — тот же подсчёт частот вручную, паралелльными структурами без map:

```cpp
// массив найденных «слово, частота» + линейный поиск на каждое слово
// -> O(n^2) и легко ошибиться в поиске/сравнении.
```

**Почему плохо:** на каждом слове линейно ищем, нет ли его уже в списке — при n
уникальных слов это O(n²). Код разбухает и дублирует то, что красно-чёрное дерево
`map` делает гарантированно и за O(log n).

**Хорошо** — `map` берёт на себя и поиск, и уникальность ключей:

```cpp
std::map<std::string, int> freq;
for (const auto& word : text)
    ++freq[word];               // новый ключ — вставка с 0, затем ++; готовый — ++
```

**Почему хорошо:** `map` автоматически объединяет повторяющиеся слова (ключи
уникальны), а `operator[]` с последующим `++` — ровно тот случай, когда вставка по
умолчанию уместна и элегантна. Дальше — стандартные алгоритмы, ни одного ручного
цикла по данным.
