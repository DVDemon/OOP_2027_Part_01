# 02. `std::map` и `std::set`

**Пункт плана:** 3 — ассоциативные контейнеры.

## Что показывает пример

* `std::map` — красно-чёрное дерево: пары «ключ → значение», автоматический
  порядок по ключу, поиск/вставка/удаление за **O(log n)**.
* `find`, `count`, `at`, `operator[]` и **ловушка `operator[]`**: при отсутствии
  ключа он молча **вставляет** элемент со значением по умолчанию.
* `std::set` — множество уникальных ключей: устранение дубликатов и проверка
  принадлежности.

## Плохо → Хорошо

**Плохо** — проверяем наличие ключа через `operator[]`:

```cpp
std::map<std::string, int> scores;
// ...наполняем scores...

if (scores["Петя"] >= 60)        // если "Петя" отсутствовал — он ТЕПЕРЬ есть!
    std::cout << "Петя сдал\n";
std::cout << scores.size() << '\n';   // неожиданно выросло на 1
```

**Почему плохо:** `operator[]` при отсутствии ключа **вставляет** элемент со
значением по умолчанию (0). В «чтение» вклинивается побочный эффект записи:
размер контейнера меняется, а повторное чтение даёт уже другое состояние.

**Хорошо** — для проверки наличия и чтения использовать `find` или `count`:

```cpp
auto it = scores.find("Петя");
if (it != scores.end() && it->second >= 60)
    std::cout << "Петя сдал\n";
// размер контейнера не изменился
```

**Почему хорошо:** `find` возвращает итератор на пару `(key, value)` или `end()` —
контейнер не модифицируется. `operator[]` оставляем только там, где вставка с
умолчанием действительно нужна (например, подсчёт частот).
