# 03. Итераторы: единый способ обхода

**Пункт плана:** 4 — концепция итераторов.

## Что показывает пример

* **Единый интерфейс обхода** любого контейнера: `begin()`, `end()`, `*it`,
  `++it`, `it != end()`.
* **Полуоткрытый интервал** `[begin, end)`: `end()` указывает «за последний»
  элемент, поэтому пустой контейнер — это `begin == end`.
* **range-for** — синтаксический сахар: компилятор сам раскрывает его в цикл по
  итераторам.
* Один и тот же код обходит `std::vector` и `std::map` (у map итератор указывает
  на пару «ключ → значение»).

## Сборка и запуск

```bash
cmake -S .. -B ../build       # из папки лекции
cmake --build ../build
./../build/03_iterators
```

## Плохо → Хорошо

**Плохо** — свой цикл для каждого контейнера с использованием его «внутренностей»:

```cpp
// вектор обходим по индексу...
for (int i = 0; i < v.size(); ++i)
    use(v[i]);

// ...а список так обойти нельзя (нет operator[]), пришлось писать отдельный цикл
```

**Почему плохо:** код обхода привязан к устройству контейнера. Добавили новый
контейнер — написали ещё один вариант цикла. Ошибки «на один элемент» и
переполнение индекса — частые спутники ручных циклов.

**Хорошо** — единый обход через итераторы, одинаковый для всех контейнеров:

```cpp
for (auto it = c.begin(); it != c.end(); ++it)
    use(*it);
```

**Почему хорошо:** итератор скрывает устройство контейнера. Один и тот же фрагмент
кода работает и для `vector`, и для `map`, и для `set`. А `range-for` делает его ещё
короче — цикл по итераторам компилятор генерирует сам.
