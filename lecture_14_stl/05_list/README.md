# 05. `std::list` — двусвязный список

**Блок плана:** 5 — `std::list`: блочная структура в куче, инвалидация указателей.

## Что показывает пример

* **Узлы лежат отдельно.** Адреса элементов списка не идут подряд: каждый
  `push_back`/`push_front` выделяет отдельный блок в куче.
* **Указатели на элементы стабильны.** Указатель на `3` переживает `push_front`,
  `push_back`, `pop_front`, `sort` и `remove_if` чужих элементов.
* **`erase` инвалидирует только удалённый** элемент (в отличие от `vector`).
* **`splice` за O(1):** узлы переезжают из одного списка в другой без копирования,
  адрес элемента сохраняется.
* **Нет `operator[]`:** доступ к N-му элементу — через `std::advance` за O(n).
* **Member-функции `sort`, `remove_if`:** `std::sort` требует random access и для
  `list` не компилируется; `l.sort()` переставляет узлы, а не значения.
* **Цена:** узел = значение + два указателя (≈24 байта на `int`) плюс отдельная
  аллокация; обход промахивается мимо кэша.

## Плохо → Хорошо

**Плохо** — выбирать `list` «потому что вставки быстрые» и работать с ним как с
массивом:

```cpp
std::list<int> l = ...;
l[3];                            // не компилируется: оператора [] нет
std::sort(l.begin(), l.end());   // не компилируется: нужен random access
```

**Почему плохо:** `list` не даёт произвольного доступа, а обход по узлам медленнее
обхода непрерывного буфера из-за промахов кэша. На типичных задачах «пройти и
найти» `vector` часто быстрее даже с учётом сдвигов.

**Хорошо** — `list` там, где нужны стабильные адреса и перенос узлов:

```cpp
int* p = &l.back();
l.push_front(0);          // p по-прежнему валиден
l.splice(pos, other);     // узлы other переехали за O(1), адреса те же
l.sort();                 // member-сортировка, узлы переставляются
```

**Почему хорошо:** вставка/удаление/перенос не трогают остальные узлы, поэтому
указатели и ссылки на них остаются валидными. Это ровно то свойство, которого нет
у `vector` при реаллокации.

## Фрагмент вывода

```
=== 1. Узлы: адреса элементов не рядом ===
  1 -> 0x13fe05eb0
  2 -> 0x13fe05e10
  3 -> 0x13fe05e30

=== 2. Указатели на элементы стабильны ===
p -> 3
после push_front/push_back: p -> 3 (тот же узел, указатель не инвалидирован)

=== 5. splice: перенос узлов за O(1), без копий ===
l после splice [6]: 1 2 10 20 3 4 
other после splice [0]: 
q -> 10 (узел переехал, адрес тот же)

=== 6. Сортировка и remove_if — member-функции ===
после sort [6]: 1 2 3 4 10 20 
p -> 3 (после sort указатель всё ещё валиден)
```

Адреса зависят от запуска; важно, что они не образуют непрерывный блок.
