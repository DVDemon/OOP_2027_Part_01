## 1. Общий принцип: контейнер — владелец памяти
> **Пример:** [01_containers](01_containers)

### 1.1. Проблема сырого динамического массива

В C динамический массив собирают вручную: указатель на буфер, текущий размер,
вместимость и набор функций `init`/`push`/`free`. В каждом проекте такая
реализация своя, и в каждой есть свои ошибки:

```cpp
int* data = new int[3];
std::size_t size = 0;
std::size_t capacity = 3;

// push_back вручную: проверка capacity, new[], копирование, delete[]
// ...

delete[] data;   // забыли на одной из веток — утечка
```

Три сущности — указатель, размер, вместимость — живут отдельно и легко
рассогласовываются. Копирование по умолчанию копирует указатель, а не данные:
две структуры начинают владеть одним буфером, и первая же `delete[]` оставляет
вторую с висячим указателем.

### 1.2. RAII: владение привязано к объекту

Контейнер STL решает это идиомой **RAII** (Resource Acquisition Is
Initialization): ресурс захватывается в конструкторе и освобождается в деструкторе.

* **Деструктор** освобождает буфер — не нужно помнить о `delete[]` и не страшны
  исключения: при разворачивании стека деструктор вызовется.
* **Копирование** делает глубокую копию: новый буфер, поэлементное копирование.
* **Перемещение** передаёт владение: указатель на буфер переходит новому объекту,
  источник остаётся пустым. Копирования элементов нет.

```cpp
{
    std::vector<int> v{1, 2, 3};
    v.push_back(4);
}   // здесь деструктор освободил буфер
```

Именно поэтому в прикладном коде на C++ не нужны `new[]`/`delete[]`: контейнер
уже является владельцем. Правило нуля из лекции 10 работает и здесь: если класс
состоит из контейнеров и умных указателей, свои деструктор и правило пяти писать
не нужно.

### 1.3. Из чего состоит контейнер

У контейнера три уровня:

| Уровень | Где лежит | Что это |
|---------|-----------|---------|
| **Объект-метаданные** | стек (если контейнер локальный) | указатель на данные, размер, вместимость или указатели на узлы |
| **Данные** | куча или сам объект | непрерывный буфер (`vector`), узлы (`list`, `map`), элементы внутри объекта (`array`) |
| **Аллокатор** | внутри объекта | политика выделения/освобождения памяти |

```cpp
std::vector<int> v{1, 2, 3};
// sizeof(v) == 24 (обычно три указателя), а элементы — в отдельном буфере в куче
```

У `std::array` метаданных нет вообще: размер — часть типа, элементы лежат прямо в
объекте. У `std::list` в объекте лежат служебные указатели, а каждый элемент —
отдельный узел в куче. Подробно эти три модели разбираются в разделах 3–5.

### 1.4. Аллокатор — сменная политика выделения

Контейнеры STL параметризованы типом аллокатора:

```cpp
template <class T, class Allocator = std::allocator<T>>
class vector;
```

`std::allocator<T>` — стандартная реализация поверх `operator new`. Аллокатор
можно заменить, не меняя код работы с контейнером: он определяет, **откуда**
берётся память (обычная куча, пул, арена, разделяемая память) и **как**
учитываются запросы.

Минимальный аллокатор в C++20 выглядит так:

```cpp
namespace mem {                       // счётчики общие для всех инстанциаций
inline std::size_t allocations = 0;
inline std::size_t deallocations = 0;
}

template <class T>
struct CountingAllocator {
    using value_type = T;

    T* allocate(std::size_t n) {
        ++mem::allocations;           // свой учёт
        return std::allocator<T>{}.allocate(n);
    }

    void deallocate(T* p, std::size_t n) noexcept {
        ++mem::deallocations;
        std::allocator<T>{}.deallocate(p, n);
    }

    template <class U>
    CountingAllocator(const CountingAllocator<U>&) noexcept {}   // перевоплощение

    template <class U>
    bool operator==(const CountingAllocator<U>&) const noexcept { return true; }
};
```

Что важно понимать:

* контейнер запрашивает память **не поэлементно**, а блоками: `vector` просит
  `n` элементов под буфер, `list` — один узел на элемент (через `rebind`);
* аллокатор должен уметь «перевоплотиться» в аллокатор другого типа — списку
  нужны не `int`, а узлы списка;
* аллокаторы бывают **stateful** (со своим состоянием) и **stateless**; от этого
  зависят правила копирования и перемещения контейнера
  (`propagate_on_container_move_assignment`, `select_on_container_copy_construction`);
* в C++17 появился `std::pmr` — полиморфные аллокаторы с `memory_resource`,
  удобные для арен и пулов.

Замер из примера 01:

```
vector: 100 push_back: allocate=8  deallocate=7  bytes=1020
list:   100 push_back: allocate=100 deallocate=0  bytes=2400
```

`vector` растёт кратно и просит память редко, но крупными кусками; `list`
выделяет отдельный узел на каждый элемент. Это первое практическое следствие
выбора модели хранения.

### 1.5. Требования к элементам

Контейнер — шаблон, поэтому он работает с любым типом `T`, у которого есть нужные
операции:

| Контейнер | Что требуется от `T` |
|-----------|----------------------|
| `vector`, `array` | копирование и/или перемещение; для эффективной реаллокации — `noexcept`-перемещение |
| `list` | копирование/перемещение; адрес элемента не меняется |
| `map`, `set` | ключ сравним через `<` (или свой компаратор) |
| любой | деструктор освобождает ресурсы (RAII) |

Если тип не перемещается и не копируется, `vector` не сможет реаллоцироваться
(точнее, не скомпилирует часть операций). Если у ключа нет `<`, `map` не
скомпилируется без явного компаратора.

## 2. Итераторы: единый интерфейс доступа
> **Пример:** [02_iterators](02_iterators)

### 2.1. Интерфейс

Итератор — объект, который указывает на элемент контейнера и умеет перемещаться
к следующему. У всех контейнеров одинаковый минимальный набор:

| Выражение | Смысл |
|-----------|-------|
| `c.begin()` | итератор на первый элемент |
| `c.end()` | итератор «за последним» |
| `*it` | доступ к текущему элементу |
| `it->field` | доступ к члену (для `map` — `it->first`/`it->second`) |
| `++it` | переход к следующему |
| `it == jt`, `it != jt` | сравнение |

```cpp
for (auto it = v.begin(); it != v.end(); ++it)
    std::cout << *it << ' ';
```

### 2.2. Полуоткрытый интервал `[begin, end)`

`end()` указывает **за последний** элемент, а не на него. Поэтому:

* длина диапазона равна `end() - begin()` (для random access) или
  `std::distance(begin, end)`;
* пустой контейнер — это `begin() == end()`, и цикл `for (it = begin; it != end;
  ++it)` для него безопасен;
* алгоритмы принимают именно пару `[first, last)` и никогда не разыменовывают
  `last`.

### 2.3. Категории итераторов

Категория — это контракт: какие операции итератор поддерживает. От неё зависит,
какие алгоритмы применимы.

| Категория | Умеет | Контейнеры |
|-----------|-------|------------|
| input | один проход вперёд, чтение | потоки ввода |
| forward | многократный проход вперёд | `forward_list`, `unordered_*` |
| bidirectional | `++it`, `--it` | `list`, `map`, `set` |
| random access | `it + n`, `it - it`, `it[n]` | `array`, `vector`, `deque`, `string` |

```cpp
std::vector<int> v{5, 3, 8, 1};
std::list<int>   l{3, 1, 2};

std::sort(v.begin(), v.end());   // OK: random access
// std::sort(l.begin(), l.end()); // ошибка: list — bidirectional
l.sort();                        // у list своя сортировка
```

`std::distance` для `vector` — O(1) (вычитание указателей), для `list` — O(n)
(шаги по узлам). Это не «медленный стандарт», а честная цена модели хранения.

### 2.4. range-for — синтаксический сахар

```cpp
for (const auto& x : v)   // читаем без копий
    use(x);

for (auto& x : v)         // меняем элементы
    ++x;
```

Компилятор раскрывает это в итераторный цикл. `const auto&` предпочтителен для
больших объектов: `for (auto x : v)` копирует каждый элемент.

### 2.5. Инвалидация

| Контейнер | Что инвалидирует итераторы и указатели |
|-----------|----------------------------------------|
| `array` | ничего: размер фиксирован, буфер не переезжает |
| `vector` | реаллокация при росте; `insert`/`erase` — итераторы после точки вставки/удаления |
| `list` | только итератор/указатель на удалённый элемент |

Это ключевая таблица лекции: она объясняет, почему `vector` нельзя «держать
итератор через `push_back`», а `list` можно.

## 3. `std::array` — статический массив на стеке
> **Пример:** [03_array](03_array)

### 3.1. Что это

`std::array<T, N>` — массив фиксированного размера `N`, элементы лежат **внутри
объекта**. Если объект локальный, он целиком находится в кадре стека; кучи нет.

```cpp
#include <array>

std::array<int, 5> a{5, 3, 8, 1, 4};
std::cout << a.size() << '\n';       // 5 — известно на этапе компиляции
std::cout << sizeof(a) << '\n';      // 20 == 5 * sizeof(int)
```

### 3.2. Чем лучше C-массива

```cpp
void f(int a[]);                  // внутри sizeof(a) == sizeof(int*)
int c[5] = {1, 2, 3, 4, 5};
c == c;                           // сравниваются указатели, не элементы
```

C-массив при передаче в функцию **decay**-ится в указатель: размер теряется.
`std::array` — обычное значение:

```cpp
template <class T, std::size_t N>
void print(const std::array<T, N>& a);   // N известен

std::array<int, 5> b = a;                 // полная копия
if (a == b) { /* поэлементное сравнение */ }
```

### 3.3. Основные операции

| Операция | Смысл |
|----------|-------|
| `a[i]` | доступ без проверки границ |
| `a.at(i)` | доступ с проверкой, бросает `std::out_of_range` |
| `a.front()`, `a.back()` | первый/последний элемент |
| `a.data()` | указатель на первый элемент |
| `a.fill(x)` | заполнить значением |
| `std::get<i>(a)` | доступ по индексу, известному компилятору |

`std::array` работает с алгоритмами STL и с range-for как любой контейнер:
`std::sort`, `std::accumulate`, `std::min_element`.

### 3.4. Размер — часть типа

```cpp
constexpr std::array<int, 3> ca{1, 2, 3};
static_assert(ca.size() == 3);
static_assert(std::get<1>(ca) == 2);

std::array deduced{10, 20, 30};   // CTAD: std::array<int, 3>
```

Размер нельзя изменить в рантайме: `std::array` не умеет расти. Если количество
элементов заранее неизвестно — нужен `vector`.

### 3.5. Стек не резиновый

```cpp
std::array<int, 1'000'000> big;   // ~4 МБ в кадре стека
```

Типичный размер стека — 1–8 МБ. Большой локальный `array` легко переполняет стек;
для больших массивов берут `std::vector` (данные в куче) или `std::unique_ptr<T[]>`.

### 3.6. Плохо → Хорошо

**Плохо:** C-массив, который не знает размера и не копируется по значению.

**Хорошо:** `std::array<T, N>` — размер в типе, value-семантика, алгоритмы STL,
нулевые накладные расходы по сравнению с C-массивом.

## 4. `std::vector` — динамический массив в куче
> **Пример:** [04_vector](04_vector)

### 4.1. Устройство

`std::vector<T>` хранит элементы **непрерывно**. Объект-метаданные обычно состоит
из трёх указателей: начало буфера, конец заполненной части, конец выделенной
памяти. Отсюда `size()` и `capacity()`.

* `size()` — сколько элементов сейчас;
* `capacity()` — сколько помещается без нового выделения.

```cpp
std::vector<int> v;
std::cout << v.size() << ' ' << v.capacity() << '\n';   // 0 0
for (int i = 0; i < 5; ++i) {
    v.push_back(i);
    std::cout << v.size() << ' ' << v.capacity() << '\n';
}
```

### 4.2. Рост и амортизированная сложность

Когда `size()` достигает `capacity()`, вектор:

1. выделяет новый буфер (обычно в 1.5–2 раза больше);
2. **перемещает** туда элементы (если перемещение `noexcept`, иначе копирует);
3. освобождает старый буфер.

Поэтому отдельный `push_back` иногда стоит O(n), но **амортизированно** — O(1):
сумма по серии вставок линейна.

```cpp
struct Tracked {
    static inline int copies = 0, moves = 0;
    int value;
    explicit Tracked(int v) : value(v) {}
    Tracked(const Tracked& o) : value(o.value) { ++copies; }
    Tracked(Tracked&& o) noexcept : value(o.value) { ++moves; }
};

std::vector<Tracked> v;
v.reserve(1);
for (int i = 0; i < 5; ++i) v.emplace_back(i);
// copies == 0, moves == 7 — элементы перенесены
```

Именно `noexcept`-перемещение (лекция 10) делает рост вектора дешёвым. Если
перемещающий конструктор не `noexcept`, вектор вынужден копировать элементы,
чтобы сохранить строгую гарантию безопасности исключений.

### 4.3. Инвалидация итераторов

```cpp
std::vector<int> v{1, 2, 3};
auto it = v.begin();
v.push_back(4);      // буфер переехал
// *it — неопределённое поведение
```

После реаллокации **все** итераторы, указатели и ссылки на элементы старого
буфера недействительны. Аналогично `insert`/`erase` инвалидируют итераторы в
точке операции и после неё.

Правила:

* не хранить итераторы/указатели через вставки;
* после вставки брать новые `begin()`/`data()`;
* если размер известен — `reserve(n)`, тогда реаллокаций при заполнении не будет;
* `shrink_to_fit()` — просьба уменьшить `capacity` до `size` (не гарантирована).

### 4.4. `push_back` vs `emplace_back`

```cpp
struct Point { int x, y; };

std::vector<Point> pts;
pts.push_back(Point{1, 2});   // временный объект + перемещение
pts.emplace_back(3, 4);       // объект строится сразу в буфере
```

`emplace_back(args...)` передаёт аргументы конструктору `T` и конструирует
элемент на месте; `push_back(x)` принимает уже готовый объект.

### 4.5. Вставка и удаление в середине

`insert`/`erase` в середину — O(n): нужно сдвинуть хвост. Если такие операции
часты, `vector` может быть плохим выбором — но не всегда: на практике обход
непрерывного буфера настолько быстрее, что `vector` часто выигрывает даже при
вставках (см. раздел 5.6).

### 4.6. Сложность

| Операция | Сложность |
|----------|-----------|
| `operator[]`, `at`, `front`, `back` | O(1) |
| `push_back`/`emplace_back` | O(1) амортизированно |
| `insert`/`erase` в середину | O(n) |
| `size`, `capacity`, `data` | O(1) |
| поиск по значению (`std::find`) | O(n) |

### 4.7. Плохо → Хорошо

**Плохо:** хранить итератор через `push_back`; расти без `reserve`.

**Хорошо:** `reserve`, новые итераторы после вставок, `emplace_back` вместо
временного объекта.

## 5. `std::list` — блочная структура в куче
> **Пример:** [05_list](05_list)

### 5.1. Устройство

`std::list<T>` — двусвязный список. Каждый элемент — отдельный узел в куче:
значение + указатель на предыдущий + указатель на следующий. В объекте списка
лежат служебные указатели (и, в типичной реализации, узел-страж).

```cpp
std::list<int> l{1, 2, 3};
// адреса &*it для соседних элементов не идут подряд
```

Следствия:

* нет `operator[]` и произвольного доступа: N-й элемент — `std::advance` за O(n);
* каждый `push_back`/`push_front` — отдельная аллокация;
* узел для `int` занимает ~24 байта (значение + два указателя), то есть в 6 раз
  больше самого `int`;
* обход прыгает по памяти и промахивается мимо кэша.

### 5.2. Стабильные указатели

Главное свойство `list`: **вставка и удаление соседей не инвалидируют указатели
и ссылки на остальные элементы**.

```cpp
std::list<int> l{1, 2, 3};
int* p = &l.back();   // указывает на 3

l.push_front(0);      // новый узел
l.push_back(4);       // новый узел
std::cout << *p;      // 3 — указатель валиден
```

`erase` инвалидирует **только** итератор/указатель на удалённый элемент.
`std::list::sort` переставляет узлы и **не** инвалидирует итераторы.

### 5.3. `splice`: перенос узлов за O(1)

```cpp
std::list<int> a{1, 2, 3};
std::list<int> b{10, 20};

auto pos = a.begin();
std::advance(pos, 2);   // перед 3
a.splice(pos, b);       // узлы 10, 20 переехали в a
```

Узлы не копируются: меняются указатели. Указатели на 10 и 20 остаются валидными.
Это операция, которой у `vector` нет вовсе.

### 5.4. Member-функции вместо алгоритмов

`std::sort` требует random access, поэтому для списка используется
`l.sort()` — она переставляет узлы, а не значения:

```cpp
l.sort();                                   // по возрастанию
l.sort([](int x, int y) { return x > y; }); // свой порядок

l.remove_if([](int x) { return x % 2 == 0; });  // удалить чётные
l.unique();                                     // убрать подряд идущие дубликаты
```

`remove_if` — member-функция, потому что ей нужен доступ к `erase`: алгоритм
`std::remove_if` лишь сдвигает значения, а список так работать не может.

### 5.5. Сложность

| Операция | Сложность |
|----------|-----------|
| доступ к N-му элементу | O(n) |
| `push_front`/`push_back`/`insert`/`erase` по итератору | O(1) |
| `splice` | O(1) |
| поиск (`std::find`) | O(n) |
| `sort` | O(n log n) |

### 5.6. Когда `list` не нужен

Распространённое заблуждение: «вставки в середину O(1), значит `list` быстрее».
На практике:

* чтобы вставить в середину, нужно **сначала найти** место — это O(n);
* обход `list` медленнее из-за промахов кэша и отсутствия предвыборки;
* узел на `int` занимает ~24 байта вместо 4.

Замеры (Bjarne Stroustrup, «Are lists evil?») показывают, что `vector` часто
быстрее даже при вставках в середину для реалистичных размеров. `list` выбирают,
когда действительно нужны **стабильные адреса** и **O(1)-перенос узлов**
(`splice`), а не «на всякий случай».

### 5.7. Плохо → Хорошо

**Плохо:** `list` как замена массиву — `l[3]` и `std::sort` не компилируются,
обход медленный.

**Хорошо:** `list` для стабильных ссылок, `splice` и частых вставок по уже
найденному итератору; во всех остальных случаях — `vector`.

## 6. Лямбда-выражения: захват и замыкание
> **Пример:** [06_lambdas](06_lambdas)

### 6.1. Синтаксис

```cpp
// [захват](параметры) -> возвращаемый_тип { тело }
auto is_even = [](int x) { return x % 2 == 0; };
```

Три части:

1. **`[]` — список захвата**: какие внешние переменные доступны внутри;
2. **`(параметры)`** — как у обычной функции;
3. **`{ тело }`** — что лямбда делает.

Тип возвращаемого значения обычно выводится; `-> T` нужен редко.

### 6.2. Список захвата

| Захват | Смысл |
|--------|-------|
| `[]` | ничего не захватывать |
| `[x]` | `x` по значению (копия в замыкании) |
| `[&x]` | `x` по ссылке |
| `[=]` | все используемые переменные по значению |
| `[&]` | все используемые переменные по ссылке |
| `[=, &x]` | всё по значению, `x` — по ссылке |
| `[&, x]` | всё по ссылке, `x` — по значению |
| `[x = выражение]` | инициализация поля замыкания (init-capture, C++14) |
| `[this]`, `[*this]` | захват `this` / копии объекта (C++17) |

```cpp
int threshold = 5;

auto by_value = [threshold](int x) { return x > threshold; };
threshold = 100;
by_value(6);      // true: внутри копия 5

int calls = 0;
auto by_ref = [&calls](int x) { ++calls; return x * 2; };
```

### 6.3. Внутреннее устройство

Лямбда — это **замыкание**: компилятор создаёт безымянный класс с полями-захватами
и `operator()`. Упрощённо:

```cpp
int threshold = 5;
auto above = [threshold](int x) { return x > threshold; };

// эквивалент:
struct Above {
    int threshold;                                  // поле-захват
    bool operator()(int x) const {                  // const по умолчанию
        return x > threshold;
    }
};
```

Следствия:

* **`sizeof` лямбды** равен размеру захваченных полей: 1 байт без захвата,
  `sizeof(int)` с одним `int`;
* **`operator()` по умолчанию `const`**; `mutable` снимает `const` и разрешает
  менять поля;
* **копирование лямбды** копирует и состояние (поля);
* **порядок и имена полей** стандартом не фиксированы — это деталь реализации;
* лямбда без захвата **конвертируется в указатель на функцию**.

```cpp
auto counter = [n = 0]() mutable { return ++n; };
counter();   // 1
counter();   // 2

auto copy = counter;   // копия состояния n == 2
copy();                // 3
```

`mutable` нужен потому, что `operator()` по умолчанию `const`: без него
`++n` не скомпилируется.

### 6.4. Лямбда и функтор

Лямбда — синтаксический сахар над функтором. Для алгоритма они неразличимы:
`std::count_if` — шаблон, он принимает любой callable.

```cpp
struct IsEven {
    bool operator()(int x) const { return x % 2 == 0; }
};

std::count_if(v.begin(), v.end(), IsEven{});   // функтор
std::count_if(v.begin(), v.end(), [](int x) { return x % 2 == 0; });  // лямбда
```

Плюс лямбды — определение в месте использования и захват контекста. Плюс
функтора — возможность дать имя типу и переиспользовать его.

### 6.5. Время жизни захвата

```cpp
auto make_bad() {
    int local = 42;
    return [&local] { return local; };   // висячая ссылка!
}

auto make_good() {
    int local = 42;
    return [local] { return local; };    // копия — безопасно
}
```

Захват по ссылке хранит ссылку, а не значение. Если лямбда переживёт переменную,
поведение не определено. Для возврата из функции безопаснее захват по значению
или init-capture `[x = local]`.

### 6.6. Плохо → Хорошо

**Плохо:** состояние предиката в глобальной переменной.

**Хорошо:** лямбда с захватом — функция и её состояние создаются в одной точке.

## 7. Шаблонные лямбды и функции высшего порядка
> **Пример:** [07_generic_lambdas](07_generic_lambdas)

### 7.1. Generic-лямбда

Параметр `auto` превращает `operator()` в шаблон:

```cpp
auto twice = [](auto x) { return x + x; };

twice(21);                 // operator()<int>
twice(1.5);                // operator()<double>
twice(std::string("ab"));  // operator()<std::string>
```

Упрощённо:

```cpp
struct Twice {
    template <class T>
    T operator()(T x) const { return x + x; }
};
```

C++20 позволяет указать параметры шаблона явно:

```cpp
auto same = []<class T>(const T& a, const T& b) { return a == b; };
```

### 7.2. Функции, принимающие лямбду

Алгоритмы STL — шаблонные функции; лямбда подставляется в них как тип-параметр:

```cpp
template <class F>
auto apply_twice(F f, int x) {
    return f(f(x));
}

apply_twice([](int x) { return x + 10; }, 1);   // 21
```

Компилятор инлайнит вызов: накладных расходов на «функцию в переменной» нет.
Именно поэтому `std::sort(v.begin(), v.end(), [](auto a, auto b) { ... })`
работает так же быстро, как сортировка с обычным компаратором.

### 7.3. `std::function` и стирание типа

`std::function<R(Args...)>` — обёртка, которая хранит **любой** callable с нужной
сигнатурой: лямбду с захватом, функтор, указатель на функцию.

```cpp
std::vector<std::function<int(int)>> pipeline;
pipeline.push_back([](int x) { return x + 1; });
pipeline.push_back([](int x) { return x * 2; });
```

Цена: стирание типа, возможная динамическая аллокация, вызов через виртуальный
механизм. `sizeof(std::function<int(int)>)` — 32–64 байта против 1 байта у
лямбды без захвата.

Правило: **шаблон/`auto`** — когда callable известен на этапе компиляции;
**`std::function`** — когда его нужно хранить в контейнере или передавать через
границу API.

### 7.4. Плохо → Хорошо

**Плохо:** дублировать лямбду под каждый тип.

**Хорошо:** `[](auto x)` — один `operator()<T>` на все типы, ошибки типов
ловятся при инстанцировании.

## 8. Стандартные алгоритмы с лямбдами
> **Пример:** [08_algorithms](08_algorithms)

### 8.1. Общий паттерн

Алгоритм принимает пару итераторов `[first, last)` и (часто) callable. Он ничего
не знает о контейнере — только о категории итератора.

```cpp
std::count_if(v.begin(), v.end(), [](int x) { return x % 2 == 0; });
```

### 8.2. Немодифицирующие

| Алгоритм | Что делает |
|----------|-----------|
| `find`, `find_if` | первый элемент (по условию) |
| `count`, `count_if` | сколько элементов (по условию) |
| `any_of`, `all_of`, `none_of` | проверка предиката на диапазоне |
| `min_element`, `max_element`, `minmax_element` | минимум/максимум |
| `for_each` | действие над каждым элементом |

### 8.3. Модифицирующие

| Алгоритм | Что делает |
|----------|-----------|
| `transform` | применить функцию к каждому элементу |
| `copy`, `copy_if` | копировать диапазон / по условию |
| `remove_if` | сдвинуть «ненужные» в конец, вернуть новый конец |
| `replace_if` | заменить по условию |
| `fill`, `generate`, `iota` | заполнить значениями/генератором/последовательностью |
| `partition` | разделить по предикату |

### 8.4. Идиома erase-remove

`std::remove_if` **не удаляет** элементы и не меняет размер: он сдвигает
оставшиеся в начало и возвращает итератор на новый логический конец. Удалить
хвост нужно контейнеру:

```cpp
auto new_end = std::remove_if(v.begin(), v.end(),
                              [](int x) { return x % 2 != 0; });
v.erase(new_end, v.end());
```

Это разделение не случайно: алгоритм работает с итераторами и не знает, как
контейнер управляет памятью. `erase` — операция контейнера.

### 8.5. Сортировки

```cpp
std::sort(v.begin(), v.end());                       // по возрастанию
std::sort(v.begin(), v.end(), [](int a, int b) {     // свой порядок
    return a > b;
});

std::stable_sort(...);    // сохраняет порядок равных
std::partial_sort(...);   // только первые N мест
```

Компаратор должен задавать **строгий слабый порядок**: `comp(a, a) == false`,
транзитивность. Типичная ошибка — `<=` вместо `<`: `std::sort` может выйти за
границы массива.

### 8.6. Свёртка

```cpp
int sum = std::accumulate(v.begin(), v.end(), 0);
int product = std::accumulate(v.begin(), v.end(), 1,
                              [](int acc, int x) { return acc * x; });

double avg = std::accumulate(students.begin(), students.end(), 0.0,
                             [](double acc, const Student& s) {
                                 return acc + s.score;
                             }) / students.size();
```

`accumulate` — из `<numeric>`; начальное значение задаёт тип аккумулятора
(`0` — `int`, `0.0` — `double`).

### 8.7. Прикладная задача

Данные: список студентов с баллами. Нужно: средний балл, число набравших ≥ 90,
гистограмма оценок, топ-3.

```cpp
const auto excellent = std::count_if(
    students.begin(), students.end(),
    [](const Student& s) { return s.score >= 90; });

std::array<int, 4> histogram{};   // оценки 2, 3, 4, 5
for (int g = 2; g <= 5; ++g)
    histogram[g - 2] = std::count_if(
        students.begin(), students.end(),
        [g](const Student& s) { return grade(s.score) == g; });
```

Ни одного ручного цикла по данным: `count_if` с лямбдой, `accumulate`,
`partial_sort`.

### 8.8. Плохо → Хорошо

**Плохо:** пять строк ручного цикла на «посчитать чётные».

**Хорошо:** `count_if` + лямбда — одна строка, намерение в имени алгоритма,
ошибок индексации нет.

## 9. `std::map` и `std::set`
> **Пример:** [09_map](09_map)

### 9.1. Устройство

`std::map<Key, Value>` — упорядоченный ассоциативный контейнер: пары «ключ →
значение» в сбалансированном (красно-чёрном) дереве. Как и `list`, состоит из
отдельных узлов в куче; порядок по ключу поддерживается автоматически.

* поиск, вставка, удаление — O(log n);
* обход — в порядке возрастания ключей;
* ключ уникален (для повторов есть `multimap`);
* `std::set<Key>` — то же дерево без значений.

```cpp
std::map<std::string, int> ages;
ages["Аня"] = 20;
ages.insert({"Борис", 21});   // не перезаписывает существующий ключ
```

### 9.2. Ловушка `operator[]`

```cpp
std::map<std::string, int> m;
std::size_t before = m.size();
int x = m["нет_такого"];   // ключ ВСТАВЛЕН со значением 0
// before == 0, m.size() == 1
```

`operator[]` — операция записи: при отсутствии ключа создаёт элемент со значением
по умолчанию. Для проверки наличия используйте `find`/`count`, для чтения с
исключением — `at`.

```cpp
auto it = m.find("Аня");
if (it != m.end())
    std::cout << it->first << " = " << it->second << '\n';

if (m.count("Борис")) { /* ключ есть */ }

try {
    std::cout << m.at("Петя");
} catch (const std::out_of_range&) { /* ключа нет */ }
```

`operator[]` уместен там, где вставка с умолчанием — часть алгоритма: например,
`++freq[word]` при подсчёте частот.

### 9.3. Обход

Итератор `map` указывает на `std::pair<const Key, Value>`:

```cpp
for (const auto& [key, value] : m)
    std::cout << key << " -> " << value << '\n';
```

Порядок — по возрастанию ключей, а не по порядку вставки. Если нужен порядок
вставки — храните `vector` пар; `std::unordered_map` (семестр 2) даёт O(1) в
среднем, но порядок вставки не сохраняет.

### 9.4. Сложность и выбор

| Операция | `vector` | `map`/`set` |
|----------|----------|-------------|
| доступ по индексу | O(1) | нет индекса |
| поиск по ключу/значению | O(n) | O(log n) |
| вставка в конец | O(1) амортизированно | — |
| вставка по ключу | O(n) (поиск + сдвиг) | O(log n) |
| обход | быстрый, подряд | медленнее, по узлам |

Правило: нужен **порядок и доступ по индексу** — `vector`; нужен **быстрый поиск
по ключу и уникальность** — `map`/`set`.

## 10. Прикладной пример: частотный анализ слов
> **Пример:** [10_word_frequency](10_word_frequency)

Задача: по тексту построить таблицу «слово → частота» и вывести топ-N.

```cpp
std::istringstream input("apple banana apple cherry banana apple");
std::vector<std::string> words{
    std::istream_iterator<std::string>{input},
    std::istream_iterator<std::string>{}};

std::map<std::string, int> freq;
for (const auto& word : words)
    ++freq[word];                       // O(log n) на слово

std::vector<std::pair<std::string, int>> items(freq.begin(), freq.end());

std::sort(items.begin(), items.end(),
          [](const auto& a, const auto& b) {
              if (a.second != b.second) return a.second > b.second;
              return a.first < b.first;
          });
```

Разбор:

1. **Слова** — `istream_iterator` читает токены; тот же приём работает с файлом.
2. **Частоты** — `map` обеспечивает уникальность ключей и поиск O(log n);
   `++freq[word]` — уместный `operator[]`.
3. **Порядок по частоте** — `map` отсортирован по ключу, поэтому пары переносятся
   в `vector` (конструктор из пары итераторов).
4. **Сортировка** — `std::sort` с лямбда-компаратором; при равной частоте —
   по слову, чтобы порядок был детерминированным.
5. **Топ-N** — вывод первых N элементов.

Сложность: O(n log m), где `n` — число слов, `m` — число уникальных.

Плохо: линейный поиск каждого слова в накопленном списке — O(n²). Хорошо: `map`
берёт поиск и уникальность на себя.

## 11. Выбор контейнера

| Критерий | `array` | `vector` | `list` | `map`/`set` |
|----------|---------|----------|--------|-------------|
| Размер | известен в compile-time | динамический | динамический | динамический |
| Где данные | в объекте (стек) | непрерывный буфер в куче | узлы в куче | узлы в куче |
| Доступ по индексу | O(1) | O(1) | нет | нет |
| Поиск по значению | O(n) | O(n) | O(n) | O(log n) по ключу |
| Вставка в конец | — | O(1) амортиз. | O(1) | — |
| Вставка в середину | — | O(n) | O(1) по итератору | O(log n) по ключу |
| Стабильные адреса | да | нет (реаллокация) | да | да |
| Инвалидация | нет | при росте и вставках | только удалённый | только удалённый |
| Когда выбирать | фиксированный размер | по умолчанию | стабильные ссылки, `splice` | поиск по ключу, порядок |

Практическое правило: **`vector` по умолчанию**; `array` — когда размер
фиксирован и известен; `list` — когда нужны стабильные адреса и перенос узлов;
`map`/`set` — когда нужен поиск по ключу и порядок.

## 12. Типичные ошибки

1. **Хранить итератор `vector` через `push_back`/`insert`** — после реаллокации
   он висячий. Берите новый после вставки.
2. **Путать `size()` и `capacity()`** — `size` — сколько элементов, `capacity` —
   сколько помещается. `reserve` меняет только `capacity`.
3. **`map::operator[]` для проверки наличия ключа** — молча вставляет элемент.
   Для проверки — `find`/`count`, для чтения — `at`.
4. **`std::sort` для `list`** — не компилируется; используйте `l.sort()`.
5. **`remove_if` без `erase`** — размер не меняется; нужна идиома erase-remove.
6. **Компаратор с `<=`** — нарушает строгий слабый порядок, `std::sort` может
   выйти за границы.
7. **Захват по ссылке в лямбде, которая переживёт переменную** — висячая ссылка.
8. **`for (auto x : v)` для больших объектов** — копирует каждый элемент;
   используйте `const auto&`.
9. **`std::array` большого размера на стеке** — риск переполнения стека.
10. **Свой аллокатор без `operator==`/перевоплощения** — контейнер не соберётся
    или будет вести себя непредсказуемо при копировании.

## 14. Практическое задание

**Анализ результатов тестирования.**

```cpp
const std::vector<int> scores = {78, 91, 55, 88, 91, 45, 66, 91, 78, 88};
```

1. Средний балл — `std::accumulate` (аккумулятор `double`).
2. Сколько набрали ≥ 90 и сколько < 60 — два `count_if` с лямбдами.
3. Функция `grade(score)` (≥ 90 → 5, 75–89 → 4, 60–74 → 3, иначе 2);
   гистограмма оценок — `std::array<int, 4>` и `count_if` по каждой оценке.
4. Топ-3 балла — `std::partial_sort` с компаратором.
5. Дополнительно: `std::map<std::string, int>` для подсчёта оценок по студентам
   (имя → балл), `find`/`count` без `operator[]`, вывод в порядке ключей.
6. Дополнительно: `std::list` из оценок; удалить нечётные через member
   `remove_if`; объяснить, почему `std::sort` к списку не применим.

Условие: ни один результат не считается ручным циклом по данным — только
алгоритмы STL и лямбды.
