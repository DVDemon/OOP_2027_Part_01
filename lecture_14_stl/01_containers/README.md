# 01. Контейнер — владелец памяти

**Блок плана:** 1 — общий принцип контейнеров: управление памятью, аллокаторы,
итераторы.

## Что показывает пример

* **RAII-владение.** `vector` выделяет буфер при вставке и освобождает его в
  деструкторе: к концу блока `allocate` и `deallocate` совпадают.
* **Метаданные и данные разделены.** Объект `vector` (обычно три указателя,
  24 байта) лежит на стеке, а буфер — в куче. У `std::array` элементы лежат прямо
  в объекте, в кадре стека.
* **Аллокатор — сменная политика.** `CountingAllocator<T>` логирует запросы.
  `vector` из 100 `push_back` делает 8 запросов, `list` — 100 (по одному на узел).
* **Глубокая копия и перемещение.** Копия выделяет новый буфер, `std::move`
  передаёт указатель без выделения памяти.
* **Единый интерфейс.** Один шаблон `dump()` обходит `vector`, `list` и `array`.

## Плохо → Хорошо

**Плохо** — сырой массив с ручными `size`/`capacity`:

```cpp
int* data = new int[3];
std::size_t size = 0, capacity = 3;
// ... ручной push_back с проверкой capacity и перевыделением ...
delete[] data;   // забудут, выйдут по исключению — утечка
```

**Почему плохо:** владение, размер и вместимость — три отдельные сущности,
которые легко рассогласовать. Копирование по умолчанию копирует указатель, а не
данные; деструктор нужно не забыть вызвать на всех путях.

**Хорошо** — контейнер владеет буфером сам, а политику выделения задаёт аллокатор:

```cpp
std::vector<int, CountingAllocator<int>> v{1, 2, 3};
v.push_back(4);   // контейнер сам решил, когда перевыделить буфер
```

**Почему хорошо:** деструктор освобождает память, копия — глубокая, перемещение
крадёт буфер. Аллокатор можно заменить, не меняя код работы с контейнером.

## Фрагмент вывода

```
=== 1. RAII: контейнер сам освобождает память ===
vector [4]: 1 2 3 4 
внутри блока: allocate=2, deallocate=1, bytes=36
после выхода из блока: allocate=2, deallocate=2, bytes=36

=== 2. Метаданные — на стеке, данные — в куче ===
sizeof(vector) = 24 (обычно три указателя: begin, end, capacity)
адрес объекта v        (стек): 0x16b549ed8
адрес буфера v.data()  (куча): 0x11e605e30
sizeof(array<int,3>) = 12, адрес его элементов (стек): 0x16b549eb8

=== 3. Аллокатор: сколько запросов делает контейнер ===
vector: 100 push_back: allocate=8, deallocate=7, bytes=1020
list:   100 push_back: allocate=100, deallocate=0, bytes=2400
```

Конкретные адреса, `capacity` и размеры узлов зависят от стандартной библиотеки
и платформы — важны соотношения, а не точные числа.
