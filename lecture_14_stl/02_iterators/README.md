# 02. Итераторы: единый интерфейс доступа

**Блок плана:** 2 — итераторы как часть общего принципа контейнеров.

## Что показывает пример

* **`begin()`/`end()` и полуоткрытый интервал** `[begin, end)`: `end()` указывает
  «за последним», поэтому пустой контейнер — это `begin == end`.
* **range-for** — синтаксический сахар над итераторным циклом.
* **Категории итераторов:** `vector`/`array` — random access, `list` —
  bidirectional. Категория печатается через `if constexpr` по
  `iterator_traits::iterator_category`.
* **Цена категории:** `std::distance` для `vector` — O(1), для `list` — O(n);
  `std::advance` — один шаг или несколько.
* **Ограничения алгоритмов:** `std::sort` требует random access, поэтому для
  `list` вызывается member-функция `sort()`.
* **Инвалидация:** `array` — ничего, `vector` — реаллокация и `insert`/`erase`,
  `list` — только удалённый элемент.

## Плохо → Хорошо

**Плохо** — обход по индексу, привязанный к устройству контейнера:

```cpp
for (std::size_t i = 0; i < v.size(); ++i)
    use(v[i]);            // только vector/array, для list не скомпилируется
```

**Почему плохо:** код знает, что у контейнера есть `operator[]` и `size`. Для
`list` нужен другой цикл, для `map` — третий. Границы легко перепутать.

**Хорошо** — один и тот же цикл по паре итераторов:

```cpp
for (auto it = c.begin(); it != c.end(); ++it)
    use(*it);
```

**Почему хорошо:** итератор скрывает устройство контейнера, а `[begin, end)`
делает цикл безопасным для пустого диапазона. Алгоритмы STL принимают ровно эту
пару — поэтому `find`, `count_if`, `for_each` работают с любым контейнером.
