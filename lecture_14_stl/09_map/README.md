# 09. `std::map` и `std::set`

**Блок плана:** 9 — ассоциативные контейнеры на дереве.

## Что показывает пример

* **`std::map<Key, Value>`** — пары «ключ → значение» в красно-чёрном дереве;
  порядок по ключу поддерживается автоматически, поиск/вставка/удаление — O(log n).
* **`operator[]` вставляет** отсутствующий ключ со значением по умолчанию —
  главная ловушка при «чтении».
* **`find`/`count`/`at`** не меняют контейнер: `find` возвращает итератор или
  `end()`, `count` — 0/1, `at` бросает `std::out_of_range`.
* **Обход** идёт в порядке возрастания ключей; structured binding
  `for (const auto& [key, value] : m)`.
* **`std::set`** — то же дерево без значений: уникальность, сортировка,
  проверка принадлежности.
* **Сравнение с `vector`:** поиск по значению O(n) против O(log n), зато у `vector`
  есть доступ по индексу O(1).

## Плохо → Хорошо

**Плохо** — проверять наличие ключа через `operator[]`:

```cpp
std::map<std::string, int> scores;
if (scores["Петя"] >= 60)   // если ключа не было — он ВСТАВЛЕН со значением 0
    std::cout << "сдал\n";
```

**Почему плохо:** `operator[]` — операция записи: при отсутствии ключа она
создаёт элемент со значением по умолчанию. Контейнер меняется от «чтения», размер
растёт, а последующая логика работает с несуществующей записью.

**Хорошо** — `find` или `count` для проверки, `at` для чтения с исключением:

```cpp
auto it = scores.find("Петя");
if (it != scores.end() && it->second >= 60)
    std::cout << "сдал\n";
```

**Почему хорошо:** `find` ничего не модифицирует и возвращает итератор на пару;
`at` даёт значение или бросает исключение. `operator[]` остаётся для случаев, где
вставка по умолчанию действительно нужна — например, `++freq[word]`.
