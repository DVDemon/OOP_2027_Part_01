# 04. `std::vector` — динамический массив в куче

**Блок плана:** 4 — `std::vector`: рост, реаллокация, инвалидация итераторов.

## Что показывает пример

* **Объект на стеке, буфер в куче:** адрес `v` рядом с локальной переменной,
  `v.data()` — в куче.
* **Рост `capacity`:** при заполнении буфер увеличивается кратно (обычно ×1.5–×2),
  поэтому `push_back` амортизированно O(1).
* **Реаллокация перемещает элементы:** счётчики `Tracked` показывают `moves=7,
  copies=0` после пяти `emplace_back` — move-конструктор `noexcept` позволяет
  переносить, а не копировать.
* **Инвалидация:** адрес буфера до и после `push_back` сравнивается как
  `std::uintptr_t`; после реаллокации он новый, старые итераторы и указатели
  недействительны.
* **`reserve`** убирает перераспределения, **`emplace_back`** строит объект сразу
  в буфере, **`insert`/`erase`** в середине — O(n), **`at`** проверяет границы,
  **`shrink_to_fit`** просит вернуть лишнюю память.

## Плохо → Хорошо

**Плохо** — хранить итератор через вставку:

```cpp
auto it = v.begin();
v.push_back(42);          // capacity могла закончиться — буфер переехал
std::cout << *it;         // неопределённое поведение
```

**Почему плохо:** `vector` хранит элементы одним непрерывным блоком. Когда места
не хватает, он выделяет новый блок, переносит туда элементы и освобождает старый.
Все итераторы, указатели и ссылки на старый буфер становятся висячими.

**Хорошо** — не хранить итераторы через вставки; брать новые после роста:

```cpp
v.push_back(42);
auto it = v.begin();      // итератор, полученный ПОСЛЕ вставки
```

**Почему хорошо:** итератор снова указывает в актуальный буфер. Если размер
известен заранее, `reserve(n)` вообще исключает перераспределения — и проблема
инвалидации при заполнении не возникает.

## Фрагмент вывода

```
=== 2. Рост: size и capacity ===
size=1 capacity=1  <- буфер заполнен
size=2 capacity=2  <- буфер заполнен
size=3 capacity=4
...
size=9 capacity=16

=== 3. Реаллокация перемещает элементы ===
после 5 emplace_back: copies=0, moves=7 (элементы перенесены, не скопированы)

=== 4. Инвалидация: адрес буфера до и после ===
capacity: 3 -> 6
буфер: НОВЫЙ — старые итераторы и указатели инвалидированы

=== 6. push_back vs emplace_back ===
push_back(Tracked{1}): copies=0, moves=1
emplace_back(1):       copies=0, moves=0
```

Точные значения `capacity` зависят от реализации стандартной библиотеки; важен
сам факт кратного роста и смены адреса буфера.
