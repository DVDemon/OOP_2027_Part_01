# Лекция 7. Copy/Move семантика. Правило пяти

Примеры к лекции. Покрывают все пункты плана: проблему поверхностного
копирования, копирующие и перемещающие операции, правила трёх/пяти/нуля,
идиому copy-and-swap, категории значений, `std::move`/`std::exchange`,
`noexcept` для move-операций и полную реализацию учебного класса `String`.

## Ключевые идеи лекции

1. **Shallow copy опасен.** Сгенерированный компилятором копирующий
   конструктор копирует значение указателя, а не данные — два объекта владеют
   одним буфером, при разрушении возникает double free.
2. **Deep copy** — выделение новой памяти и копирование содержимого; основа
   корректного владения ресурсом.
3. **Правило трёх:** если нужен один из {деструктор, копирующий конструктор,
   копирующее присваивание}, скорее всего нужны все три.
4. **Copy-and-swap** даёт строгую гарантию исключений и автоматически решает
   проблему самоприсваивания, передавая аргумент по значению.
5. **Категории значений:** lvalue имеет имя и адрес, prvalue — временный
   объект, xvalue — «истекающее» значение (`std::move`). rvalue-ссылка `T&&`
   позволяет «красть» ресурсы вместо копирования.
6. **Move-операции** переносят владение и обнуляют источник, оставляя его в
   валидном, но неопределённом состоянии.
7. **`std::move`** — это `static_cast<T&&>`: он не перемещает, а лишь
   разрешает перемещение. **`std::exchange`** удобен для обнуления источника.
8. **Правило пяти** дополняет правило трёх move-операциями; **Правило нуля** —
   делегируйте владение RAII-членам и не пишите ни одного спецметода.
9. **`noexcept` на move** критичен: без него `std::vector` при реаллокации
   копирует элементы вместо перемещения.
10. **`String`** — учебный пример, объединяющий все идеи лекции.
