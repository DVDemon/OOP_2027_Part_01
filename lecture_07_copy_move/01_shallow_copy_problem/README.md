# 01. Проблема поверхностного копирования (shallow copy)

**Пункт плана:** 1 — проблема поверхностного копирования.

## Что показывает пример

* Класс `NaiveString` владеет буфером через `char*`.
* Сгенерированный компилятором копирующий конструктор копирует значение
  указателя — два объекта владеют одним буфером.
* Печать адресов доказывает, что `a` и `b` указывают на одну и ту же память.
* Проблема показана БЕЗОПАСНО: деструктор не вызывает `delete[]`, освобождение
  выполняется вручную ровно один раз.

## Запуск

```bash
./build/01_shallow_copy_problem
```

## Плохо → Хорошо

**Плохо** — полагаться на сгенерированный копирующий конструктор для класса
с указателем-владельцем:

```cpp
class NaiveString {
    char* data_;
public:
    NaiveString(const char* s) : data_(new char[std::strlen(s) + 1]) { /* ... */ }
    ~NaiveString() { delete[] data_; }     // в реальном классе
    // копирующий конструктор НЕ определён -> компилятор сделает shallow copy
};

NaiveString a("Hello");
NaiveString b = a;   // b.data_ == a.data_  (один буфер на двоих)
// при выходе из области видимости: delete[] вызовется ДВАЖДЫ -> double free (UB)
```

**Почему плохо:** копируется только адрес. Оба деструктора освобождают один
и тот же блок памяти — это неопределённое поведение (double free), часто
крах или повреждение кучи.

**Хорошо** — глубокое копирование: выделить новый буфер и скопировать данные
(см. пример 02). Тогда у каждого объекта свой буфер, и каждый деструктор
освобождает свою память ровно один раз.
