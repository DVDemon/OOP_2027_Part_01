# 05. rvalue-ссылки и категории значений

**Пункт плана:** 5 — rvalue-ссылки (`T&&`) и категории значений
(lvalue, prvalue, xvalue).

## Что показывает пример

* Перегрузка функции по категории аргумента: `const T&` для lvalue,
  `T&&` для rvalue.
* lvalue (именованный объект), prvalue (литерал, временный), xvalue
  (`std::move`).
* Адрес можно взять только у lvalue.
* rvalue-ссылка с именем (`int&& r`) сама является lvalue.

## Запуск

```bash
./build/05_value_categories
```

## Категории значений

```
            expression
            /        \
       glvalue       rvalue
       /     \       /     \
   lvalue   xvalue        prvalue
```

| Категория | Что это | Примеры |
|-----------|---------|---------|
| lvalue  | имеет имя, можно взять адрес | `int x;`, `std::string s;`, `s[0]` |
| prvalue | чистое временное значение | `42`, `s1 + s2`, `Foo()` |
| xvalue  | «истекающее» значение | `std::move(x)`, возврат `T&&` |

## Плохо → Хорошо

**Плохо** — одна перегрузка `const T&` всегда копирует, даже для временных:

```cpp
void store(const std::string& s) { data_ = s; }  // всегда КОПИЯ

store(make_string());   // временный объект всё равно копируется
```

**Почему плохо:** временный объект `make_string()` всё равно будет
скопирован, хотя его ресурсы можно было бы «украсть» — он сразу же исчезнет.

**Хорошо** — добавить перегрузку `T&&` для временных объектов:

```cpp
void store(const std::string& s) { data_ = s; }              // lvalue: копия
void store(std::string&& s)      { data_ = std::move(s); }   // rvalue: move

store(named);             // -> копия (named ещё нужен)
store(make_string());     // -> перемещение (временный объект)
```

**Почему хорошо:** для временных объектов вызывается перемещение — ресурс
переносится без выделения новой памяти. Именно на этом основаны
перемещающие конструктор и присваивание (см. пример 06).
