# 07. Приватное наследование vs композиция

**Пункт плана:** 7.

## Что показывает пример

* `StackPrivate : private std::vector<int>` — отношение
  «реализован посредством» (implemented-in-terms-of).
* `StackComposed` — то же самое через поле `std::vector<int>`.
* Что интерфейс `vector` (`push_back`, `operator[]`, `clear`) наружу
  не протекает ни в одном варианте.

## Запуск

```bash
./build/07_private_vs_composition
```

## Плохо → Хорошо

**Плохо** — публично наследоваться от `std::vector`, когда нужен стек:

```cpp
class Stack : public std::vector<int> {};
// у стека внезапно есть insert, erase, operator[] — инвариант не защищён
```

**Хорошо** — композиция:

```cpp
class Stack {
    std::vector<int> data_;
public:
    void push(int v) { data_.push_back(v); }
    // остальной интерфейс vector скрыт
};
```

**Почему:** `Stack` не «является» вектором. Наследование открывает лишние
операции, которые могут нарушить инвариант стека; композиция даёт ровно
нужный интерфейс.

## Когда приватное наследование всё же оправдано

* нужен доступ к `protected`-членам базы;
* нужно переопределить виртуальные функции базы;
* оптимизация пустого базового класса (EBO).

Во всех остальных случаях — композиция.

## Ключевая мысль

Приватное наследование — это деталь реализации, а не отношение типов.
Современный стиль предпочитает композицию: она проще, слабее связывает
классы и не протекает наружу.
