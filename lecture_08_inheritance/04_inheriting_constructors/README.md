# 04. Наследование конструкторов (`using Base::Base`)

**Пункт плана:** 4.

## Что показывает пример

* `using Base::Base` наследует все конструкторы базового класса.
* Унаследованный конструктор **не** инициализирует поля наследника —
  для них работают default member initializers.
* Собственный конструктор наследника можно объявить рядом.
* Копирующий и перемещающий конструкторы через `using` не наследуются.

## Запуск

```bash
./build/04_inheriting_constructors
```

## Плохо → Хорошо

**Плохо** — вручную переписывать каждый конструктор базы:

```cpp
class Derived : public Base {
public:
    Derived(int x) : Base(x) {}
    Derived(int x, double y) : Base(x, y) {}
    // при добавлении нового конструктора в Base — снова править Derived
};
```

**Хорошо** — унаследовать их одной строкой:

```cpp
class Derived : public Base {
    std::string label_{"<нет>"};  // значение по умолчанию
public:
    using Base::Base;
};
```

**Почему:** меньше дублирования и меньше шансов разойтись с базой при её
изменении. Важно помнить про поля наследника: они инициализируются только
своими default-инициализаторами.

## Ключевая мысль

`using Base::Base` — это «возьми конструкторы базы как свои». Всё, что
относится к полям наследника, остаётся на наследнике.
