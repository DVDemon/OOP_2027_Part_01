# 11. Виртуальное наследование

**Пункт плана:** 11.

## Что показывает пример

* `virtual public Device` у `Printer` и `Scanner` — в `Copier` остаётся
  **один** подобъект `Device`.
* Отсутствие неоднозначности: `c.id` и `&c.Printer::id == &c.Scanner::id`.
* Ответственность most-derived класса: конструктор `Device` вызывает
  `Copier`, а вызовы из `Printer`/`Scanner` игнорируются.
* Расположение в памяти: `sizeof` и адреса при обычном и виртуальном
  наследовании; у промежуточных классов появляется `vbptr`.

## Схема

```
        Device  (один экземпляр)
        /    \
    Printer  Scanner   (virtual public Device)
        \    /
        Copier
```

## Запуск

```bash
./build/11_virtual_inheritance
```

Ожидаемый порядок при создании `Copier`:

```
Device(42)
Printer()
Scanner()
Copier()
```

При создании `Printer` напрямую он сам является most-derived, поэтому
работает его собственный вызов `Device(7)`.

## Плохо → Хорошо

**Плохо** — забыть вызвать конструктор виртуальной базы в most-derived
классе:

```cpp
class Copier : public Printer, public Scanner {
public:
    Copier(int id) : Printer(id), Scanner(id) {}  // Device() по умолчанию
};
```

**Хорошо** — вызвать явно:

```cpp
Copier(int id) : Device(id), Printer(id), Scanner(id) {}
```

**Почему:** при виртуальном наследовании инициализацию общей базы выполняет
только наиболее производный класс; вызовы из промежуточных игнорируются.

## Цена

Виртуальное наследование добавляет `vbptr` и косвенный доступ к базе:
объект больше, обращение медленнее. Используйте его только там, где общий
подобъект действительно нужен.

## Ключевая мысль

`virtual` в списке наследования меняет не доступ, а **структуру объекта**:
общая база существует в единственном экземпляре, а за её инициализацию
отвечает самый производный класс.
