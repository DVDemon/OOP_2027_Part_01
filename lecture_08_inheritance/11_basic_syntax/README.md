# 01. Синтаксис множественного наследования

**Пункт плана:** 1 — синтаксис множественного наследования.

## Что показывает пример

* Класс `Copier` наследуется сразу от двух баз: `Printer` и `Scanner`.
* Производный класс получает интерфейсы обоих базовых классов.
* Порядок конструирования определяется **списком наследования** (слева направо),
  а не списком инициализации.

## Запуск

```bash
./build/01_basic_syntax
```

Ожидаемый вывод:

```
Printer()
Scanner()
Copier()
---
[PRINT] Привет
scan(): Отсканированный документ
[PRINT] Отсканированный документ
```

## Плохо → Хорошо

**Плохо** — полагаться, что порядок конструирования задаётся списком
инициализации:

```cpp
class Copier : public Printer, public Scanner {
public:
    // Запишем Scanner первым в списке инициализации —
    Copier() : Scanner(), Printer() {}
    // ...но компилятор всё равно сконструирует Printer ПЕРВЫМ
    // (он первый в списке наследования). GCC/Clang выдадут
    // -Wreorder. Это сбивает с толку и ведёт к ошибкам, если
    // один подобъект зависит от другого.
};
```

**Хорошо** — записывать список инициализации в том же порядке, что и список
наследования; тогда код читается так же, как выполняется:

```cpp
class Copier : public Printer, public Scanner {
public:
    Copier() : Printer(), Scanner() {}  // порядок совпадает с реальным
};
```

**Почему:** реальный порядок конструирования баз фиксирован порядком в списке
наследования. Если список инициализации записан иначе, читатель кода делает
неверные выводы о последовательности побочных эффектов в конструкторах.
