# 10. Проблема ромба (diamond problem)

**Пункт плана:** 10.

## Что показывает пример

* Общий предок `Device` у `Printer` и `Scanner`, которые наследуются
  в `Copier`.
* Без `virtual` в объекте `Copier` оказываются **две** независимые копии
  `Device`.
* Неоднозначность `c.id` и обход через `c.Printer::id` / `c.Scanner::id`.
* Рост размера объекта (`sizeof(Copier)`).

## Схема

```
        Device          Device          <- две копии
          |               |
       Printer          Scanner
          \              /
             Copier
```

## Запуск

```bash
./build/10_diamond_problem
```

## Плохо → Хорошо

**Плохо** — оставить обычное наследование и «чинить» неоднозначность
квалификацией:

```cpp
c.Printer::id = 1;
c.Scanner::id = 101;   // это два разных поля, а не одно
```

**Хорошо** — виртуальное наследование (пример 11):

```cpp
class Printer : virtual public Device { /* ... */ };
class Scanner : virtual public Device { /* ... */ };
```

**Почему:** задача почти всегда в том, чтобы общий предок был **один**;
квалификация лишь маскирует дублирование данных и рассинхронизацию.

## Ключевая мысль

Ромб — это не про имена, а про данные: две копии базы означают два
независимых состояния. Пока это не осознано, любое «исправление» через
квалификацию оставляет баг.
