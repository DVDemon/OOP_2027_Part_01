# 08. Спецификатор `final`

**Пункт плана:** 8.

## Что показывает пример

* `final` у класса запрещает наследование от него.
* `final` у виртуального метода запрещает его переопределение в наследниках.
* Прочие виртуальные методы по-прежнему переопределяются (`handle`).

## Запуск

```bash
./build/08_final_specifier
```

## Плохо → Хорошо

**Плохо** — оставить класс «открытым» для наследования, хотя он для этого не предназначен:

```cpp
class Framework {           // кто-то унаследует и сломает инварианты
    void run();             // невиртуальный — вызов через Framework* пойдёт мимо
};
```

**Хорошо** — явно запретить наследование/переопределение там, где оно недопустимо:

```cpp
class Framework final { ... };          // наследование запрещено

class Base {
    virtual void process() final;       // переопределение запрещено
};
```

**Почему:** `final` фиксирует намерение проектировщика на уровне компилятора:
нарушение приводит к ошибке сборки, а не к скрытому багу. Дополнительно это
позволяет компилятору девиртуализировать вызовы и иногда ускорить код.
