# Лекция 8. Наследование: одиночное, множественное, виртуальное

Двенадцать примеров к лекции. Часть I (1–8) покрывает одиночное наследование:
синтаксис и модификаторы доступа, порядок конструирования/разрушения,
наследование конструкторов, сокрытие имён, срезку объектов, приватное
наследование против композиции, `final` и принцип «предпочитайте композицию».
Часть II (9–12) разбирает множественное и виртуальное наследование: синтаксис
и неоднозначность, проблему ромба, `virtual`-базы, расположение объекта
в памяти, примеси и альтернативы.

Шаблоны в примерах не используются — их разбор в лекции 15.

## Сборка

```bash
cmake -S . -B build
cmake --build build
```

```bash
./build/01_inheritance_basics

./build/12_mixins_and_alternatives
```

## Ключевые идеи лекции

1. **`public`-наследование = отношение is-a.** Только оно сохраняет
   подстановочность наследника вместо базы и обязано проходить тест Лисков.
2. **Модификатор наследования** меняет уровень доступа к членам базы;
   `private`-члены базы существуют, но напрямую недоступны наследнику.
3. **Порядок строго определён:** конструирование сверху вниз (база → члены →
   тело), разрушение — в обратном порядке.
4. **`using Base::Base`** наследует конструкторы базы, но не инициализирует
   поля наследника; копирующий/перемещающий конструкторы так не наследуются.
5. **Name hiding:** перегрузка в наследнике скрывает все одноимённые
   перегрузки базы; возвращает их директива `using Base::foo;`.
6. **Срезка:** копирование наследника в базовый тип отбрасывает производную
   часть — передавайте полиморфные объекты по ссылке/указателю.
7. **Композиция предпочтительнее наследования:** более слабая связь и
   гибкость; приватное наследование — только для `protected`, переопределения
   виртуальных функций или EBO.
8. **`final`** запрещает наследование/переопределение и помогает компилятору
   девиртуализировать вызовы.
9. **Множественное наследование** — класс может иметь несколько прямых баз;
   порядок конструирования задаётся списком наследования (слева направо),
   одноимённые члены требуют квалификации, а указатели на разные базы могут
   иметь разные адреса.
10. **Проблема ромба** — при общем предке без `virtual` в объекте оказываются
    две копии базы: дублирование данных и неоднозначность имён.
11. **Виртуальное наследование** (`virtual public`) гарантирует единственный
    общий подобъект базы; за его конструктор отвечает most-derived класс,
    а промежуточные классы хранят `vbptr`.
12. **Примеси и интерфейсы** — безопасные формы MI: базы без общего состояния
    и без данных; если у баз есть данные, предпочитайте композицию.
