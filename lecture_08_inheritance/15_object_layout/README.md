# 05. Расположение объекта в памяти: с виртуальным наследованием и без

**Пункт плана:** 5 — расположение объекта в памяти.

## Что показывает пример

* `sizeof` объекта при обычном и виртуальном наследовании.
* Без `virtual`: две копии `Device`, разные адреса `id`, больший размер.
* С `virtual`: один общий `Device` + `vbptr` (virtual base pointer) в каждом
  промежуточном классе; оба пути ромба ведут к одному `id`.

Конкретные числа зависят от компилятора и ABI — важна качественная картина.

## Запуск

```bash
./build/05_object_layout
```

## Схема расположения

### Без виртуального наследования

```
Copier (два экземпляра Device):
+-------------------------+
| Device (от Printer)     |  <- Printer::id
+-------------------------+
| Printer members         |
+-------------------------+
| Device (от Scanner)     |  <- Scanner::id
+-------------------------+
| Scanner members         |
+-------------------------+
| Copier members          |
+-------------------------+
```

### С виртуальным наследованием

```
Copier (один экземпляр Device):
+-------------------------+
| Printer subobject       |
|   vbptr -----+          |  <- указатель на виртуальную базу
+-------------------------+
| Scanner subobject       |
|   vbptr -----+          |
+-------------------------+
| Copier members          |
+-------------------------+
| Device (shared)     <---+  <- единственный экземпляр
+-------------------------+
```

## Плохо → Хорошо

**Плохо** — использовать обычное наследование от общего предка с данными:
объект «толстеет» за счёт дублирования базы, а её поля рассинхронизируются.

```cpp
struct Copier : Printer, Scanner {};  // две копии Device внутри
```

**Хорошо** — `virtual` убирает дублирование данных; ценой служат `vbptr` и
косвенный доступ к базе.

```cpp
struct Printer : virtual Device {};
struct Scanner : virtual Device {};
struct Copier  : Printer, Scanner {};  // один общий Device
```

**Почему:** виртуальное наследование экономит память на данных общей базы и
устраняет рассинхронизацию, но добавляет по указателю (`vbptr`) на каждый
виртуальный путь и делает доступ к базе косвенным. Поэтому `virtual`
применяют только когда общий предок действительно должен быть единственным.
