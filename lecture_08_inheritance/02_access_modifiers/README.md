# 02. Модификаторы наследования: public, protected, private

**Пункт плана:** 2.

## Что показывает пример

* Как модификатор наследования меняет уровень доступа к членам базы.
* `private`-члены базы существуют в объекте, но недоступны наследнику напрямую.
* Доступ к `private`-члену только через методы базового класса.

## Запуск

```bash
./build/02_access_modifiers
```

## Таблица доступа

| Член в базе | `public`-наследование | `protected`-наследование | `private`-наследование |
|---|---|---|---|
| `public`    | `public`    | `protected` | `private`  |
| `protected` | `protected` | `protected` | `private`  |
| `private`   | недоступен  | недоступен  | недоступен |

## Плохо → Хорошо

**Плохо** — использовать `private`/`protected`-наследование «по привычке» для is-a:

```cpp
class Dog : private Animal { ... };   // снаружи Dog уже не "является" Animal
```

Полиморфная подстановка `Animal* = &dog;` перестаёт работать.

**Хорошо** — для отношения is-a применять `public`-наследование:

```cpp
class Dog : public Animal { ... };    // интерфейс Animal остаётся публичным
```

**Почему:** только `public`-наследование сохраняет отношение is-a и допускает
подстановку наследника вместо базы. `protected`/`private` — это деталь реализации.
