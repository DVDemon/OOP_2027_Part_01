# 02. Модификаторы наследования и таблица доступа

**Пункт плана:** 2.

## Что показывает пример

* `public`, `protected` и `private`-наследование одного и того же `Base`.
* Как модификатор наследования меняет уровень доступа к членам базы.
* Что `private`-члены базы недоступны наследнику ни при каком модификаторе.
* Что доступ к ним возможен только через методы самого базового класса.

## Таблица доступа

| Член в базе | `public`-наследование | `protected`-наследование | `private`-наследование |
|---|---|---|---|
| `public`    | `public`    | `protected` | `private` |
| `protected` | `protected` | `protected` | `private` |
| `private`   | недоступен  | недоступен  | недоступен |

## Запуск

```bash
./build/02_access_modifiers
```

## Плохо → Хорошо

**Плохо** — считать, что `private`-члены базы «исчезают» в наследнике:

```cpp
class Derived : public Base {
    void f() { priv = 1; }   // ОШИБКА: private-член базы недоступен
};
```

**Хорошо** — обращаться через публичный интерфейс базы:

```cpp
class Base {
    int priv_;
public:
    int priv() const { return priv_; }
};
```

**Почему:** `private`-члены физически есть в объекте наследника, но
компилятор запрещает прямой доступ — это и есть инкапсуляция.

## Ключевая мысль

Модификатор наследования — это модификатор доступа «наследника к наследию».
По умолчанию для `class` он `private`, для `struct` — `public`; для отношения
is-a почти всегда нужен именно `public`.
