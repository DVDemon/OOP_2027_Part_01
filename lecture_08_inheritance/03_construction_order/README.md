# 03. Порядок конструирования и разрушения

**Пункт плана:** 3.

## Что показывает пример

* Конструирование идёт сверху вниз: база → её члены → члены наследника → тело.
* Разрушение идёт строго в обратном порядке.
* Порядок определяется списком баз и объявлением полей, а не порядком
  в списке инициализации.
* Для наглядности каждый шаг печатается в консоль.

## Запуск

```bash
./build/03_construction_order
```

Ожидаемый вывод:

```
Member(Base::m) -> Base() -> Member(Derived::m) -> Derived()
~Derived() -> ~Member(Derived::m) -> ~Base() -> ~Member(Base::m)
```

## Плохо → Хорошо

**Плохо** — рассчитывать, что члены инициализируются в порядке их записи
в списке инициализации:

```cpp
class Point {
    int y_;
    int x_;
public:
    Point(int x, int y) : x_(x), y_(y) {}  // сначала всё равно y_, потом x_
};
```

**Хорошо** — объявлять поля в том же порядке, в котором они инициализируются,
и полагаться на порядок базы → члены → тело:

```cpp
class Point {
    int x_;
    int y_;
public:
    Point(int x, int y) : x_(x), y_(y) {}
};
```

**Почему:** несовпадение порядков — источник трудноуловимых багов, особенно
когда инициализатор одного поля зависит от другого.

## Ключевая мысль

Время жизни части объекта всегда подчинено иерархии: база живёт дольше
наследника. Поэтому в конструкторе наследника база уже готова, а в деструкторе
наследника она ещё жива — обратное неверно.
