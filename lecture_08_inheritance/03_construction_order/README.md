# 03. Порядок конструирования и разрушения объектов

**Пункт плана:** 3.

## Что показывает пример

* Конструирование «сверху вниз»: база → члены наследника → тело конструктора.
* Разрушение «снизу вверх»: тело деструктора наследника → его члены → база.
* Члены печатают своё создание/уничтожение, поэтому порядок виден в выводе.

## Запуск

```bash
./build/03_construction_order
```

Ожидаемый вывод (фрагмент):

```
Member(Base::m)
Base()
Member(Derived::m)
Derived()
...
~Derived()
~Member(Derived::m)
~Base()
~Member(Base::m)
```

## Плохо → Хорошо

**Плохо** — обращаться к ещё не сконструированным членам наследника из конструктора базы
(или полагаться на «удачный» порядок инициализации):

```cpp
Base() { useDerivedData(); }   // данных наследника ещё нет!
```

**Хорошо** — помнить строгий порядок и инициализировать всё в списке инициализации
в порядке объявления полей:

```cpp
Derived() : Base(), member_{} { /* база и члены уже готовы */ }
```

**Почему:** на момент работы конструктора базы производная часть ещё не существует.
Знание порядка конструирования/разрушения предотвращает обращение к «мусору» и утечки.
