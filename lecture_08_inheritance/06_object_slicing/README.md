# 06. Срезка объектов (object slicing)

**Пункт плана:** 6.

## Что показывает пример

* Копирование наследника в переменную базового типа отбрасывает
  производную часть: поля и переопределения теряются.
* Срезку в параметре функции при передаче по значению.
* Срезку в массиве (или контейнере) базового типа.
* Решение: передавать полиморфные объекты по ссылке или указателю.

## Запуск

```bash
./build/06_object_slicing
```

Обратите внимание на `sizeof(Base)` и `sizeof(Derived)`: в переменной
`Base` физически нет места для полей `Derived`.

## Плохо → Хорошо

**Плохо** — передавать полиморфный объект по значению:

```cpp
void render(Base shape) { shape.print(); }  // всегда Base
Base copy = derived;                        // СРЕЗКА
Base arr[] = {derived1, derived2};          // СРЕЗКА
```

**Хорошо** — по ссылке или указателю:

```cpp
void render(const Base& shape) { shape.print(); }
const Base& ref = derived;
Base* ptr = &derived;
```

**Почему:** ссылка и указатель не копируют объект, поэтому сохраняется
динамический тип и полиморфный вызов.

## Ключевая мысль

Срезка — это не ошибка компилятора, а следствие копирования по значению.
Если объект полиморфный, по значению его передавать нельзя.
