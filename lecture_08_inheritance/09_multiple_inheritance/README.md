# 09. Синтаксис множественного наследования

**Пункт плана:** 9.

## Что показывает пример

* `Copier : public Printer, public Scanner` — класс получает интерфейсы
  двух независимых баз.
* Порядок конструирования задаётся **списком наследования** (слева направо),
  а не списком инициализации.
* Неоднозначность одноимённых членов (`Printer::status` и `Scanner::status`)
  и её разрешение квалификацией.
* Корректировку указателей: адрес `B*` внутри `C : A, B` смещён
  относительно `C*`; `static_cast` возвращает его обратно.

## Запуск

```bash
./build/09_multiple_inheritance
```

## Плохо → Хорошо

**Плохо** — обращаться к одноимённым членам баз без квалификации:

```cpp
class Copier : public Printer, public Scanner {};
Copier c;
c.status();   // ОШИБКА: Printer::status или Scanner::status?
```

**Хорошо** — разрешить неоднозначность явно:

```cpp
c.Printer::status();
c.Scanner::status();
// или объявить собственный status() в Copier
```

**Почему:** компилятор не имеет права выбрать одну из баз за вас.

## Память и указатели

```
C : A, B   ->   [ A-подобъект ][ B-подобъект ][ поля C ]
                       ^              ^
                       |              +-- B* смещён на sizeof(A)
                       +-- C* и A* обычно совпадают
```

`static_cast` корректирует адрес автоматически; `reinterpret_cast` — нет,
поэтому для навигации по иерархии он непригоден.

## Ключевая мысль

Множественное наследование — это не «два класса в одном», а два независимых
подобъекта. Неоднозначности разрешаются квалификацией, а смещения указателей
компилятор берёт на себя при корректном приведении.
