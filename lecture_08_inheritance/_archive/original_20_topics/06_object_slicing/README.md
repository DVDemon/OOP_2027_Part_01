# 06. Срезка объектов (object slicing)

**Пункт плана:** 6.

## Что показывает пример

* Присваивание `Base b = derived;` копирует только Base-часть — производная теряется.
* Передача по значению срезает объект внутри параметра функции.
* Передача по ссылке/указателю сохраняет полиморфизм.

## Запуск

```bash
./build/06_object_slicing
```

## Плохо → Хорошо

**Плохо** — хранить и передавать полиморфные объекты по значению:

```cpp
void process(Base b);          // срезка в параметре
std::vector<Base> shapes;      // срезка при добавлении наследников
```

Виртуальные вызовы пойдут к `Base`, производные данные исчезнут.

**Хорошо** — работать через ссылку или указатель (в контейнерах — умные указатели):

```cpp
void process(const Base& b);                 // без срезки, полиморфизм работает
std::vector<std::unique_ptr<Base>> shapes;   // хранит наследников целиком
```

**Почему:** объект базового типа физически меньше наследника, поэтому копирование
«в базу» отбрасывает лишние поля и таблицу виртуальных функций наследника.
Ссылка и указатель не копируют объект, а ссылаются на исходный — полиморфизм сохраняется.
