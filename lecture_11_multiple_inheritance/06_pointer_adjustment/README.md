# 06. Корректировка указателей (pointer adjustment)

**Пункт плана:** 6 — корректировка указателей.

## Что показывает пример

* При множественном наследовании приведение к разным базам может менять
  **числовое значение** указателя (B-подобъект смещён относительно начала C).
* `static_cast`/`dynamic_cast` выполняют корректировку **автоматически**.
* `reinterpret_cast` корректировку **не делает** — он запрещён для навигации
  по иерархии наследования.

## Запуск

```bash
./build/06_pointer_adjustment
```

Ожидаемый вывод (адреса различаются от запуска к запуску):

```
C*: 0x...
A*: 0x...      <- обычно совпадает с C*
B*: 0x...      <- смещён относительно C*
pa == pc (как void*)? true
pb == pc (как void*)? false  <- указатель скорректирован
static_cast<C*>(pb) вернул исходный объект? true
A::hello_a, a=1
B::hello_b, b=2
C::hello_c, c=3
```

## Плохо → Хорошо

**Плохо** — использовать `reinterpret_cast` для перехода между типами в иерархии:

```cpp
B* pb = &obj;
C* bad = reinterpret_cast<C*>(pb);  // НЕ корректирует смещение!
bad->hello_c();                     // UB: читаем поля по неверному адресу
```

**Хорошо** — `static_cast` (или `dynamic_cast`) корректирует смещение правильно:

```cpp
B* pb = &obj;
C* good = static_cast<C*>(pb);  // компилятор вычитает смещение B-подобъекта
good->hello_c();                // корректно
```

**Почему:** B-подобъект расположен не в начале объекта `C`, поэтому `B*`
численно отличается от `C*`. `static_cast`/`dynamic_cast` знают раскладку
объекта и прибавляют/вычитают нужное смещение. `reinterpret_cast` лишь
переинтерпретирует биты адреса без корректировки — результат указывает «не туда»
и приводит к неопределённому поведению.
