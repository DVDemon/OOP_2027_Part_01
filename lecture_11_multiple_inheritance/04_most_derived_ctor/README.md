# 04. Ответственность наиболее производного класса за вызов конструктора

**Пункт плана:** 4 — most-derived класс отвечает за вызов конструктора
виртуальной базы.

## Что показывает пример

* При виртуальном наследовании конструктор виртуальной базы `A` вызывает
  **только** наиболее производный класс (most-derived).
* Вызовы `A(1)` и `A(2)` внутри промежуточных `B` и `C` **игнорируются**, когда
  эти классы не являются most-derived (как при создании `D`).
* Если объект `B` создаётся напрямую — most-derived уже сам `B`, и его `A(1)`
  срабатывает.

## Запуск

```bash
./build/04_most_derived_ctor
```

Ожидаемый вывод:

```
=== Создаём D ===
A(999)
B()
C()
D()
=== Создаём B напрямую ===
A(1)
B()
```

## Плохо → Хорошо

**Плохо** — рассчитывать, что промежуточный класс проинициализирует
виртуальную базу за most-derived:

```cpp
class D : public B, public C {
public:
    D() : B(), C() {}   // ОШИБКА: A не имеет конструктора по умолчанию,
                        // а D не вызвал A(...) явно -> не компилируется
};
```

**Хорошо** — most-derived класс вызывает конструктор виртуальной базы сам:

```cpp
class D : public B, public C {
public:
    D() : A(999), B(), C() {}   // OK: D берёт ответственность на себя
};
```

**Почему:** виртуальная база разделяется между путями ромба, поэтому её
конструктор не может вызываться дважды (из `B` и из `C`). Стандарт возлагает
единственный вызов на наиболее производный класс. Если у виртуальной базы нет
конструктора по умолчанию и most-derived не вызвал её конструктор явно — это
ошибка компиляции (одна из типичных ловушек MI).
