# 03. Виртуальное наследование: синтаксис и семантика

**Пункт плана:** 3 — виртуальное наследование.

## Что показывает пример

* Синтаксис `virtual public Device` в списке наследования промежуточных классов.
* Семантику: в объекте `Copier` существует **единственный** общий подобъект `Device`.
* Отсутствие неоднозначности при `c.id`.
* Порядок конструирования: виртуальная база конструируется **самой первой**.

```
        Device  (один экземпляр)
        /    \
    Printer  Scanner   (virtual public Device)
        \    /
        Copier
```

## Запуск

```bash
./build/03_virtual_inheritance
```

Ожидаемый вывод:

```
Device(42)
Printer()
Scanner()
Copier()
---
c.id = 42
&c.Printer::Device::id == &c.Scanner::Device::id? true
Printer id=42
doc id=42
```

## Плохо → Хорошо

**Плохо** — оставить обычное наследование там, где предок логически общий:

```cpp
class Printer : public Device { /* ... */ };  // нет virtual
class Scanner : public Device { /* ... */ };  // нет virtual
// -> две копии Device, неоднозначность, дублирование id
```

**Хорошо** — пометить наследование от общего предка как `virtual`:

```cpp
class Printer : virtual public Device { /* ... */ };
class Scanner : virtual public Device { /* ... */ };
// -> один общий Device на весь Copier
```

**Почему:** `virtual` сообщает компилятору, что подобъект `Device` должен быть
**разделяемым** между всеми путями ромба. Все промежуточные классы ссылаются на
один и тот же экземпляр через `vbptr`, поэтому `id` гарантированно один и
обращение к нему однозначно.

> Замечание: `virtual` указывают **промежуточные** классы (`Printer`, `Scanner`),
> а отвечает за вызов конструктора `Device` — наиболее производный класс `Copier`
> (см. пример [`04_most_derived_ctor`](../04_most_derived_ctor)).
