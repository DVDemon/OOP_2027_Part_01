# 08. Оператор `->` (proxy-объекты)

**Пункт плана:** 8.

## Что показывает пример

* `SmartPtr<T>` — `operator->` возвращает `T*` (классический умный
  указатель).
* `LoggingWrapper<T>` + `LoggingProxy<T>` — `operator->` возвращает не
  указатель, а объект-прокси, у которого тоже есть `operator->`.
* «Drill-down»: компилятор повторяет `->`, пока не получит сырой
  указатель. Прокси даёт хук «до» и «после» обращения (RAII).

## Запуск

```bash
./build/08_arrow_proxy
```

## Плохо → Хорошо

**Плохо** — обращаться к ресурсу напрямую и вручную логировать каждый раз:

```cpp
std::cout << "доступ начат\n";
widget.hello();
std::cout << "доступ завершён\n";
```

ПОЧЕМУ плохо: ручной парный код легко забыть; при исключении «завершён»
не напечатается; засоряет вызывающий код.

**Хорошо** — прокси через `operator->`:

```cpp
LoggingProxy<T> operator->() { return LoggingProxy<T>(&obj_); }
// ...
w->hello();   // лог "начат" в конструкторе прокси, "завершён" — в деструкторе
```

ПОЧЕМУ хорошо: временный прокси живёт ровно на время выражения. Его
конструктор/деструктор гарантированно обрамляют вызов (даже при
исключении), а вызывающий код остаётся чистым: просто `w->hello()`.

> Правило: `operator->` должен вернуть либо указатель, либо объект,
> у которого тоже есть `operator->`.
