# 09. Операторы преобразования типа, `explicit`

**Пункт плана:** 9.

## Что показывает пример

* Неявный `operator double()` — естественное преобразование дроби в число.
* `explicit operator bool()` — работает в условиях (`if (f)`), но не в
  арифметике.
* Ловушку неявных преобразований, ведущую к скрытым багам.

## Запуск

```bash
./build/09_conversions
```

## Плохо → Хорошо

**Плохо** — неявный `operator bool()`:

```cpp
operator bool() const { return num_ != 0; }   // без explicit
// Fraction f(3, 4);
// int x = f + 1;   // КОМПИЛИРУЕТСЯ: f -> true -> 1, итог x == 2 (!)
```

ПОЧЕМУ плохо: компилятор молча превращает объект в `bool`, затем в `int`,
и арифметика «срабатывает» с бессмысленным результатом. Подобные ловушки
особенно опасны со сравнениями (`s == "hello"` сравнит указатели, а не
строки).

**Хорошо** — `explicit`:

```cpp
explicit operator bool() const { return num_ != 0; }
// if (f) { ... }                 // OK: булев контекст
// int x = f + 1;                 // ОШИБКА компиляции — и хорошо!
```

ПОЧЕМУ хорошо: `explicit` разрешает преобразование только там, где оно
осмысленно (условия `if`, `while`, `&&`, `||`), и блокирует случайные
неявные конверсии.

> **Правило:** операторы преобразования делайте `explicit`, если только
> преобразование не абсолютно естественно (как дробь -> `double`).
