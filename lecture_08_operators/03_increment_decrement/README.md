# 03. Префиксный и постфиксный `++` / `--`

**Пункт плана:** 3.

## Что показывает пример

* Префиксный `operator++()` — меняет объект, возвращает `Counter&`.
* Постфиксный `operator++(int)` — фиктивный параметр `int` отличает его
  от префиксного; возвращает копию объекта ДО изменения.
* Постфиксный реализован через префиксный (не дублируем логику).

## Запуск

```bash
./build/03_increment_decrement
```

## Плохо → Хорошо

**Плохо** — постфиксный возвращает ссылку (как префиксный):

```cpp
Counter& operator++(int) {   // НЕВЕРНАЯ семантика
    ++value_;
    return *this;            // вернёт УЖЕ изменённое значение
}
```

ПОЧЕМУ плохо: семантика `c++` требует вернуть значение ДО инкремента.
Возврат `*this` после `++` ломает выражения вида `arr[i++]`.

**Хорошо** — сохранить старое состояние, вернуть копию:

```cpp
Counter operator++(int) {
    Counter old = *this;   // запоминаем состояние ДО
    ++(*this);             // переиспользуем префиксный
    return old;            // возвращаем КОПИЮ по значению
}
```

ПОЧЕМУ хорошо: корректная семантика и нет дублирования — изменение
выполняет единственный префиксный оператор.

> **Предпочитайте `++i`**: постфиксный создаёт лишнюю копию. Для тяжёлых
> объектов это заметная цена.
