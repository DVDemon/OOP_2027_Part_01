# 10. Пользовательские литералы и канонические формы

**Пункт плана:** 10.

## Что показывает пример

* Класс `Money` (хранит копейки в целом числе — без ошибок округления).
* Пользовательские литералы `operator""_rub` (для целого и для дробного
  литерала).
* Канонические формы в одном классе: `+=`→`+`, `<=>` по умолчанию,
  `explicit operator bool`, `operator<<`.
* `constexpr`-операторы и `static_assert` (вычисление на этапе компиляции).

## Запуск

```bash
./build/10_literals_canonical
```

## Канонические формы (шпаргалка)

| Оператор | Форма | Возврат |
|----------|-------|---------|
| `+` | `friend T operator+(T lhs, const T& rhs)` | `T` (через `+=`) |
| `+=` | `T& operator+=(const T&)` | `T&` |
| `++` (pre) | `T& operator++()` | `T&` |
| `++` (post) | `T operator++(int)` | `T` (через pre) |
| `<=>` | `auto operator<=>(const T&) const` | `ordering` |
| `<<` | `friend ostream& operator<<(ostream&, const T&)` | `ostream&` |
| `[]` | `T& operator[](size_t)` + const-версия | `T&` / `const T&` |
| `bool` | `explicit operator bool() const` | `bool` |

## Плохо → Хорошо

**Плохо** — хранить деньги в `double` и создавать «магическими» числами:

```cpp
double total = 100.0 - 49.90;   // 50.0999999... — ошибка округления
Money m(10000);                 // что значит 10000? рубли? копейки?
```

ПОЧЕМУ плохо: `double` накапливает ошибки округления (деньги этого не
прощают), а «голое» число в конструкторе нечитаемо.

**Хорошо** — целые копейки + выразительный литерал:

```cpp
Money price = 100_rub;          // сразу понятно: 100 рублей
Money total = 100_rub - 49.90_rub;   // точная арифметика в копейках
```

ПОЧЕМУ хорошо: литерал `_rub` делает единицу измерения частью кода
(не перепутать рубли с копейками), а целочисленное хранение исключает
ошибки округления.

> Имя пользовательского литерала ОБЯЗАНО начинаться с `_` — имена без
> подчёркивания зарезервированы за стандартной библиотекой.
