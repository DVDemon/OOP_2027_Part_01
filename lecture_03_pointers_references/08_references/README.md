# 08. lvalue-ссылки. Указатели vs ссылки. Константные ссылки

**Пункт плана:** 8.

## Что показывает пример

* Ссылка как псевдоним: тот же адрес, что у оригинала.
* Передача по ссылке (`int&`) и по const-ссылке (`const int&`).
* `const int& cref = 42;` — продление жизни временного объекта.

## Свойства ссылок

1. Должна быть инициализирована при создании.
2. Нельзя переназначить на другой объект.
3. Не может быть `nullptr`.
4. Нет «арифметики ссылок».

| Свойство | Указатель | Ссылка |
|---|---|---|
| Может быть `nullptr` | да | нет |
| Можно переназначить | да | нет |
| Требует разыменования | да (`*ptr`) | нет |
| Инициализация обязательна | нет | да |
| Арифметика | да | нет |

## Плохо → Хорошо

**Плохо** — принимать большой объект по значению: создаётся лишняя копия:

```cpp
void print(std::string s);   // копия всей строки на каждый вызов
```

**Хорошо** — принимать по `const`-ссылке (без копии, без права на изменение):

```cpp
void print(const std::string& s);   // ни копии, ни изменений
```

А когда функция должна **изменить** аргумент — берите неконстантную ссылку:

```cpp
void increment(int& value) { ++value; }   // меняет оригинал, без * как у указателя
```

**Почему:** ссылка — это псевдоним существующего объекта; передача по ссылке избегает копирования.
Используйте ссылки, когда можете (нагляднее, не `nullptr`); указатели — когда нужен `nullptr`,
переназначение или арифметика.
