# 09. Range-for со ссылками. Категории значений

**Пункт плана:** 9.

## Что показывает пример

* Range-for: по ссылке (`auto&`), по const-ссылке (`const auto&`), по значению (`auto`).
* Категории значений: **lvalue** (имеет адрес), **prvalue** (временное), **xvalue** (готово к перемещению).
* Привязка ссылок к разным категориям.

```
          выражение
         /         \
      glvalue      rvalue
      /    \       /    \
   lvalue  xvalue  xvalue  prvalue
```

## Запуск

```bash
./build/09_value_categories
```

## Примеры категорий

| Категория | Примеры |
|---|---|
| lvalue | `x`, `arr[i]`, `*ptr`, `s[0]` |
| prvalue | `42`, `x + 1`, `std::string("tmp")` |
| xvalue | `std::move(x)` |

## Плохо → Хорошо

**Плохо** — итерировать большие объекты по значению: копия на каждой итерации:

```cpp
std::vector<std::string> rows = /* ... */;
for (auto row : rows) {        // копирует каждую строку
    std::cout << row << '\n';
}
```

**Хорошо** — `const auto&` для чтения, `auto&` для изменения:

```cpp
for (const auto& row : rows) std::cout << row << '\n';  // только чтение, без копий
for (auto& row : rows) row += "!";                      // изменение на месте
```

**Почему:** `auto` в range-for делает копию элемента. Для тяжёлых типов это дорого. Ссылка
устраняет копирование; `const` дополнительно защищает от случайного изменения. Понимание lvalue/rvalue
объясняет, почему `int& r = x + 1;` запрещено, а `const int& r = x + 1;` — нет.
