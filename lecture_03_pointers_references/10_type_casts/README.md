# 10. Приведение типов

**Пункт плана:** 10.

## Что показывает пример

* Неявные преобразования (расширение/сужение).
* `static_cast` — явное безопасное приведение, `void* -> T*`.
* `const_cast` — снятие `const` (и почему это опасно).
* `reinterpret_cast` — побитовый просмотр байтов `int`.

| Оператор | Назначение | Безопасность |
|---|---|---|
| `static_cast` | явные безопасные преобразования | высокая |
| `const_cast` | снятие/добавление `const` | средняя |
| `reinterpret_cast` | побитовая реинтерпретация | низкая |
| `dynamic_cast` | приведение в иерархии (позже) | высокая |
| `(type)expr` | C-style | избегать |

## Плохо → Хорошо

**Плохо** — C-style приведение: непонятно, какое именно преобразование выполняется, и компилятор молчит:

```cpp
double pi = 3.99;
int n = (int)pi;            // что это: сужение? reinterpret? снятие const? непонятно
char* s = (char*)&pi;       // молча превращается в reinterpret_cast — опасно
```

**Хорошо** — именованные приведения C++: явное намерение, проверка компилятором, легко найти поиском:

```cpp
int n = static_cast<int>(pi);                         // явное сужение
auto* s = reinterpret_cast<unsigned char*>(&pi);      // явная побитовая реинтерпретация
```

**Почему:** C-style каст молча выбирает любое из преобразований (включая `reinterpret`/`const_cast`),
скрывая опасные операции. Именованные `*_cast` документируют намерение, ограничивают допустимые
преобразования и легко находятся в коде при ревью. `const_cast` снятия `const` с реально `const`-объекта
и запись в него — это UB; `reinterpret_cast` оставляйте для низкоуровневого кода (сериализация, hardware).
