# 01. Модель памяти процесса

**Пункт плана:** 1.

## Что показывает пример

* Четыре сегмента адресного пространства: стек, куча, статическая память, сегмент кода.
* Как получить и сравнить адреса объектов из разных сегментов.
* Размер указателя не зависит от типа данных.

```
Высокие адреса
┌─────────────────────┐
│       Стек (stack)   │ ← локальные переменные, адреса возврата (растёт вниз)
│         ↓            │
│         ↑            │
│       Куча (heap)    │ ← динамическая память (new/delete)
├─────────────────────┤
│   Статическая память │ ← глобальные и static переменные
├─────────────────────┤
│   Сегмент кода       │ ← машинные инструкции (read-only)
└─────────────────────┘
Низкие адреса
```

## Плохо → Хорошо

**Плохо** — выделять крупные данные на стеке: стек ограничен (1-8 МБ), легко получить переполнение стека:

```cpp
int big[2'000'000];   // ~8 МБ на стеке — риск stack overflow
```

**Хорошо** — крупные данные хранить в куче (а лучше в контейнере, который управляет памятью сам):

```cpp
int* big = new int[2'000'000];   // куча: размер ограничен лишь ОЗУ
// ... использование ...
delete[] big;
```

**Почему:** стек быстрый, но маленький и с автоматическим временем жизни; куча большая и гибкая, но требует ручного управления (или умных указателей/контейнеров).
