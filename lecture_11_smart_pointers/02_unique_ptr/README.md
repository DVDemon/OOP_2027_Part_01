# 02. `std::unique_ptr`

**Пункт плана:** 2.

## Что показывает пример

* Создание через `make_unique` и через конструктор.
* Операции `get`, `reset`, проверку на `nullptr`.
* Запрет копирования и передачу владения через `std::move`.
* `unique_ptr` для массива.
* Пользовательский deleter для ресурса C-библиотеки (`FILE*`).

## Запуск

```bash
./build/02_unique_ptr
```

## Основные операции

| Операция | Смысл |
|----------|-------|
| `get()` | сырой указатель, владение НЕ передаётся |
| `reset(p)` | освободить старый ресурс, владеть новым |
| `release()` | отказаться от владения (вызывающий обязан `delete`) |
| `std::move(p)` | передать владение, исходный становится `nullptr` |

## Плохо → Хорошо

**Плохо** — `unique_ptr` из «голого» `new` и попытка копирования:

```cpp
std::unique_ptr<int> p(new int(42));
auto q = p;   // ОШИБКА компиляции: копирование запрещено
```

**Хорошо** — `make_unique` и явная передача владения:

```cpp
auto p = std::make_unique<int>(42);
auto q = std::move(p);   // владение перешло, p == nullptr
```

**Почему:** `unique_ptr` моделирует *единоличное* владение — копирование
означало бы два владельца одного ресурса и двойной `delete`. `make_unique`
к тому же исключает «голый» `new` в коде и безопасен при исключениях.
