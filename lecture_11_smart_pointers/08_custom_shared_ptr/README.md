# 08. Реализация собственного `SharedPtr` (учебная)

**Пункт плана:** 8.

## Что показывает пример

* Учебную реализацию `edu::SharedPtr` (`shared_ptr.h`): конструкторы,
  копирование (с увеличением счётчика), перемещение, присваивание,
  `use_count`, `reset`.
* Освобождение объекта при достижении счётчиком нуля.

## Сборка и запуск

```bash
cmake -S .. -B ../build       # из папки лекции
cmake --build ../build
./../build/08_custom_shared_ptr
```

Цели: `08_custom_shared_ptr` — демонстрация в консоли.

## Плохо → Хорошо

**Плохо** — копировать `shared_ptr`, не трогая счётчик:

```cpp
SharedPtr(const SharedPtr& o) : ptr_(o.ptr_), ref_count_(o.ref_count_) {}
// счётчик не вырос -> объект удалят слишком рано -> висячий указатель
```

**Хорошо** — копирование увеличивает счётчик, разрушение уменьшает:

```cpp
SharedPtr(const SharedPtr& o) : ptr_(o.ptr_), ref_count_(o.ref_count_) {
    if (ref_count_) ++(*ref_count_);
}
~SharedPtr() { release(); }   // --count; при нуле delete объекта и счётчика
```

**Почему:** `shared_ptr` владеет ресурсом совместно. Счётчик должен точно
отражать число владельцев: каждая новая копия его увеличивает, каждое
разрушение — уменьшает, и только переход к нулю освобождает ресурс.
Несоблюдение этого инварианта даёт либо преждевременное удаление, либо утечку.

## Чего не хватает по сравнению с `std::shared_ptr`

* **Потокобезопасности.** Настоящий `std::shared_ptr` меняет счётчик
  атомарными операциями; учебная версия использует обычный `++/--` и не
  безопасна при доступе из нескольких потоков.
* Хранения deleter и allocator в control block, поддержки `weak_ptr`,
  единой аллокации объекта и блока (как в `make_shared`).
