# 05. Цикл `shared_ptr` между двумя классами

**Пункт плана:** 5.

## Что показывает пример

* Два класса ссылаются друг на друга **сильными** указателями: `Author` владеет
  `Document`, а `Document` — `Author`. Это цикл владения.
* **Удаление не освобождает память**: после `reset` внешних `shared_ptr`
  счётчики ссылок остаются равны 1 (каждый объект держит другой), деструкторы
  не вызываются — утечка.
* Утечку видно по счётчику живых экземпляров: после выхода из области видимости
  он не ноль. `weak_ptr` подтверждает, что объекты живы, хотя снаружи ссылок на
  них уже нет.
* **Обход** — сделать обратную связь наблюдающей: владеет документ автором,
  автор смотрит на документ через `weak_ptr`. Владение одностороннее, поэтому
  объекты освобождаются вместе с владельцем.

## Запуск

```bash
./build/05_shared_ptr_cycle
```

## Ожидаемый вывод

```
--- ПЛОХО: shared_ptr в обе стороны ---
  Author(Толстой) создан
  Document(Война и мир) создан
  use_count(author) = 2, use_count(document) = 2
  ссылки снаружи сброшены: автор жив — да, документ жив — да
  живых Author = 1, Document = 1 — память не освобождена (утечка)

--- ХОРОШО: обратная связь через weak_ptr ---
  Author(Толстой) создан
  Document(Война и мир) создан
  use_count(author) = 2, use_count(document) = 1
  документ видит автора: Толстой
  после reset(author) автор жив — да (его держит документ)
  ~Document(Война и мир)
  ~Author(Толстой)
  после reset(document): автор жив — нет, документ жив — нет
  живых Author = 0, Document = 0 — память освобождена
```

## Плохо → Хорошо

**Плохо** — обе связи владеющие:

```cpp
class Author {
    std::shared_ptr<Document> document_;   // автор владеет документом
};

class Document {
    std::shared_ptr<Author> author_;       // документ владеет автором
};

// author -> document -> author: use_count никогда не станет 0
```

**Хорошо** — владеет только одна сторона, обратная связь наблюдает:

```cpp
class Author {
    std::weak_ptr<Document> document_;     // наблюдение, не владение
};

class Document {
    std::shared_ptr<Author> author_;       // единственный владелец
};
```

**Почему:** `shared_ptr` освобождает объект, когда счётчик сильных ссылок
достигает нуля. В цикле счётчик каждого объекта уменьшается, но не до нуля:
внешние ссылки убрали, а внутренние остались. Объекты становятся недостижимыми,
но живыми — это и есть утечка, и никакой код её уже не освободит.

**Куда ставить `weak_ptr`.** Слабой делают **обратную** связь (от зависимого
объекта к владельцу): «документ знает автора» — сильная, «автор знает свой
документ» — слабая. Если сделать слабыми обе связи, владельца не останется и
объекты будут удаляться раньше, чем ими закончат пользоваться.
