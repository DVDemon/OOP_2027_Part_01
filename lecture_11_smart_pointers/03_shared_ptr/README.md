# 03. `std::shared_ptr`

**Пункт плана:** 3.

## Что показывает пример

* Разделяемое владение и подсчёт ссылок (`use_count`).
* Как копирование увеличивает счётчик, а разрушение копии — уменьшает.
* Удаление объекта при достижении счётчиком нуля.
* `make_shared` (одна аллокация) против `shared_ptr(new T)` (две аллокации).

## Запуск

```bash
./build/03_shared_ptr
```

## Внутреннее устройство

```
shared_ptr<T> sp:
+----------+
| ptr  -----------> T object
| ctrl -----------> Control Block
+----------+        +-------------------+
                    | strong_count      |
                    | weak_count        |
                    | deleter/allocator |
                    +-------------------+
```

## Плохо → Хорошо

**Плохо** — две аллокации и риск утечки при вычислении аргументов:

```cpp
std::shared_ptr<Widget> p(new Widget(...));  // объект + control block раздельно
f(std::shared_ptr<Widget>(new Widget),
  std::shared_ptr<Widget>(new Widget));      // порядок вычисления не определён
```

**Хорошо** — `make_shared`:

```cpp
auto p = std::make_shared<Widget>(...);      // одна аллокация
f(std::make_shared<Widget>(), std::make_shared<Widget>());
```

**Почему:** `make_shared` размещает объект и control block в одном блоке памяти
(быстрее, лучше для кэша) и не оставляет «голого» `new`, который мог бы утечь,
если между выделением и захватом указателя возникнет исключение.
