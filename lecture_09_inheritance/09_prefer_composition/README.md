# 09. Принцип «предпочитайте композицию наследованию»

**Пункт плана:** 9.

## Что показывает пример

* `Car` **содержит** `Engine` (отношение has-a) через композицию.
* Делегирование: `Car::start()` обращается к методу двигателя.

## Сборка и запуск

```bash
cmake -S .. -B ../build       # из папки лекции
cmake --build ../build
./../build/09_prefer_composition
```

Цели: `09_prefer_composition` — демонстрация в консоли.

## Плохо → Хорошо

**Плохо** — наследование там, где отношение на самом деле has-a:

```cpp
class Car : public Engine { ... };   // машина НЕ "является" двигателем
```

Также классический антипример нарушения LSP: `Circle : public Ellipse` —
у эллипса два радиуса, и `setRadii(3, 5)` делает «круг» не-кругом.

**Хорошо** — композиция отражает отношение «содержит»:

```cpp
class Car {
    Engine engine_;       // машина СОДЕРЖИТ двигатель
};
```

**Почему:** `public`-наследование означает is-a и обязано проходить тест Лисков (LSP):
наследник должен быть взаимозаменяем с базой. Если это не так — наследование ломает
семантику и подстановку. Композиция выражает has-a, даёт слабую связь и гибкость.
