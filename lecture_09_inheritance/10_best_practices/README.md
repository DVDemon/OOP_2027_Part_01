# 10. Практические рекомендации (иерархия фигур)

**Пункт плана:** 10 (а также практическое задание лекции).

## Что показывает пример

* Иерархия `Shape` → `Rectangle` → `Square` (практическое задание).
* Виртуальный деструктор у полиморфной базы.
* Хранение полиморфных объектов через `std::unique_ptr` (без срезки).
* Демонстрация срезки и её последствий.
* `final` у `Square` — запрет дальнейшего наследования.

## Сборка и запуск

```bash
cmake -S .. -B ../build       # из папки лекции
cmake --build ../build
./../build/10_best_practices
```

Цели: `10_best_practices` — демонстрация в консоли.

## Замечание про LSP (`Square : Rectangle`)

Строго по LSP квадрат — не вполне «прямоугольник»: у прямоугольника стороны
меняются независимо, у квадрата нет. Поэтому в примере мы НЕ даём независимых
сеттеров сторон, а фиксируем инвариант (сторона одна) в конструкторе. Это
сохраняет подстановочность для операций чтения (`area`, `perimeter`).

## Плохо → Хорошо

**Плохо** — типичные ошибки наследования:

```cpp
class Shape { ~Shape(); };                 // невиртуальный деструктор базы
std::vector<Shape> figures;                // срезка наследников
class Square : public Rectangle {          // плюс независимые сеттеры сторон
    void setWidth(double);                 // ломает инвариант квадрата (LSP)
};
```

**Хорошо** — следовать рекомендациям лекции:

```cpp
class Shape { virtual ~Shape() = default; };          // виртуальный деструктор
std::vector<std::unique_ptr<Shape>> figures;          // без срезки
class Square final : public Rectangle {               // final, без опасных сеттеров
    std::string name() const override;                // override обязателен
};
```

**Почему:** виртуальный деструктор нужен для корректного удаления через `Shape*`;
умные указатели хранят наследников целиком и сохраняют полиморфизм; `override`
ловит опечатки в сигнатурах; отсутствие независимых сеттеров не нарушает LSP;
`final` фиксирует, что дальше иерархию расширять не предполагается.
