# 08. Правило пяти и Правило нуля

**Пункт плана:** 8 — Правило пяти (Rule of Five) и Правило нуля (Rule of Zero).

## Что показывает пример

* `Buffer` владеет сырым `std::byte*` и определяет все пять спецметодов
  (деструктор, копирующие и перемещающие конструктор и присваивание).
* `Person` хранит `std::string` и `std::vector` — не определяет НИ ОДНОГО
  спецметода (Rule of Zero); компилятор генерирует корректные.

## Запуск

```bash
./build/08_rule_of_five_zero
```

## Два правила

* **Rule of Five.** Если класс управляет ресурсом напрямую (сырой указатель,
  файловый дескриптор и т. п.), определите все пять: `~T`, `T(const T&)`,
  `T& operator=(const T&)`, `T(T&&)`, `T& operator=(T&&)`.
* **Rule of Zero.** Если класс не управляет ресурсом напрямую, не определяйте
  ни одного спецметода — делегируйте владение членам-обёрткам.

## Плохо → Хорошо

**Плохо** — управлять памятью вручную там, где это не нужно:

```cpp
class Person {
    char* name_;   // зачем сырой указатель?
public:
    Person(const char* n) : name_(new char[std::strlen(n) + 1]) { /* ... */ }
    ~Person() { delete[] name_; }
    // и теперь ОБЯЗАН написать ещё 4 метода правила пяти, не ошибившись...
};
```

**Почему плохо:** ручное управление памятью — источник ошибок (double free,
утечки, забытый `noexcept`). Вы берёте на себя работу, которую уже идеально
делает стандартная библиотека.

**Хорошо** — Rule of Zero: хранить данные в RAII-обёртках:

```cpp
class Person {
    std::string name_;       // сам управляет памятью
    std::vector<int> ids_;   // тоже
    int age_ = 0;
    // НИ ОДНОГО спецметода: компилятор сгенерирует корректные copy/move/dtor
};
```

**Почему хорошо:** `std::string`/`std::vector`/`unique_ptr` уже реализуют
правило пяти. Компилятор соберёт из них корректные операции автоматически.
Меньше кода — меньше ошибок.

> Совет: по умолчанию стремитесь к Rule of Zero. Rule of Five применяйте
> только в низкоуровневых классах-обёртках над ресурсом (как сам
> `std::vector` внутри).
