# 04. Идиома copy-and-swap

**Пункт плана:** 4 — идиома copy-and-swap.

## Что показывает пример

* Оператор присваивания принимает аргумент **по значению** (`Text other`).
* Дружественный `swap` без исключений (`noexcept`).
* Один оператор обслуживает и копирующее, и перемещающее присваивание.
* Самоприсваивание работает корректно без явной проверки `this == &other`.

## Запуск

```bash
./build/04_copy_and_swap
```

## Идиома

```cpp
friend void swap(Text& a, Text& b) noexcept {
    using std::swap;
    swap(a.size_, b.size_);
    swap(a.data_, b.data_);
}

Text& operator=(Text other) {   // аргумент по значению -> копия уже сделана
    swap(*this, other);          // обмениваемся; старые данные уйдут с other
    return *this;                // деструктор other освободит старый буфер
}
```

## Плохо → Хорошо

**Плохо** — ручное присваивание с проверкой самоприсваивания и хрупким
порядком операций:

```cpp
Text& operator=(const Text& other) {
    if (this == &other) return *this;   // нужна явная проверка
    delete[] data_;                     // освободили...
    data_ = new char[other.size_ + 1];  // ...а если new бросит — dangling!
    std::strcpy(data_, other.data_);
    size_ = other.size_;
    return *this;
}
```

**Почему плохо:** легко ошибиться с порядком (`delete` до `new`), нужна
отдельная проверка самоприсваивания, нет общей реализации для move.

**Хорошо** — copy-and-swap (см. `main.cpp`):

* **Exception safety.** Копия делается при создании параметра, ещё до входа
  в тело. Если копирование бросит исключение, `*this` не тронут (сильная
  гарантия).
* **Самоприсваивание.** `a = a` просто создаёт временную копию и меняется с
  ней — никакой явной проверки не требуется.
* **Переиспользование.** Если есть перемещающий конструктор, тот же оператор
  обслуживает и `a = std::move(b)`: параметр будет создан перемещением.

> Цена — одна дополнительная копия. Для большинства классов это приемлемо
> ради простоты и безопасности.
