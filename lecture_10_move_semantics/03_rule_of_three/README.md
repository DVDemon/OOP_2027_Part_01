# 03. Правило трёх (Rule of Three)

**Пункт плана:** 3 — правило трёх.

## Что показывает пример

* Класс `IntArray` владеет динамическим массивом `int*`.
* Согласованно определены три специальных метода: деструктор, копирующий
  конструктор, копирующее присваивание.
* Копия независима от оригинала (изменение `b` не затрагивает `a`).

## Запуск

```bash
./build/03_rule_of_three
```

## Правило трёх

Если классу нужно пользовательское определение хотя бы одного из:

1. деструктора,
2. копирующего конструктора,
3. копирующего оператора присваивания —

то, скорее всего, нужны **все три**. Эти методы управляют одним и тем же
ресурсом, и определить только часть — значит оставить остальные в
поверхностной (опасной) форме.

## Плохо → Хорошо

**Плохо** — определить деструктор, но забыть про копирование:

```cpp
class IntArray {
    int* data_;
public:
    explicit IntArray(std::size_t n) : data_(new int[n]{}) {}
    ~IntArray() { delete[] data_; }   // деструктор есть...
    // ...а копирующий конструктор и присваивание — сгенерированы (shallow!)
};

IntArray a(3);
IntArray b = a;   // shallow copy: b.data_ == a.data_
// оба деструктора освободят один буфер -> double free (UB)
```

**Почему плохо:** наличие деструктора с `delete[]` — сигнал, что класс владеет
ресурсом. Сгенерированные компилятором копирующие операции делают
поверхностную копию указателя, и владение «раздваивается».

**Хорошо** — определить все три согласованно (см. `main.cpp`): копирующий
конструктор и присваивание выполняют глубокое копирование, деструктор
освобождает свой буфер.

> В современном C++ к этим трём добавляются move-операции — это уже
> Правило пяти (см. пример 08).
