# 06. Перемещающий конструктор и перемещающее присваивание

**Пункт плана:** 6 — перемещающий конструктор и перемещающее присваивание.

## Что показывает пример

* Перемещающий конструктор `Resource(Resource&&)` крадёт буфер источника,
  не выделяя новую память.
* Перемещающее присваивание `operator=(Resource&&)` освобождает свой ресурс
  и забирает чужой.
* Источник после перемещения обнулён — валидное, но неопределённое состояние.
* Счётчик выделений показывает: перемещения память не выделяют.

## Запуск

```bash
./build/06_move_ctor_assign
```

## Перемещающие операции

```cpp
Resource(Resource&& other) noexcept
    : size_(other.size_), data_(other.data_) {  // забрали указатель
    other.data_ = nullptr;                       // обнулили источник
    other.size_ = 0;
}

Resource& operator=(Resource&& other) noexcept {
    if (this != &other) {
        delete[] data_;          // освободили своё
        data_ = other.data_;     // украли чужое
        size_ = other.size_;
        other.data_ = nullptr;   // обнулили источник
        other.size_ = 0;
    }
    return *this;
}
```

## Плохо → Хорошо

**Плохо** — забыть обнулить источник после кражи указателя:

```cpp
Resource(Resource&& other) noexcept
    : size_(other.size_), data_(other.data_) {
    // забыли other.data_ = nullptr;
}
// теперь other.data_ и this->data_ указывают на один буфер
// деструктор other освободит его -> double free (UB)
```

**Почему плохо:** если источник не обнулён, и он, и приёмник владеют одним
буфером — при разрушении источника возникает double free.

**Хорошо** — после переноса указателя обнулить источник (см. `main.cpp`):
источник становится «пустым», его деструктор сделает `delete[] nullptr`
(безопасно), а владельцем буфера остаётся только приёмник.

> Перемещение особенно важно для временных объектов и `std::vector`:
> оно избегает дорогого глубокого копирования. Ключевое условие —
> пометить move-операции `noexcept` (см. пример 09).
