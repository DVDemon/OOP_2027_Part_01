# 09. noexcept для move-операций

**Пункт плана:** 9 — `noexcept` для move-операций.

## Что показывает пример

* Два почти одинаковых класса: `Good` (move-конструктор `noexcept`) и
  `Bad` (без `noexcept`).
* `std::is_nothrow_move_constructible_v<T>` различает их.
* При реаллокации `std::vector` перемещает элементы `Good`, но копирует
  элементы `Bad`.

## Запуск

```bash
./build/09_noexcept_move
```

Обратите внимание на вывод: для `Good` при добавлении второго элемента
печатается «перемещение», а для `Bad` — «копирование».

## Почему это важно

`std::vector` при росте должен перенести элементы в новый блок памяти. Он
обязан давать строгую гарантию исключений: если перенос прервётся, вектор
должен остаться в исходном состоянии. Перемещение «портит» источник, поэтому
вектор рискнёт перемещать только тогда, когда move-конструктор **гарантированно
не бросает** — то есть помечен `noexcept`. Иначе вектор выберет копирование.

## Плохо → Хорошо

**Плохо** — move-операции без `noexcept`:

```cpp
class Widget {
public:
    Widget(Widget&& other);             // нет noexcept
    Widget& operator=(Widget&& other);  // нет noexcept
};

std::vector<Widget> v;
v.push_back(/* ... */);  // при реаллокации vector КОПИРУЕТ (медленно)
```

**Почему плохо:** компилятор не знает, что перемещение безопасно, и ради
строгой гарантии исключений выбирает копирование. Вся выгода от move-семантики
теряется именно там, где она нужнее всего — в контейнерах.

**Хорошо** — помечать move-операции `noexcept`:

```cpp
class Widget {
public:
    Widget(Widget&& other) noexcept;             // ОБЯЗАТЕЛЬНО
    Widget& operator=(Widget&& other) noexcept;  // ОБЯЗАТЕЛЬНО
};
```

**Почему хорошо:** `std::vector` теперь перемещает элементы при реаллокации.
Проверить можно через `std::is_nothrow_move_constructible_v<Widget>`.

> Правило: move-конструктор и move-присваивание должны быть `noexcept`.
> Корректно написанные перемещения и не должны бросать — они лишь переносят
> указатели.
