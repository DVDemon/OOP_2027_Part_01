# Лекция 10. Виртуальные функции и полиморфизм

Примеры к лекции. Покрывают все пункты плана: виды полиморфизма, виртуальные
функции и их семантику, устройство vtable, спецификаторы `override`/`final`,
абстрактные классы и интерфейсы, виртуальный деструктор, `dynamic_cast`/RTTI,
виртуальные вызовы из конструктора/деструктора, стоимость виртуальных вызовов
и девиртуализацию, а также полиморфные коллекции и паттерны Factory Method и
Strategy.

## Сборка

```bash
cmake -S . -B build
cmake --build build
```

Запуск примеров:

```bash
./build/01_polymorphism_kinds
./build/02_virtual_functions
./build/03_vtable
./build/04_override_final
./build/05_abstract_interfaces_demo
./build/06_virtual_destructor
./build/07_dynamic_cast_rtti
./build/08_virtual_in_ctor
./build/09_devirtualization
./build/10_polymorphic_collections_demo
```

## Ключевые идеи лекции

1. **Три вида полиморфизма.** Ad-hoc (перегрузка) и параметрический (шаблоны) —
   на этапе компиляции; полиморфизм подтипов (`virtual`) — в runtime.
2. **`virtual` = позднее связывание.** Работает только через ссылку или
   указатель на базовый класс; передача по значению вызывает срезку (slicing).
3. **vtable и vptr** — механизм реализации виртуальных вызовов: один уровень
   косвенности по сравнению с обычным вызовом.
4. **`override`** превращает молчаливую ошибку (новая функция вместо
   переопределения) в ошибку компиляции; **`final`** запрещает переопределение
   и помогает девиртуализации.
5. **Абстрактный класс** (хотя бы одна `= 0`) нельзя инстанцировать;
   **интерфейс** — абстрактный класс из чисто виртуальных функций.
6. **Виртуальный деструктор обязателен** для полиморфных классов — иначе
   утечка при `delete` через указатель на базу.
7. **`dynamic_cast`/`typeid`** — безопасное приведение и RTTI; частое
   применение — признак плохого дизайна, предпочитайте виртуальные функции.
8. **Из конструктора/деструктора** виртуальные вызовы не полиморфны — объект
   ещё/уже не «стал» потомком.
9. **Полиморфные объекты** храните как `vector<unique_ptr<Base>>`; паттерны
   Factory Method и Strategy строятся на полиморфизме подтипов.
