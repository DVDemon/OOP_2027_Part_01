# 01. Виды полиморфизма

**Пункт плана:** 1 — виды полиморфизма: ad-hoc, параметрический, подтипов.

## Что показывает пример

* **Ad-hoc** (перегрузка функций/операторов) — разные реализации под одним именем,
  выбор по типам аргументов на этапе компиляции.
* **Параметрический** (шаблоны) — один код для любого подходящего типа.
* **Полиморфизм подтипов** (виртуальные функции) — выбор реализации в runtime
  по фактическому типу объекта. Это главная тема лекции.

## Запуск

```bash
./build/01_polymorphism_kinds
```

## Сравнение

| Вид | Механизм | Когда выбирается реализация |
|-----|----------|-----------------------------|
| Ad-hoc | перегрузка | этап компиляции (по типам аргументов) |
| Параметрический | шаблоны | этап компиляции (инстанцирование) |
| Подтипов | `virtual` | runtime (по фактическому типу) |

## Плохо → Хорошо

**Плохо** — ручная диспетчеризация по «тегу типа», которую легко забыть обновить:

```cpp
double area(const Shape& s) {
    if (s.kind == CIRCLE) return /* ... */;   // забудем новый тип — баг
    if (s.kind == SQUARE) return /* ... */;
    return 0;  // молча неверный результат
}
```

**Хорошо** — полиморфизм подтипов: добавили класс — переопределили `area()`,
весь остальной код работает без изменений и не требует правок:

```cpp
void printArea(const Shape& s) { std::cout << s.area(); }  // не знает конкретный тип
```

**Почему:** диспетчеризация по `if/switch` нарушает принцип
открытости/закрытости (OCP) — каждый новый тип требует правки всех таких мест.
Виртуальные функции переносят выбор реализации в сам объект.
