# 03. Таблица виртуальных функций (vtable)

**Пункт плана:** 3 — таблица виртуальных функций (vtable), устройство.

## Что показывает пример

* У класса с виртуальными функциями есть скрытый указатель **vptr** на **vtable** —
  массив адресов реализаций виртуальных методов.
* `sizeof` объекта включает место под `vptr`.
* У объектов разных классов `vptr` указывает на разные vtable.
* Виртуальный вызов = `vptr` → адрес из vtable → косвенный вызов.

> Внимание: vtable — деталь реализации компилятора, стандарт её не предписывает.
> Пример использует `reinterpret_cast` только для наглядности; в реальном коде
> так делать не нужно.

## Запуск

```bash
./build/03_vtable
```

## Схема

```
Объект Cat:             vtable Cat:
+----------+           +-------------------+
| vptr ----+---------->| &Cat::speak       |
| ...      |           | &Animal::eat      |   (не переопределён в Cat)
+----------+           +-------------------+

Объект Dog:             vtable Dog:
+----------+           +-------------------+
| vptr ----+---------->| &Dog::speak       |
| ...      |           | &Dog::eat         |
+----------+           +-------------------+
```

## Плохо → Хорошо

**Плохо** — пытаться диспетчеризовать вручную, имитируя vtable «руками»:

```cpp
struct Animal { int kind; void (*speak)(); };  // ручной указатель на функцию
```

**Хорошо** — довериться компилятору: `virtual` строит vtable автоматически,
корректно для иерархий и множественного наследования:

```cpp
struct Animal { virtual void speak() const; };
```

**Почему:** ручная эмуляция диспетчеризации хрупка (легко рассинхронизировать
таблицу и реализацию), не масштабируется на наследование и не проверяется
компилятором. `virtual` — это та же идея, но безопасная и сопровождаемая.
