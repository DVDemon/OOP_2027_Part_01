# 05. Чисто виртуальные функции, абстрактные классы, интерфейсы

**Пункт плана:** 5 — чисто виртуальные функции, абстрактные классы, интерфейсы.

## Что показывает пример

* **Чисто виртуальная функция** (`= 0`) — без обязательной реализации в базе.
* **Абстрактный класс** — содержит хотя бы одну чисто виртуальную функцию;
  объект такого класса создать нельзя.
* **Интерфейс** (в C++) — абстрактный класс без данных, только из чисто
  виртуальных функций (`ISerializable`).
* Один класс может реализовывать несколько интерфейсов (множественное
  наследование от `Shape` и `ISerializable`).
* Разделение на `shapes.h` / `shapes.cpp` / `main.cpp`.

## Сборка и запуск

```bash
cmake -S .. -B ../build       # из папки лекции
cmake --build ../build
./../build/05_abstract_interfaces_demo
```

Цели: `05_abstract_interfaces_demo` — демонстрация в консоли.

## Плохо → Хорошо

**Плохо** — «базовый класс» с пустыми невиртуальными заглушками:

```cpp
class Shape {
public:
    double area() const { return 0; }   // не virtual, бессмысленная заглушка
};
// Потомок «переопределяет» area, но через Shape& вызовется заглушка -> 0.
// Хуже того: можно создать бессмысленный объект Shape.
```

**Хорошо** — чисто виртуальный контракт:

```cpp
class Shape {
public:
    virtual double area() const = 0;   // обязателен к реализации
    virtual ~Shape() = default;
};
```

**Почему:** `= 0` делает класс абстрактным — компилятор запретит создавать
«пустые» объекты и заставит каждого потомка реализовать метод. Контракт
выражен в типе, а не в комментарии. Интерфейс из чисто виртуальных функций
разделяет «что умеет объект» и «как он устроен».
