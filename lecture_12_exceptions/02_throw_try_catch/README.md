# 02. Синтаксис: `throw`, `try`, `catch`

**Пункт плана:** 2 — синтаксис `throw`, `try`, `catch`.

## Что показывает пример

* Выброс исключения через `throw`.
* Перехват в `try`/`catch`.
* Правильный порядок catch-блоков: от наиболее конкретного к общему.
* «Ловушка» `catch (...)`.

## Запуск

```bash
./build/02_throw_try_catch
```

## Плохо → Хорошо

**Плохо** — общий блок стоит раньше конкретного:

```cpp
try { divide(10.0, 0.0); }
catch (const std::exception& e) { /* ... */ }        // перехватит ВСЁ
catch (const std::invalid_argument& e) { /* ... */ } // мёртвый код, не сработает
```

ПОЧЕМУ плохо: компилятор выбирает первый подходящий `catch`; базовый класс
ловит и производный, поэтому конкретный блок ниже никогда не выполнится
(многие компиляторы выдадут предупреждение).

**Хорошо** — сначала конкретные типы, потом общие:

```cpp
catch (const std::invalid_argument& e) { /* конкретная обработка */ }
catch (const std::exception& e)        { /* всё остальное из std */ }
catch (...)                            { /* совсем неизвестное */ }
```

ПОЧЕМУ хорошо: каждый тип попадает в наиболее точный обработчик; ловим по
`const`-ссылке, чтобы избежать срезки (см. пример 09).
