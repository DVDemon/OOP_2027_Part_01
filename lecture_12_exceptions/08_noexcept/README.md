# 08. `noexcept`: спецификатор и оператор

**Пункт плана:** 8 — `noexcept`: спецификатор и оператор.

## Что показывает пример

* `noexcept` как спецификатор функции (обещание не бросать).
* `noexcept(expr)` как оператор (проверка на этапе компиляции).
* Условный `noexcept(noexcept(...))`.
* Почему `std::vector` использует move только для `noexcept`-операций.

## Запуск

```bash
./build/08_noexcept
```

## Спецификатор vs оператор

| Запись | Это | Смысл |
|---|---|---|
| `void f() noexcept` | спецификатор | обещание: `f` не бросает |
| `noexcept(f())` | оператор | `true`/`false` на этапе компиляции |
| `noexcept(noexcept(e))` | оба | условный: noexcept зависит от `e` |

## Плохо → Хорошо

**Плохо** — пометить `noexcept` функцию, которая на самом деле может бросить:

```cpp
void save(const std::string& path) noexcept {
    std::ofstream f(path);
    if (!f) throw std::runtime_error("...");  // нарушение обещания!
}
```

ПОЧЕМУ плохо: если такая функция всё же бросит, исключение не «выйдет» наружу —
вызывается `std::terminate()`, и программа аварийно завершается без шанса на
обработку.

**Хорошо** — `noexcept` только там, где гарантированно нет исключений (особенно
move-конструктор и `swap`):

```cpp
Buffer(Buffer&& other) noexcept;          // перемещение указателей не бросает
friend void swap(Buffer&, Buffer&) noexcept;
```

ПОЧЕМУ хорошо: `std::vector` при расширении перемещает элементы только если
их move-конструктор `noexcept` (иначе копирует ради строгой гарантии). Честный
`noexcept` ускоряет код и включает оптимизации стандартной библиотеки.
