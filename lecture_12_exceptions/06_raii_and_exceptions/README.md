# 06. RAII и исключения

**Пункт плана:** 6 — RAII и исключения.

## Что показывает пример

* Управление памятью через `std::unique_ptr`.
* Собственный RAII-класс, освобождающий ресурс в деструкторе.
* Гарантию освобождения ресурса при раскрутке стека.

## Запуск

```bash
./build/06_raii_and_exceptions
```

## Плохо → Хорошо

**Плохо** — ручное освобождение после операции, которая может бросить:

```cpp
void bad() {
    int* p = new int[100];
    risky_operation();   // если бросит — delete[] ниже не выполнится
    delete[] p;          // утечка памяти при исключении
}
```

ПОЧЕМУ плохо: при исключении управление уходит вверх по стеку, минуя
`delete[]`; «сырой» указатель не имеет деструктора, ресурс теряется.

**Хорошо** — владелец-объект освобождает ресурс в деструкторе:

```cpp
void good() {
    auto p = std::make_unique<int[]>(100);
    risky_operation();   // если бросит — p освободится автоматически
}                        // delete[] не нужен
```

ПОЧЕМУ хорошо: деструктор `unique_ptr` вызывается при раскрутке стека
независимо от того, как мы выходим из функции — нормально или с исключением.
То же касается `std::lock_guard`, `std::ifstream` и любых RAII-обёрток.
