# 09. Повторный выброс: `throw;` vs `throw e;`

**Пункт плана:** 9 — повторный выброс, срезка.

## Что показывает пример

* Корректный повторный выброс через `throw;`.
* Ошибочный `throw e;`, приводящий к срезке производного класса.
* Разницу видно по тому, в какой `catch` попадает исключение.

## Запуск

```bash
./build/09_rethrow
```

Ожидаемый вывод: после `throw;` исключение ловится как `DerivedException`,
а после `throw e;` — уже как `BaseException` (срезка).

## Плохо → Хорошо

**Плохо** — пробрасывать пойманное исключение по имени:

```cpp
catch (const BaseException& e) {
    log(e);
    throw e;   // бросается КОПИЯ статического типа BaseException
}
```

ПОЧЕМУ плохо: `throw e;` создаёт новый объект типа, которым объявлен `e`
(`BaseException`), отбрасывая (срезая) производную часть `DerivedException`.
Внешний обработчик `catch (const DerivedException&)` уже не сработает.

**Хорошо** — пробрасывать текущее исключение без аргумента:

```cpp
catch (const BaseException& e) {
    log(e);
    throw;     // пробрасывает оригинал, сохраняя динамический тип
}
```

ПОЧЕМУ хорошо: `throw;` повторно активирует то же самое исключение целиком —
тип не теряется, и его можно перехватить по производному классу выше по стеку.
Аналогично: ловить всегда нужно по `const`-ссылке, а не по значению.
