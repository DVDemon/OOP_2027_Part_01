# 05. Гарантии безопасности исключений

**Пункт плана:** 5 — none / basic / strong / nothrow.

## Что показывает пример

* Один и тот же класс с операцией добавления в двух вариантах: с базовой
  и со строгой гарантией.
* Наблюдатели и `swap` с гарантией `nothrow`.

## Запуск

```bash
./build/05_safety_guarantees
```

## Четыре уровня

| Гарантия | Описание | Пример |
|---|---|---|
| **nothrow** | никогда не бросает | деструкторы, `swap`, `size()` |
| **strong** | commit-or-rollback: при исключении состояние не меняется | copy-and-swap, `vector::push_back` |
| **basic** | объект корректен, но в неопределённом состоянии | большинство операций |
| **none** | утечки/повреждение данных | плохой код |

## Плохо → Хорошо

**Плохо** — изменять объект «на месте», когда часть операций может бросить (basic):

```cpp
void add_basic(const std::vector<int>& items) {
    for (int x : items) {
        if (x < 0) throw std::invalid_argument("...");
        data_.push_back(x);   // часть уже добавлена к моменту броска
    }
}
```

ПОЧЕМУ плохо: при исключении объект остаётся в частично изменённом состоянии —
вызывающий код не может рассчитывать на откат.

**Хорошо** — сделать всю «опасную» работу над копией и зафиксировать результат
`noexcept`-операцией (strong):

```cpp
void add_strong(const std::vector<int>& items) {
    auto copy = data_;
    for (int x : items) {
        if (x < 0) throw std::invalid_argument("...");
        copy.push_back(x);
    }
    std::swap(data_, copy);   // фиксация не бросает
}
```

ПОЧЕМУ хорошо: если исключение случится до `swap`, изменяется только копия, а
оригинал нетронут — это и есть строгая гарантия (commit-or-rollback).
