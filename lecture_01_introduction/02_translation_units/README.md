# 02. Единицы трансляции и ODR

**Пункты плана:** 4 — этапы трансляции; 5 — правило одного определения (ODR).

## Что показывает пример

Программа собрана из **двух единиц трансляции** (`main.cpp` и `math_utils.cpp`)
плюс заголовок `math_utils.h`. Это иллюстрирует:

* разделение **объявления** (в `.h`) и **определения** (в `.cpp`);
* защиту заголовка от повторного включения (`#pragma once`);
* когда определение можно держать в заголовке (`inline`-функция `square`);
* роль линковщика — связать вызов `add()` из `main.o` с определением в `math_utils.o`.

## Этапы трансляции

```
source.cpp ──препроцессор──▶ source.i ──компилятор──▶ source.o ──линковщик──▶ program
```

Посмотреть результат препроцессора и остановиться на компиляции:

```bash
g++ -std=c++20 -E main.cpp -o main.i   # только препроцессор
g++ -std=c++20 -c main.cpp -o main.o   # компиляция без линковки
```

## Плохо → Хорошо

**Плохо** — определить нешаблонную функцию прямо в заголовке без `inline`:

```cpp
// math_utils.h  — ПЛОХО
int add(int a, int b) { return a + b; }   // определение в заголовке
```

Если такой заголовок включат две `.cpp`, линковщик увидит **два** определения
`add` → ошибка «multiple definition» (нарушение ODR).

**Хорошо** — в заголовке только объявление, определение в одном `.cpp`:

```cpp
// math_utils.h  — ХОРОШО
int add(int a, int b);            // объявление

// math_utils.cpp
int add(int a, int b) { return a + b; }   // единственное определение
```

Либо пометить функцию `inline` — тогда определение в заголовке допустимо
(как у `square` в этом примере).

## Защита заголовка

```cpp
#pragma once          // современный способ (поддерживается всеми компиляторами)

// либо классический include guard:
#ifndef MATH_UTILS_H
#define MATH_UTILS_H
// ...
#endif
```
