# 05. Инициализация переменных

**Пункт плана:** 11 — copy / direct / list / value-инициализация.

## Что показывает пример

* Четыре формы инициализации: copy (`= 42`), direct (`(42)`), list (`{42}`), value (`{}`).
* Почему `{}` защищает от сужающих преобразований.
* Most vexing parse — почему `Widget w();` объявляет функцию, а не объект.

## Запуск

```bash
./build/05_initialization
```

## Формы инициализации

```cpp
int a = 42;     // copy
int b(42);      // direct
int c{42};      // direct-list (фигурная)
int d = {42};   // copy-list
int e{};        // value -> гарантированно 0
```

## Плохо → Хорошо

**Плохо** — `=` пропускает сужающее преобразование молча:

```cpp
int x = 3.14;   // компилируется, тихо усекает до 3
double big = 1e20;
int y = big;    // переполнение, UB, но компилятор не остановит
```

**Хорошо** — фигурная инициализация запрещает сужение:

```cpp
int x{3.14};    // ОШИБКА КОМПИЛЯЦИИ: narrowing conversion
int z{3};       // ok
```

**Most vexing parse:**

```cpp
Widget w1();    // ПЛОХО: это объявление функции w1() -> Widget
Widget w2{};    // ХОРОШО: создание объекта
```

> Правило: предпочитайте `{}` везде, где нет особых причин для другого синтаксиса.
> Раскомментируйте строку `int bad{3.14};` в `main.cpp`, чтобы увидеть ошибку компиляции.
