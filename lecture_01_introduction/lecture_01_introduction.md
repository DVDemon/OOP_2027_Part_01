## 1. История C++: от C к современному C++

Язык C++ был создан Бьёрном Страуструпом в Bell Labs в начале 1980-х годов как расширение языка C. Первоначально язык назывался «C with Classes» — C с классами. Основная идея: добавить к эффективному системному языку C поддержку абстракций данных и объектно-ориентированного программирования, сохранив совместимость и производительность.

### Ключевые отличия C++ от C

| Аспект | C | C++ |
|--------|---|-----|
| Парадигма | Процедурная | Мультипарадигменная (ООП, обобщённая, функциональная) |
| Типизация | Слабая | Более строгая (перегрузка, шаблоны) |
| Управление памятью | `malloc`/`free` | `new`/`delete`, RAII, умные указатели |
| Стандартная библиотека | stdio, stdlib | STL (контейнеры, алгоритмы, итераторы) |
| Полиморфизм | Только через указатели на функции | Виртуальные функции, шаблоны |

### Сравнение языков: Python, C, C++ и Rust

Студенты этого курса уже знают C и Python. Сводное сравнение четырёх языков:

| Аспект | Python | C | C++ | Rust |
|--------|--------|---|-----|------|
| Парадигма | Скриптовый, динамический | Процедурная | Мультипарадигменная (ООП, обобщённая, функциональная) | Элементы ООП |
| Типизация | Динамическая | Статическая, слабая | Статическая, более строгая | Статическая, строгая |
| Управление памятью | Сборщик мусора | Вручную: `malloc`/`free` | Вручную + RAII, умные указатели | Автоматически на этапе компиляции (владение) |
| Безопасность памяти | Безопасно, ошибки в рантайме | Много неопределённого поведения | RAII помогает, UB остаётся | Гарантии на этапе компиляции |
| Скорость выполнения | Низкая (интерпретация) | Максимальная | Максимальная | Максимальная |
| Применение | Анализ данных, ML, скриптинг | ОС, встраиваемые системы | Игры, GUI, высоконагруженные сервисы | Системный софт, инструменты, веб |

### Роль C++ в учебном курсе

**Почему в курсе C++:** вы уже владеете производительностью C и гибкостью Python. C++ соединяет оба мира — скорость C и мощные абстракции — поверх огромной экосистемы. Rust решает те же задачи, но с более строгими гарантиями и более высоким входным порогом.

> **Важно:** модель программирования на C++ учит **декомпозировать сложные задачи на простые**, строить модель программы и делать код, который легко расширять и менять.

> **Важно:** C++ — не надмножество C. Существуют конструкции, допустимые в C, но запрещённые в C++ (например, неявное приведение `void*` к другим типам указателей).

## 2. Стандарты C++11/14/17/20

С 2011 года комитет по стандартизации ISO выпускает обновления каждые три года:

- **C++11** — «современный C++»: `auto`, `nullptr`, range-for, лямбды, `std::move`, `unique_ptr`/`shared_ptr`, `constexpr`, variadic templates.
- **C++14** — шлифовка C++11: обобщённые лямбды, `decltype(auto)`, relaxed `constexpr`.
- **C++17** — structured bindings, `if constexpr`, `std::optional`, `std::variant`, `std::string_view`, параллельные алгоритмы.
- **C++20** — concepts, ranges, coroutines, modules, `std::format`, `<=>` (spaceship operator).
- **C++23 и далее** — продолжение развития языка.

В этом курсе мы работаем с **C++20** (GCC 13+ / GCC 14).

Компиляция с нужным стандартом:

```bash
g++ -std=c++20 -Wall -Wextra -o program main.cpp
```

## 3. Структура программы. Точка входа `main`

Минимальная программа на C++:

```cpp
// main.cpp
#include <iostream>

int main() {
    std::cout << "Hello, C++!" << std::endl;
    return 0;
}
```

> **Пример на GitHub:** [01_FirstCppProgram](https://github.com/DVDemon/mai_oop_examples_public/tree/main/examples/lection00_01/01_FirstCppProgram)

Функция `main` — точка входа в программу. Стандарт допускает две формы:

```cpp
int main() { /* ... */ }
int main(int argc, char* argv[]) { /* ... */ }
```

- `argc` — количество аргументов командной строки.
- `argv` — массив C-строк с аргументами.
- Возвращаемое значение `0` означает успешное завершение (можно опустить `return 0;` — компилятор добавит его неявно).

## 4. Этапы трансляции: препроцессор → компилятор → линковщик

Преобразование исходного кода в исполняемый файл проходит несколько стадий:

```
source.cpp
    │
    ▼  Препроцессор (#include, #define, #ifdef)
source.i  (единица трансляции, translation unit)
    │
    ▼  Компилятор (синтаксический анализ, оптимизация)
source.o  (объектный файл)
    │
    ▼  Линковщик (связывание объектных файлов и библиотек)
program   (исполняемый файл)
```

### Препроцессор

Работает как текстовый процессор: раскрывает `#include`, макросы `#define`, условную компиляцию `#ifdef`.

```cpp
#include <iostream>  // подстановка содержимого заголовка
#define PI 3.14159   // текстовая замена (избегайте — используйте constexpr)
```

Посмотреть результат работы препроцессора:

```bash
g++ -E main.cpp -o main.i
```

### Компилятор

Компилятор анализирует каждую единицу трансляции независимо и создаёт объектный файл (`.o` / `.obj`).

```bash
g++ -c main.cpp -o main.o   # только компиляция, без линковки
```

### Линковщик

Линковщик (linker) собирает объектные файлы в один исполняемый файл, разрешая внешние символы:

```bash
g++ main.o utils.o -o program
```

## 5. Правило одного определения (ODR)

**One Definition Rule** — одно из фундаментальных правил C++:

1. В пределах одной единицы трансляции любая переменная, функция, класс, перечисление или шаблон может быть **определён** не более одного раза.
2. Во всей программе любая нешаблонная функция или переменная с внешней связью может быть **определена** ровно в одном файле.
3. Классы, шаблоны и `inline`-функции могут определяться в нескольких единицах трансляции, но определения должны быть **идентичными** (token-for-token).

Нарушение ODR — неопределённое поведение (undefined behavior).

```cpp
// utils.h — объявление (declaration)
int add(int a, int b);

// utils.cpp — определение (definition)
int add(int a, int b) {
    return a + b;
}
```

Защита заголовков от повторного включения:

```cpp
#pragma once          // современный способ (нестандартный, но поддерживается всеми)

// или классический include guard:
#ifndef UTILS_H
#define UTILS_H
// содержимое заголовка
#endif
```

**Разделение:** в `.h`-файлах размещаются объявления (declaration), в `.cpp` — определения (definition).

## 6. Система сборки `make`

`make` — классическая утилита автоматизации сборки: избавляет от необходимости вручную перекомпилировать каждый файл и перелинковывать проект.

### Правило (rule) — основа всего

```
цель: зависимости
<табуляция>команда
```

- **Цель (target)** — обычно имя файла, который нужно получить (`.o`, исполняемый файл, `.a`).
- **Зависимости (prerequisites)** — файлы, из которых цель создаётся (`.cpp`, `.h`, другие `.o`).
- **Команда (recipe)** — действие для создания цели. **Критически важно:** отступ должен быть символом **табуляции**, пробелы не допускаются.

```makefile
main.o: main.cpp functions.h
	g++ -c main.cpp -o main.o
```

### Ключевые принципы

- **Инкрементальная сборка.** Make отслеживает временные метки файлов и пересобирает только то, что изменилось (устарело) — критически важно для больших C++ проектов.
- **Декларативный подход.** Вы описываете, *что* нужно собрать, а не *как* (в отличие от shell-скриптов с последовательными командами). Make сам строит граф зависимостей и определяет порядок выполнения.

## 7. Система сборки CMake

CMake — кроссплатформенная система генерации файлов сборки. Вместо написания Makefile вручную, вы описываете проект в `CMakeLists.txt`:

```cmake
cmake_minimum_required(VERSION 3.16)
project(MyFirstProject LANGUAGES CXX)

set(CMAKE_CXX_STANDARD 20)
set(CMAKE_CXX_STANDARD_REQUIRED ON)

add_executable(hello main.cpp)
```

Сборка проекта:

```bash
mkdir build && cd build
cmake ..                    # генерация файлов сборки
cmake --build .             # компиляция
./hello                     # запуск
```

Основные команды: `add_executable()` (программа), `add_library()` (библиотека).

Полезные флаги компиляции:

```cmake
target_compile_options(hello PRIVATE -Wall -Wextra -Wpedantic)
```

### Опции компиляции и режимы сборки

**Флаги компилятора g++/clang++:**

| Флаг | Назначение |
|------|------------|
| `-std=c++20` | Стандарт языка C++20 |
| `-g` | Таблица отладки: имена функций, переменных, номера строк |
| `-O0` | Отключить оптимизацию — пошаговое выполнение соответствует исходнику |
| `-O2` / `-O3` | Оптимизация скорости; отладка становится «перепутанной» |
| `-Wall -Wextra -Wpedantic` | Предупреждения о потенциальных ошибках |
| `-o program` | Имя выходного файла |

Собрать с отладочной информацией вручную:

```bash
g++ -g -O0 -std=c++20 -Wall -Wextra -o program main.cpp
```

**Режимы сборки CMake** задаются переменной `CMAKE_BUILD_TYPE`:

| Тип | Флаги (GCC/Clang) | Когда использовать |
|-----|--------------------|--------------------|
| `Debug` | `-g -O0` | Разработка и отладка (**по умолчанию в проектах курса**) |
| `Release` | `-O3 -DNDEBUG` | Готовая программа |
| `RelWithDebInfo` | `-O2 -g -DNDEBUG` | Профилирование |

Выбор режима при конфигурировании:

```bash
cmake -S . -B build -DCMAKE_BUILD_TYPE=Debug
cmake --build build
```

> **Важно:** если `CMAKE_BUILD_TYPE` не задан, CMake собирает **без** `-g` — отладчик не найдёт точку останова (сообщение `no locations (pending)`). Проекты курса по умолчанию собираются в режиме `Debug`, поэтому отладка работает сразу.

## 8. Введение в Google Test

Google Test (gtest) — фреймворк для модульного тестирования C++ кода.

> **Пример на GitHub:** [06_GTest](https://github.com/DVDemon/mai_oop_examples_public/tree/main/examples/lection00_01/06_GTest)

Подключение через CMake (FetchContent):

```cmake
include(FetchContent)
FetchContent_Declare(
  googletest
  GIT_REPOSITORY https://github.com/google/googletest.git
  GIT_TAG v1.14.0
)
FetchContent_MakeAvailable(googletest)

add_executable(tests tests.cpp)
target_link_libraries(tests GTest::gtest_main)
```

Пример теста:

```cpp
#include <gtest/gtest.h>

int add(int a, int b) { return a + b; }

TEST(AddTest, PositiveNumbers) {
    EXPECT_EQ(add(2, 3), 5);
    EXPECT_EQ(add(0, 0), 0);
}

TEST(AddTest, NegativeNumbers) {
    EXPECT_EQ(add(-1, -1), -2);
    EXPECT_EQ(add(-1, 1), 0);
}
```

Запуск:

```bash
cd build && ctest --output-on-failure
```

## 9. Отладка с gdb / lldb: точки останова, пошаговое выполнение, стек вызовов

Отладчик — главный инструмент поиска ошибок в собранной программе. GNU Debugger (gdb) позволяет остановить программу в любой точке, посмотреть значения переменных и увидеть, как мы в неё попали.

Компиляция с информацией для отладчика (на macOS вместо gdb используется **lldb** — команды почти совпадают, примеры ниже приведены для lldb):

```bash
g++ -g -O0 -o program main.cpp    # -g — таблица отладки, -O0 — отключить оптимизацию
```

```bash
$ lldb ./build/01_first_program
(lldb) b main.cpp:14    # точка останова на входе в main (строка 14 файла main.cpp)
(lldb) run              # запуск программы до точки останова
(lldb) next             # следующая строка, не заходя в функции
(lldb) step             # следующая строка, заходя в функции
(lldb) print argc       # значение переменной argc
(lldb) bt               # стек вызовов: как мы сюда попали
(lldb) frame variable   # все локальные переменные текущего кадра
(lldb) continue         # продолжить до следующей точки останова
(lldb) quit             # выход из отладчика
```

> **Почему файл и номер строки?** Команда `break main` (по одному имени функции) ненадёжна: имя может не совпасть из-за перегрузок, пространств имён, шаблонов или отсутствия отладочной информации, и breakpoint останется «висящим» (`Breakpoint 1: no locations`). `break main.cpp:12` привязывается к конкретной строке и работает стабильно.

### Основные команды

| Команда | Сокращение | Назначение |
|---------|-----------|------------|
| `break main.cpp:12` | `b` | Точка останова на строке: `break main.cpp:12`, с условием — `break main.cpp:12 if x > 0` |
| `run` | `r` | Запуск программы |
| `next` | `n` | Шаг без захода в функции |
| `step` | `s` | Шаг с заходом в функции |
| `print x` | `p` | Вывести значение переменной |
| `frame variable` | `fr v` | Все локальные переменные текущего кадра (в gdb — `info locals`) |
| `thread backtrace` | `bt` | Стек вызовов — цепочка вложенных функций |
| `continue` | `c` | Продолжить выполнение |
| `quit` | `q` | Выйти из отладчика |

### Пример сеанса

```cpp
int add(int a, int b) { return a + b; }

int main() {
    int x = 40;
    int y = 2;
    int z = add(x, y);
    return 0;
}
```

```bash
(lldb) break main.cpp:1    # точка останова на входе в add (строка 1)
(lldb) run
(lldb) print a          # (int) $0 = 40 — аргументы скопированы в кадр функции add
(lldb) frame variable   # (int) a = 40, (int) b = 2
(lldb) bt               # frame #0: add(a=40, b=2) ... frame #1: main() ...
(lldb) continue
```

## 10. Базовые типы данных, литералы, `sizeof`

### Целочисленные типы

> **Примеры на GitHub:** [07_IntegerModifiers](https://github.com/DVDemon/mai_oop_examples_public/tree/main/examples/lection00_01/07_IntegerModifiers)

```cpp
#include <iostream>
#include <cstdint>

int main() {
    // Основные целочисленные типы
    short s = 32767;            // минимум 16 бит
    int i = 2'147'483'647;     // минимум 16 бит, обычно 32
    long l = 2'147'483'647L;   // минимум 32 бита
    long long ll = 9'223'372'036'854'775'807LL; // минимум 64 бита

    // Типы фиксированного размера (рекомендуются)
    int8_t  i8  = 127;
    int16_t i16 = 32767;
    int32_t i32 = 2'147'483'647;
    int64_t i64 = 9'223'372'036'854'775'807LL;

    std::cout << "sizeof(short)     = " << sizeof(short)     << std::endl;
    std::cout << "sizeof(int)       = " << sizeof(int)       << std::endl;
    std::cout << "sizeof(long)      = " << sizeof(long)      << std::endl;
    std::cout << "sizeof(long long) = " << sizeof(long long) << std::endl;

    // Разделитель разрядов (C++14)
    int million = 1'000'000;

    // Литералы в разных системах счисления
    int dec = 42;       // десятичный
    int oct = 052;      // восьмеричный (начинается с 0)
    int hex = 0x2A;     // шестнадцатеричный
    int bin = 0b101010; // двоичный (C++14)

    return 0;
}
```

### Типы с плавающей точкой

### Логический тип и символы

### Как вычисляются выражения?

Составные операторы присваивания выполняются **справа налево**:

```cpp
int x = 10;
int y = 20;
y += x *= 40;       // x *= 40 → x = 400; затем y += 400 → y = 420
```

### Память на стеке

Локальные переменные хранятся на **стеке** — области памяти процесса, растущей «вниз»:

```
┌──────────────────────────────┐
│ кадр add(): a, b             │  ← вершина стека
├──────────────────────────────┤
│ кадр main(): x, y, z         │
└──────────────────────────────┘
```

- **Автоматическое время жизни:** память выделяется при входе в блок и освобождается при выходе из него — освобождать вручную не нужно.
- **Быстро:** выделение и освобождение — это простое изменение указателя стека, без системных вызовов.
- **Размер ограничен** (обычно единицы МБ): большой локальный массив или глубокая рекурсия приводят к переполнению стека (stack overflow).
- Неинициализированная локальная переменная содержит **неопределённое значение** («мусор») — чтение до присваивания это UB.

Динамическая память (**куча**, `new`/`delete`, умные указатели) — тема следующих лекций.

## 11. Инициализация переменных

В C++ существует несколько форм инициализации:

```cpp
// Copy initialization (копирующая)
int a = 42;

// Direct initialization (прямая)
int b(42);

// List initialization / brace initialization (фигурная, C++11)
int c{42};       // direct-list-initialization
int d = {42};    // copy-list-initialization

// Value initialization (инициализация значением)
int e{};         // гарантированно 0
int f = {};      // гарантированно 0
```

**Почему предпочтительна фигурная инициализация (`{}`):**

1. Защита от сужающих преобразований:

```cpp
int x = 3.14;   // OK — тихое усечение до 3
// int y{3.14};  // Ошибка компиляции! Сужающее преобразование
```

2. Единообразный синтаксис для всех типов.
3. Защита от «most vexing parse»:

```cpp
// Widget w();   // Объявление функции! (most vexing parse)
Widget w{};      // Создание объекта
```

## 12. `const`, `constexpr`, `auto`, пространства имён

### `const` — неизменяемость в рантайме

> **Пример на GitHub:** [17_Constants](https://github.com/DVDemon/mai_oop_examples_public/tree/main/examples/lection00_01/17_Constants)

```cpp
const int max_size = 100;   // значение фиксировано после инициализации
// max_size = 200;          // ошибка компиляции
```

### `constexpr` — вычисление на этапе компиляции

> **Пример на GitHub:** [18_ConstantExpressions](https://github.com/DVDemon/mai_oop_examples_public/tree/main/examples/lection00_01/18_ConstantExpressions)

```cpp
constexpr int square(int x) { return x * x; }

constexpr int result = square(5);  // вычислено на этапе компиляции
static_assert(result == 25, "Must be 25");

// constexpr переменная обязана быть инициализирована
// значением, вычислимым на этапе компиляции
constexpr double pi = 3.14159265358979;
```

Отличие `const` от `constexpr`:

| | `const` | `constexpr` |
|---|---------|-------------|
| Когда вычисляется | Может в рантайме | Обязано на этапе компиляции |
| Контекст | Любой | Только compile-time аргументы |
| Используется в `static_assert` | Не всегда | Да |

### `auto` — вывод типа

> **Пример на GitHub:** [11_Auto](https://github.com/DVDemon/mai_oop_examples_public/tree/main/examples/lection00_01/11_Auto)

```cpp
auto x = 42;           // int
auto y = 3.14;         // double
auto z = "hello";      // const char*
auto s = std::string("hello"); // std::string

// auto обязателен при инициализации
// auto a;  // ошибка: нельзя вывести тип без инициализатора
```

`auto` особенно полезен для длинных типов:

```cpp
double square(double x) { return x * x; }

auto f = &square;  // тип double (*)(double) — вручную писать долго
```

**Осторожно с `auto`:**

- В **параметрах функций** `auto` создаёт неоднозначность — обычные функции не могут объявлять параметры через `auto` (только шаблоны и лямбды, а также `auto` как краткая запись шаблона в C++20).
- Не злоупотребляйте `auto` там, где тип должен быть очевиден читателю.

### Пространства имён

Пространства имён предотвращают конфликты имён:

```cpp
namespace math {
    double pi = 3.14159;
    double square(double x) { return x * x; }
}

namespace physics {
    double c = 299'792'458.0; // скорость света, м/с
}

int main() {
    std::cout << math::pi << std::endl;
    std::cout << math::square(5) << std::endl;

    // using-директива (избегайте в заголовочных файлах!)
    using namespace math;
    std::cout << pi << std::endl;

    // using-объявление (предпочтительнее)
    using math::square;
    std::cout << square(3) << std::endl;

    return 0;
}
```

**Доступ через `::`** — оператор разрешения области видимости: `math::pi` vs `physics::pi`.

> **Правило:** никогда не используйте `using namespace std;` в заголовочных файлах. В `.cpp`-файлах допустимо, но лучше использовать конкретные `using std::cout;`.

## Ключевые концепции

1. **C++ — мультипарадигменный язык**, поддерживающий процедурное, объектно-ориентированное, обобщённое и функциональное программирование.
2. **Этапы сборки:** препроцессор → компилятор → линковщик. Каждый `.cpp`-файл — отдельная единица трансляции.
3. **ODR** — правило одного определения. Его нарушение ведёт к неопределённому поведению.
4. **Инструментарий:** VS Code (IDE), GCC 14, `make`/CMake (сборка), gdb/lldb (отладка), Google Test (тесты).
5. **Фигурная инициализация `{}`** предпочтительна: защищает от сужающих преобразований и most vexing parse.
6. **`const`** гарантирует неизменяемость, **`constexpr`** — вычислимость на этапе компиляции.
7. **`auto`** выводит тип из инициализатора — упрощает код, но не злоупотребляйте: тип должен быть очевиден читателю.
8. **Отладка:** компилируйте с `-g -O0`, ставьте точки останова, шагайте `next`/`step`, смотрите стек вызовов через `bt`.
9. **Стек:** локальные переменные живут на стеке с автоматическим временем жизни; его размер ограничен — остерегайтесь глубокой рекурсии и больших локальных массивов.

## Распространённые ошибки

### 1. `using namespace std;` в заголовке

```cpp
// header.h — ПЛОХО!
#pragma once
using namespace std;  // загрязняет глобальное пространство имён для всех,
                      // кто включит этот заголовок
```

### 2. Макроконстанты вместо `constexpr`

```cpp
#define MAX_SIZE 100            // ПЛОХО: нет типа, нет области видимости
constexpr int max_size = 100;   // ХОРОШО
```

### 3. Неинициализированные переменные

```cpp
int x;           // неопределённое значение! (UB при чтении)
int y{};         // гарантированно 0
```

### 4. Путаница с системами счисления

```cpp
int a = 010;  // это НЕ 10, а 8 (восьмеричная система!)
int b = 10;   // а вот это 10
```

### 5. Забытый `return` в `main`

Для `main` допустимо, но для любой другой функции с не-`void` типом возврата — неопределённое поведение.

### 6. Большой массив в локальной переменной

```cpp
void process() {
    int data[1'000'000];  // ПЛОХО: ~4 МБ на стеке, лимит стека — единицы МБ
}                          // → переполнение стека (stack overflow)
```

Для больших данных используйте динамическую память (тема кучи и `std::vector` — в следующих лекциях).

### 7. Отладка без `-g`

```bash
gdb ./program   # «no debugging symbols found»
```

Без таблицы отладки gdb показывает только адреса, а не имена функций и переменных. Отладочные сборки собирайте с `-g -O0`.

### Задание: «Калькулятор с тестами»

1. Создайте проект с CMake (`CMakeLists.txt`), подключите Google Test.
2. Реализуйте файл `calculator.h` / `calculator.cpp` с функциями:
   - `int add(int a, int b);`
   - `int subtract(int a, int b);`
   - `double divide(double a, double b);` — при делении на ноль верните `std::numeric_limits<double>::infinity()`.
   - `constexpr int factorial(int n);` — рекурсивный факториал (для n >= 0).
3. Напишите тесты (`tests.cpp`) с использованием Google Test:

6. Соберите отладочную версию (`-g`) и отладьте в lldb одну из функций: поставьте точку останова на строку с вызовом `add` (`break calculator.cpp:номер_строки`), пройдите пошагово (`next`, `step`), проверьте значения аргументов через `print` и стек вызовов через `bt`.
