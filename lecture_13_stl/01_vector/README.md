# 01. `std::vector` — динамический массив

**Пункт плана:** 2 — `std::vector`.

## Что показывает пример

* Устройство вектора: элементы хранятся в **непрерывной области памяти**,
  доступ по индексу — O(1).
* `size()` (сколько элементов сейчас) **против** `capacity()` (сколько выделено
  памяти) и перераспределение при росте.
* `push_back` vs `emplace_back`: вторая конструирует объект прямо внутри вектора,
  без временной копии.
* `reserve` — зарезервировать память заранее, чтобы избежать повторных
  перераспределений.

## Сборка и запуск

```bash
cmake -S .. -B ../build       # из папки лекции
cmake --build ../build
./../build/01_vector
```

## Плохо → Хорошо

**Плохо** — добавить миллион элементов и каждый раз полагаться на автоматический
рост: вектор при этом перераспределяет память десятки раз (копируя все элементы):

```cpp
std::vector<int> v;
for (int i = 0; i < 1'000'000; ++i)
    v.push_back(i);          // ~20 перераспределений и копирований всего буфера
```

**Почему плохо:** каждое перераспределение — это выделение нового буфера и
копирование всех накопленных элементов. Суммарно это работает, но заметно
медленнее и создаёт нагрузку на память.

**Хорошо** — если размер известен заранее, зарезервировать память:

```cpp
std::vector<int> v;
v.reserve(1'000'000);        // выделили всю память сразу, size() остался 0
for (int i = 0; i < 1'000'000; ++i)
    v.push_back(i);          // ни одного перераспределения
```

**Почему хорошо:** ни одного перераспределения — вектор только заполняет уже
выделенный буфер. Выигрыш особенно заметен для больших объектов, которые дорого
копировать.
