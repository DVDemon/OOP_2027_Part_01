# Примеры к курсу «Объектно-ориентированное программирование на C++20»

Семестр 1. Подробные примеры кода к каждой лекции.

## Как устроены примеры

* На **каждую лекцию** — отдельная папка `lecture_NN_<тема>/`.
* В папке лекции — **единый `CMakeLists.txt`**, который собирает все примеры лекции.
* В папке лекции — `README.md` с обзором всех примеров и инструкцией по сборке.
* Каждый пример — **отдельная поддиректория** `NN_<тема>/` со своим `README.md` и исходным кодом.

## Стиль примеров: «плохо → хорошо»

Большинство примеров построены по принципу **прогрессивного улучшения**:

1. Сначала показывается наивный или ошибочный код («Плохо») — и объясняется, *почему* он плох.
2. Затем — правильное решение («Хорошо») с пояснением, какую проблему оно устраняет.

Компилируемый `main.cpp` обычно содержит **хороший** вариант (а часто и контрастную
демонстрацию проблемы в управляемом виде). Ошибочные варианты, которые **не компилируются**
по своей природе (например, сужающее преобразование), приводятся в `README.md` как сниппеты.

## Требования

* Компилятор с поддержкой **C++20** (GCC 13+, Clang 17+, Apple Clang 15+, MSVC 19.38+).
* **CMake** 3.20+.
* GoogleTest используется **только в `lecture_01`** (там, где про него
  рассказывается). Для её тестов нужен доступ в интернет (библиотека
  подтягивается через `FetchContent`); в остальных лекциях тестов нет.

## Сборка одной лекции

```bash
cd lecture_01_introduction
cmake -S . -B build
cmake --build build
```

Запуск конкретного примера:

```bash
./build/01_first_program
```

Запуск тестов (только в `lecture_01`, где рассказывается про GoogleTest):

```bash
cd build && ctest --output-on-failure
```

## Сборка всех лекций сразу

В корне `examples/` есть агрегирующий `CMakeLists.txt`, который добавляет все
16 лекций через `add_subdirectory`. Имена целей во всём дереве уникальны
(например, `10_best_practices` в лекциях 9 и 13 различаются), поэтому конфликтов
не возникает:

```bash
cd examples
cmake -S . -B build
cmake --build build          # сконфигурирует и соберёт все 16 лекций
```

По умолчанию тесты в агрегирующей сборке **выключены** — GoogleTest есть только
в `lecture_01`, и скачивать его без надобности не нужно. Включить тесты:

```bash
cmake -S . -B build -DLECTURE_BUILD_TESTS=ON
```

При **автономной** сборке `lecture_01` (см. «Сборка одной лекции» выше) тесты
включаются по умолчанию — лекция рассказывает про GoogleTest, и удобно сразу
запустить `ctest`.

> Для запуска конкретного примера удобнее собирать лекцию отдельно (см. её
> `README.md`) — тогда бинарники лежат прямо в `<лекция>/build/`.

## Отладочная информация и санитайзеры

* **Отладочная информация включается всегда**: флаг `-g` (GCC/Clang) или
  `/Zi` + `/DEBUG` (MSVC) ставится безусловно, независимо от
  `CMAKE_BUILD_TYPE`. Даже в `Release` можно отлаживать примеры.
* **Санитайзеры** (лекция 3, примеры с памятью) включаются опцией
  `ENABLE_SANITIZERS` (AddressSanitizer + UndefinedBehaviorSanitizer):

  ```bash
  cd lecture_03_pointers_references
  cmake -S . -B build -DENABLE_SANITIZERS=ON
  cmake --build build
  ```
