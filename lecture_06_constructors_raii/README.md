# Лекция 6. Конструкторы, деструкторы, RAII

Примеры к лекции. Покрывают все пункты плана: виды конструкторов, список
инициализации членов (MIL) и порядок инициализации, делегирующие конструкторы,
`explicit`, `=default`/`=delete` и таблицу автогенерации, деструкторы и порядок
уничтожения, идиому RAII, время жизни объектов, паттерн Singleton и связь с
правилом пяти.

```bash
cmake -S . -B build
cmake --build build
```

## Ключевые идеи лекции

1. **MIL инициализирует поля до тела конструктора** — единственный способ задать `const`-поля, ссылки и объекты без конструктора по умолчанию.
2. **Поля инициализируются в порядке объявления в классе**, а не в порядке списка инициализации; несовпадение — частый источник UB.
3. **Делегирующие конструкторы** убирают дублирование, перенаправляя работу к одному «полному» конструктору.
4. **`explicit`** запрещает неявные преобразования и copy-initialization — защита от случайной конверсии.
5. **`=default`/`=delete`** дают явный контроль над специальными методами; объявление деструктора или конструктора меняет автогенерацию остальных.
6. **RAII** связывает время жизни ресурса со временем жизни объекта: захват в конструкторе, освобождение в деструкторе — корректность даже при исключениях.
7. **Деструкторы вызываются в обратном порядке**: поля — обратно объявлению, локальные объекты — обратно созданию.
8. **Magic Statics (C++11)** делают ленивую инициализацию локальной `static`-переменной потокобезопасной — основа простого Singleton.
9. **Правило пяти**: если класс управляет ресурсом, продумайте все пять специальных методов (тема следующей лекции).
