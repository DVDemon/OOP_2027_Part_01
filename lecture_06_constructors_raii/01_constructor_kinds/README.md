# 01. Виды конструкторов

**Пункт плана:** 1 — по умолчанию, параметризованный, копирующий, конвертирующий.

## Что показывает пример

* Конструктор **по умолчанию** (`Point()`) — вызывается без аргументов.
* **Параметризованный** конструктор (`Point(double, double)`).
* **Копирующий** конструктор `Point(const Point&)` — создаёт копию.
* **Конвертирующий** конструктор `Temperature(double)` — допускает неявную
  конверсию `double -> Temperature` при передаче в функцию и при
  copy-initialization.

## Плохо → Хорошо

**Плохо** — присваивать поля в теле конструктора, полагаясь на их
предварительную инициализацию по умолчанию:

```cpp
Point(double x, double y) {
    x_ = x;   // сначала x_ инициализируется значением по умолчанию,
    y_ = y;   // потом присваивается — двойная работа
}
```

**Хорошо** — инициализировать через список инициализации (MIL):

```cpp
Point(double x, double y) : x_(x), y_(y) {}
```

**Почему:** в теле конструктора происходит присваивание уже
проинициализированным полям. Для встроенных типов это лишняя работа, а для
`const`-полей, ссылок и объектов без конструктора по умолчанию — вообще ошибка
компиляции. MIL инициализирует сразу нужным значением.

> Конвертирующий конструктор удобен, но опасен: `describe(36.6)` молча создаёт
> `Temperature`. Если такая конверсия нежелательна — пометьте конструктор
> `explicit` (см. пример `04_explicit`).
