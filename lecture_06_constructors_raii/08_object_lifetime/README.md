# 08. Время жизни объектов

**Пункт плана:** 8 — автоматическое, динамическое, статическое время жизни,
временные объекты.

## Что показывает пример

* **Автоматическое** (стек): `Loud a("auto-a")` — уничтожается при выходе из
  блока.
* **Динамическое** (куча): `std::make_unique<Loud>(...)` — RAII-владение,
  автоматическое удаление.
* **Временный** объект: `Loud("temp")` живёт до конца полного выражения.
* **Статическое**: локальная `static`-переменная в `shared_config()` —
  создаётся при первом вызове, живёт до конца программы (Magic Static).

## Запуск

```bash
./build/08_object_lifetime
```

> Статический объект `static-config` уничтожается **после** `main`, поэтому его
> строка `- static-config уничтожен` появится последней.

## Плохо → Хорошо

**Плохо** — управлять динамической памятью вручную:

```cpp
auto* p = new std::vector<int>(100);
use(*p);
delete p;            // забудут / не дойдут при исключении -> утечка
```

**Хорошо** — RAII-владение через умный указатель:

```cpp
auto p = std::make_unique<std::vector<int>>(100);
use(*p);
// delete не нужен: unique_ptr освободит память автоматически
```

**Почему:** ручной `new`/`delete` требует выполнить освобождение на каждом пути
выхода, включая исключения — это источник утечек и двойных `delete`. Умный
указатель привязывает время жизни кучи к области видимости (RAII).

> Временный объект продлевает жизнь только при привязке к `const&`:
> `const std::string& r = getName();` — временная строка живёт, пока жива `r`.
