# 04. Ключевое слово `explicit`

**Пункт плана:** 4 — `explicit`.

## Что показывает пример

* `Money(long)` без `explicit` — допускает неявную конверсию: `chargeUnsafe(500)`
  и `Money m = 1000;` компилируются.
* `SafeMoney(long)` с `explicit` — требует явного создания: `SafeMoney(500)`,
  `SafeMoney good(1000)`, `SafeMoney good2{2000}`.
* Закомментированные строки показывают, какие конструкции `explicit` запрещает.

## Запуск

```bash
./build/04_explicit
```

## Плохо → Хорошо

**Плохо** — конвертирующий конструктор без `explicit` допускает случайную
конверсию:

```cpp
class Money { Money(long cents); };

void charge(const Money&);
charge(500);        // компилируется: 500 -> Money(500). А хотели рубли?
Money m = 1000;     // copy-init «проскальзывает» незаметно
```

**Хорошо** — пометить конструктор `explicit`:

```cpp
class SafeMoney { explicit SafeMoney(long cents); };

// charge(500);              // ОШИБКА: неявная конверсия запрещена
charge(SafeMoney(500));      // явно и читаемо
SafeMoney m(1000);           // direct init
```

**Почему:** неявные преобразования делают код короче, но прячут ошибки —
случайно переданное число «волшебно» превращается в объект, причём не всегда в
том смысле, что подразумевал автор. `explicit` заставляет писать создание
явно, и компилятор ловит несоответствия типов.

> Правило: делайте конструкторы с одним параметром `explicit` по умолчанию.
> Снимайте `explicit`, только когда неявная конверсия действительно желательна
> и семантически очевидна.
> Раскомментируйте `chargeSafe(500);`, чтобы увидеть ошибку компиляции.
