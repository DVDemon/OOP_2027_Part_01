# 09. Паттерн Singleton

**Пункт плана:** 9 — Singleton.

## Что показывает пример

* `Database` — единственный экземпляр, доступный через `getInstance()`.
* Локальная `static`-переменная (Magic Static) даёт ленивую, потокобезопасную
  (с C++11) инициализацию.
* Приватные конструктор и деструктор + удалённые копирование/перемещение
  гарантируют, что другого экземпляра создать нельзя.
* Две ссылки `a` и `b` указывают на один и тот же объект.

## Запуск

```bash
./build/09_singleton
```

## Плохо → Хорошо

**Плохо** — статический указатель с ручной инициализацией («классический»
Singleton до C++11):

```cpp
class Database {
    static Database* instance_;
public:
    static Database* getInstance() {
        if (!instance_) instance_ = new Database();  // гонка в многопотоке!
        return instance_;                            // и кто вызовет delete?
    }
};
```

**Хорошо** — Magic Static:

```cpp
static Database& getInstance() {
    static Database instance;   // лениво, потокобезопасно, авто-уничтожение
    return instance;
}
```

**Почему:** проверка `if (!instance_)` без синхронизации даёт гонку данных в
многопоточной программе, а `new` без `delete` — утечку. Локальная `static`
инициализируется ровно один раз (компилятор добавляет потокобезопасную
защиту с C++11) и уничтожается автоматически при завершении программы.

> **Предостережение:** Singleton часто считают анти-паттерном — он вводит
> глобальное состояние, скрывает зависимости и усложняет тестирование.
> Применяйте осознанно; нередко лучше передавать зависимость явно.
