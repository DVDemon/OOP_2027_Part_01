# 11. Перегрузка копирующих и перемещающих операторов

**Пункт плана:** дополнительный пример — правило пяти в действии (развитие п. 10).

## Что показывает пример

Класс `TrackedBuffer` владеет динамическим буфером `int` и печатает каждый
специальный метод. Это делает видимым, **что именно** вызывает компилятор:

* **копирующий конструктор** `TrackedBuffer(const TrackedBuffer&)` — глубокая
  копия: собственный буфер + поэлементное копирование;
* **копирующий оператор присваивания** `operator=(const TrackedBuffer&)` —
  реализован через *copy-and-swap* (сильная гарантия исключений и корректное
  самоприсваивание);
* **перемещающий конструктор** `TrackedBuffer(TrackedBuffer&&) noexcept` —
  забирает владение указателем, источник обнуляется;
* **перемещающий оператор присваивания** `operator=(TrackedBuffer&&) noexcept`
  — освобождает свой ресурс и забирает чужой (с проверкой самоперемещения);
* **деструктор** — освобождает `new[]` (для перемещённого объекта — безопасный
  `delete[] nullptr`).

## Ключевые сигнатуры (правило пяти)

```cpp
class TrackedBuffer {
public:
    ~TrackedBuffer();                                     // 1. деструктор

    TrackedBuffer(const TrackedBuffer&);                  // 2. копирование
    TrackedBuffer& operator=(const TrackedBuffer&);       // 3. копир. присваивание

    TrackedBuffer(TrackedBuffer&&) noexcept;              // 4. перемещение
    TrackedBuffer& operator=(TrackedBuffer&&) noexcept;   // 5. перем. присваивание
};
```

> **`noexcept` у перемещения — не формальность.** `std::vector` при
> перевыделении буфера переносит элементы. Если конструктор перемещения
> не помечен `noexcept`, контейнер выберет **копирование** (чтобы сохранить
> строгую гарантию), и вы получите лишние глубокие копии. Раздел 5 примера
> печатает вызовы — видно, что при росте `vector` срабатывает перемещение.

## Плохо → Хорошо

**Плохо** — перемещающий конструктор без `noexcept` и «забытая» очистка
источника:

```cpp
TrackedBuffer(TrackedBuffer&& other)                 // нет noexcept
    : data_(other.data_), size_(other.size_) {}      // other.data_ не обнулён!
// Деструктор other освободит тот же буфер -> double free.
```

**Хорошо** — забрать владение и обнулить источник:

```cpp
TrackedBuffer(TrackedBuffer&& other) noexcept
    : data_(std::exchange(other.data_, nullptr)),
      size_(std::exchange(other.size_, 0)) {}
```

**Почему:** перемещение — это «передача владения». Если указатель источника
не обнулить, оба объекта будут считать буфер своим, и двойное `delete[]`
приведёт к UB. `std::exchange` одновременно читает и обнуляет поле.
А `noexcept` позволяет контейнерам безопасно и быстро переносить элементы.
