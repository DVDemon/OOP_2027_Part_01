# 10. Резюме: `DynamicArray` и правило пяти

**Пункт плана:** 10 — резюме и связь с правилом пяти.

## Что показывает пример

Класс `DynamicArray` собирает воедино конструкторы из лекции и реализует
полное **правило пяти**:

1. конструктор по умолчанию (пустой массив);
2. делегирующий `DynamicArray(count, value)` -> `DynamicArray(capacity)`;
3. конструктор из `std::initializer_list<int>`;
4. копирующий конструктор — **глубокая** копия;
5. перемещающий конструктор — перенос владения (`noexcept`);
6. деструктор — освобождение `new[]`;
7. оператор присваивания `operator=(DynamicArray)` — **copy-and-swap**,
   единая реализация и для копирования, и для перемещения;
8. `swap` (`noexcept`) — обмен «сырыми» ресурсами, основа copy-and-swap.

Все пять специальных методов заданы явно, поэтому класс безопасно владеет
динамическим буфером и работает с `std::vector<DynamicArray>`.

## Правило пяти

Если класс управляет ресурсом (память, файл, сокет), продумайте все пять
специальных методов:

1. деструктор;
2. копирующий конструктор;
3. копирующий оператор присваивания;
4. перемещающий конструктор;
5. перемещающий оператор присваивания.

## Плохо → Хорошо

**Плохо** — определить деструктор с `delete[]`, но положиться на
сгенерированный копирующий конструктор:

```cpp
DynamicArray a{1, 2, 3};
DynamicArray b = a;   // поверхностная копия: b.data_ == a.data_
// при разрушении a и b -> двойное delete[] -> UB
```

**Хорошо** — задать владение явно и реализовать присваивание через
**copy-and-swap**:

```cpp
// Копирование — глубокая копия.
DynamicArray(const DynamicArray& other)
    : data_(other.capacity_ > 0 ? new int[other.capacity_]{} : nullptr),
      size_(other.size_), capacity_(other.capacity_) {
    std::copy(other.data_, other.data_ + other.size_, data_);
}

// Перемещение — перенос владения за O(1), без копирования элементов.
DynamicArray(DynamicArray&& other) noexcept
    : data_(other.data_), size_(other.size_), capacity_(other.capacity_) {
    other.data_ = nullptr;
    other.size_ = 0;
    other.capacity_ = 0;
}

// Обмен «сырыми» ресурсами: O(1) и noexcept.
void swap(DynamicArray& other) noexcept {
    std::swap(data_, other.data_);
    std::swap(size_, other.size_);
    std::swap(capacity_, other.capacity_);
}

// Единый оператор присваивания (copy-and-swap).
// other by value уже построен: копия для lvalue, перемещение для rvalue.
// Обмениваемся ресурсами; временный other освобождает прежнее содержимое *this.
DynamicArray& operator=(DynamicArray other) {
    swap(other);
    return *this;
}
```

**Плохо** — «swap над целыми объектами» внутри того же оператора:

```cpp
DynamicArray& operator=(DynamicArray other) {
    std::swap(*this, other);   // ловушка!
    return *this;
}
```

`std::swap(*this, other)` в своей реализации делает `*this = std::move(other)`,
то есть снова вызывает `operator=`. Пока отдельный `operator=(DynamicArray&&)`
объявлен, это случайно работает, но стоит его убрать или пометить `=delete` — и
получается бесконечная рекурсия с переполнением стека. Обменивать нужно поля
(`data_`, `size_`, `capacity_`) через `swap`, а не объекты целиком.

**Почему:** наличие ручного деструктора — сигнал, что класс владеет ресурсом.
Автогенерированная (поверхностная) копия почти наверняка некорректна: два объекта
разделят один указатель и оба попытаются его освободить. Глубокая копия даёт
каждому объекту собственный буфер. Перемещение вместо копирования забирает
указатель у временного объекта и обнуляет его, что даёт прирост производительности
и сохраняет корректность при разрушении. Copy-and-swap даёт **строгую гарантию
исключений** у `operator=`: сначала строится копия `other`, и лишь затем
выполняется `noexcept`-обмен, поэтому при исключении `*this` не меняется.
Перемещающий конструктор и `swap` помечены `noexcept` — это позволяет
`std::vector` использовать перемещение при росте контейнера.
