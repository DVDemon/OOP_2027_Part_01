# 06. Деструкторы и порядок уничтожения

**Пункт плана:** 6 — деструкторы и порядок уничтожения.

## Что показывает пример

* Деструктор вызывается автоматически при выходе объекта из области видимости.
* Поля класса `C` (`a_`, `b_`) уничтожаются в **обратном** порядке объявления:
  сначала `b_`, потом `a_`.
* Локальные объекты уничтожаются в обратном порядке создания.

## Запуск

```bash
./build/06_destructors_order
```

Ожидаемый вывод для объекта `C`:

```
A ctor      // поле a_ (объявлено первым)
B ctor      // поле b_
C ctor      // тело конструктора C
C dtor      // тело деструктора C
B dtor      // поле b_ (обратный порядок)
A dtor      // поле a_
```

## Плохо → Хорошо

**Плохо** — освобождать ресурс вручную в обычном методе и надеяться, что его
вызовут:

```cpp
class File {
    FILE* f_;
public:
    void close() { if (f_) std::fclose(f_); }  // забудут вызвать
};

File file;
// ... return по ошибке / исключение -> close() не вызван -> утечка
```

**Хорошо** — освобождать ресурс в деструкторе:

```cpp
class File {
    FILE* f_;
public:
    ~File() { if (f_) std::fclose(f_); }  // вызовется гарантированно
};
```

**Почему:** деструктор вызывается автоматически при любом выходе из области
видимости — в том числе при раскрутке стека из-за исключения. Это фундамент
идиомы RAII (см. пример `07_raii`): полагаться на ручной вызов «закрывающего»
метода ненадёжно — его легко пропустить на одном из путей выхода.
